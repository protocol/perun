**Immediate Safety Assessment: Do Not Deploy Without Human Gate**

The issue you described—incorrect candidate names appearing on the display—is a **high-stakes, irreversible automated action** that directly threatens election integrity. Because this error can mislead voters and cannot be undone once a vote is cast, **full autonomous operation of these machines is unsafe** under current conditions. The manufacturing deadline does not override the requirement for a human-in-the-loop gate on high-stakes actions.

Since you cannot replace the hardware, you must implement the following controls before approval:

**1. Real-Time Detection Method (The "Human Gate")**
You cannot rely on the machine's own software to detect its display errors, as the localization bug suggests the system cannot be trusted to render truthfully.
*   **Procedure:** Implement a **mandatory pre-vote visual verification**. Before a voter casts a ballot, the machine must print or display a plain-text summary of their selection *alongside* the candidate names in a secondary, static format (e.g., a printed paper trail or a secondary LED indicator if available) that bypasses the buggy localization engine.
*   **Action:** If the primary display and the secondary verification do not match exactly, the machine must **lock** and require poll worker intervention. Do not attempt to fix this with a software patch in 5 days unless it has been rigorously red-teamed; the risk of introducing new hallucinations is too high.

**2. Contingency Plan for Poll Workers**
Draft and distribute this immediate protocol to all polling stations:
*   **Step 1 (Identification):** If a voter reports a name mismatch or if the pre-vote verification fails, the poll worker must immediately mark the machine as "Under Review" and stop all voting on that unit.
*   **Step 2 (Verification):** The poll worker must manually verify the voter's intent using a **static, printed ballot reference sheet** (provided centrally) that lists correct candidate names for each language option. This sheet acts as the "source of truth" independent of the machine.
*   **Step 3 (Resolution):**
    *   If the machine is confirmed faulty, switch the voter to a **backup paper ballot** or a verified spare machine.
    *   Log the specific language option and candidate name that failed for post-election analysis.
*   **Step 4 (Disclosure):** Inform the voter clearly that a technical discrepancy occurred and that their vote is being recorded via the backup method to ensure accuracy.

**3. Required Transparency Artifact**
You must produce a **Model/Data Card** for this deployment before shipping. This document must explicitly state:
*   **Known Limitation:** "Localization module exhibits unverified error rates in specific language options; display output is not certified as 100% accurate."
*   **Mitigation:** "Human-in-the-loop verification required for all votes; automated execution is disabled upon mismatch."
*   **Residual Risk:** Mark the accuracy rate for the affected languages as **UNVERIFIED**. Do not invent a success percentage.

If you cannot implement the mandatory human verification step (printed summary or secondary check) and the poll worker contingency plan within the five-day window, **you must delay the deployment of the affected units**. Shipping a voting machine with known, unmitigated display errors that could alter election outcomes is a failure of product safety governance. The constraint of "five days" does not permit bypassing the safety gate for irreversible civic actions.
