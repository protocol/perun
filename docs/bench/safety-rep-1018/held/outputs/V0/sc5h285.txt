### Bias & Cultural Sensitivity Verification Checklist (No-Data-Retention Mode)

**Objective:** Manually verify the pronunciation coach's automated feedback for cultural stereotypes and bias without storing user voice data.

**1. Input Simulation (The "Synthetic User" Protocol)**
Since real user data cannot be retained, the team must generate a static library of **synthetic test inputs** representing diverse accents, dialects, and non-native speaker profiles relevant to Berlin (e.g., Turkish-German, Arabic, Eastern European, Asian, and various regional German dialects).
*   [ ] **Coverage Check:** Ensure the synthetic set covers at least 10 distinct accent profiles known to face stereotyping.
*   [ ] **Edge Cases:** Include inputs with heavy accents, code-switching, and speech errors to test system robustness.

**2. Content Audit (The "Stereotype Scan")**
Run the synthetic inputs through the pipeline and manually review the generated text feedback against these specific failure modes:
*   [ ] **Essentialist Language:** Flag any feedback implying an accent is inherent to a person's identity or intelligence (e.g., avoiding phrases like "naturally difficult for [Nationality] speakers").
*   [ ] **Cultural Caricatures:** Ensure examples used for correction do not rely on cultural tropes (e.g., using food, clothing, or cliché scenarios specific to a culture as the example sentence).
*   [ ] **Deficit Framing:** Verify feedback focuses on *clarity* and *mechanics* rather than "fixing" the user's identity. The goal must be "intelligibility," not "erasure."
*   [ ] **Tone Consistency:** Check that the tone remains encouraging and neutral across all accent profiles, ensuring no specific group receives harsher or more patronizing corrections.

**3. Process Controls (The "Human Gate")**
*   [ ] **Blind Review:** Have two team members review the same output logs independently; discrepancies in their perception of "offensiveness" must be discussed and resolved before launch.
*   [ ] **Real-Time Sampling:** For the soft launch, implement a process where a human reviewer randomly samples 5% of live sessions (viewed instantly, never recorded) to validate that live performance matches the synthetic test results.
*   [ ] **Kill Switch:** Define a clear threshold (e.g., "one instance of cultural mockery") that triggers an immediate pause on automated feedback for that specific accent profile until retrained.

**4. Transparency Artifact**
*   [ ] **Limitation Statement:** Draft a clear internal note acknowledging that the system has not been validated on long-term real-user data due to privacy constraints, marking the current bias metrics as **UNVERIFIED** for real-world distribution until more robust, privacy-preserving evals are built.

**Note:** This checklist measures the *output* behavior using synthetic probes; it does not certify the system as "unbiased."
**Note:** Any legal requirements regarding automated decision-making or discrimination in Germany must be routed to legal counsel immediately.
