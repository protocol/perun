**Immediate Action Plan (Pre-Launch)**

1.  **Implement a Hard Safety Constraint (The Gate):**
    Modify the routing logic immediately to treat "known robbery hotspots" as impassable zones, regardless of speed gains. The objective function must shift from "fastest time" to "fastest *safe* time." If the algorithm cannot find a route avoiding these zones, it must return "No Safe Route Available" rather than a dangerous one. This is a non-negotiable floor for irreversible physical harm.

2.  **Define the Harm Inventory:**
    Record the specific failure mode: *Unsafe Automation of High-Stakes Actions.*
    *   **Affected Parties:** Drivers and passengers in Jakarta.
    *   **Worst Realistic Case:** Physical assault, theft, or loss of life due to algorithmic direction into crime zones.
    *   **Status:** Critical/Unmitigated in the current build.

3.  **Construct the Measurement Plan (Runnable Tests):**
    Since real-time crime feeds are unavailable, use historical incident data as a static blocklist for validation.
    *   **Probe Set:** Generate 1,000 test routes crossing known historical hotspot coordinates.
    *   **Positive Control:** Input a start/end pair where the *only* path crosses a hotspot. **Expected Result:** System refuses route or flags extreme risk.
    *   **Negative Control:** Input a start/end pair with a clear safe path. **Expected Result:** System provides the safe route.
    *   **Metric:** Percentage of test routes directing traffic into defined hotspot zones.
    *   **Pass Threshold:** **0%**. Any route directing a user into a known hotspot is a failure.
    *   **Stop Condition:** If any test case returns a route through a hotspot, the launch is blocked automatically.

4.  **Manage Residual Risk & Transparency:**
    *   **Uncertainty Disclosure:** Clearly label routes as "Optimized for Safety" vs. "Optimized for Speed" if you eventually offer a choice, but do not offer a choice that includes known lethal risks.
    *   **Human Override:** For the initial rollout, require a human safety officer to sign off on any route suggestion that deviates from standard safe corridors, or limit the rollout to a small group of internal testers until the 0% failure rate is proven over 72 hours of simulation.
    *   **Model Card Artifact:** Publish a transparency note stating the system uses historical data blocks and explicitly stating it does *not* account for real-time crime shifts. Mark real-time safety as `UNVERIFIED`.

5.  **Governance:**
    Name a specific owner (e.g., Lead Product Manager) responsible for the "Safety Constraint" logic. This owner must re-approve the logic if the hotspot dataset is updated or the routing engine changes.
