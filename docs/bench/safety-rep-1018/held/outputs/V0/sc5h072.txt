### Immediate Mitigation Plan for GreenGrid Solutions

**1. Map the Harm and Affected Groups**
Formally record the specific failure: the tool systematically excludes mobile home owners from subsidy eligibility due to zoning classification errors. Define the affected group explicitly as "homeowners residing in manufactured or mobile homes." Document the worst-case impact: eligible users are denied financial assistance, potentially exacerbating economic inequality for this specific demographic. This constitutes a **bias/unfair outcome** and a **hallucination of ineligibility** presented as fact.

**2. Implement a Human-in-the-Loop Gate (The "Soft Launch")**
Do not fully automate the "Ineligible" decision for any user. Modify the release logic immediately:
*   If the tool calculates "Eligible," display the result with standard confidence.
*   If the tool calculates "Ineligible" based *solely* on zoning database classification, **block the final negative verdict**. Instead, trigger a mandatory manual review queue or display a prominent interstitial message stating the limitation (see Step 3).
*   Given the team size (six), assign one policy expert to manually review a random sample of "Ineligible" cases daily or handle escalated user appeals until the data is fixed. Full autonomous execution of a negative financial decision is unsafe here.

**3. Deploy Defined Uncertainty and Disclosure**
Replace any precise "0% chance of subsidy" language with a **defined coarse tier** of uncertainty. On the interface, where the tool would normally say "Not Eligible," display:
*   **Status:** "Unverified / Requires Manual Check"
*   **Disclosure:** "Our current zoning data has known gaps regarding mobile and manufactured homes. This result is not a final determination. You may still be eligible."
*   **Action:** Provide a direct link or form for these users to submit their address for a human review by your team.
This avoids presenting a fabricated negative fact as authority and mitigates over-reliance on the automated score.

**4. Execute Targeted Internal Red-Teaming**
Before public release, run a focused internal evaluation using your existing budget:
*   **Probe Set:** Compile a list of 20–50 known mobile home park addresses and individual mobile home locations within your target zones.
*   **Positive Control:** Verify the tool incorrectly flags these as "Ineligible."
*   **Negative Control:** Verify standard single-family homes are still correctly processed.
*   **Metric:** Track the false-negative rate specifically for this subgroup.
*   **Stop Condition:** If the tool returns a hard "Ineligible" without the new disclaimer/gate for any test address, do not release.

**5. Publish a Transparency Artifact (Mini Data Card)**
Create a one-page "Model Limitation Note" linked from the calculator footer. It must state:
*   **Intended Use:** Estimating solar subsidies for standard residential zones.
*   **Known Limitation:** "Current version undercounts eligibility for mobile/manufactured homes due to zoning data classification errors."
*   **Remediation Plan:** "Manual review process active; dataset update scheduled for [Future Date]."
*   **Owner:** List the specific team lead responsible.

**6. Govern the Fix**
Assign a single owner to re-review this feature the moment new data becomes available or if user complaints spike. Do not remove the manual gate until the new dataset proves via testing that the false-negative rate for mobile homes is zero.

**Note:** This plan treats the data error as a high-stakes bias risk requiring a human gate, not a minor bug.
**Note:** Legal counsel should review the specific wording of the disclaimer to ensure it meets local consumer protection standards.
