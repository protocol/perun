# Pre-Launch Review: Wildfire Perimeter Mapper Latency & Verification Protocol

**BLUF:** The 15-minute processing latency creates a critical risk where mapped fire lines may lag behind rapidly spreading fronts. This document mandates specific user communications and manual verification steps to prevent over-reliance on automated outputs during active incidents.

### 1. Risk Communication to Users
All user interfaces and briefing materials must explicitly state the system's limitation before any map is displayed. The following disclosures are required:

*   **Prominent Latency Warning:** Every map view must display a persistent, high-contrast banner: **"CAUTION: Imagery and fire lines are delayed by approximately 15 minutes. Do not use for real-time navigation or immediate escape routing."**
*   **Confidence Tiering:** Instead of presenting fire lines as absolute facts, label them as **"Unverified / Single-Source (Satellite)"**. Use a defined coarse tier system (e.g., "Reported" vs. "Ground-Confirmed") rather than numerical confidence scores, which imply false precision.
*   **Intended Use Statement:** Clearly define the tool's scope: "This tool supports strategic planning and resource allocation based on recent historical data. It is **not** a real-time tactical sensor for immediate life-safety decisions."

### 2. Mandatory Manual Verification Steps
Incident Commanders and ground crews must execute the following verification loop before acting on any mapped perimeter:

*   **Ground Truth Cross-Check:** Before committing resources to a mapped "contained" line, crews must verify status via direct radio contact with ground spotters or aerial reconnaissance. No automated "contained" label replaces visual confirmation.
*   **Rapid Spread Heuristic:** If wind speeds exceed 20 mph or terrain is steep/south-facing, assume the active fire front has advanced **beyond** the mapped line by a distance calculated using local spread rates over the 15-minute latency window. Treat the mapped line as the *minimum* possible extent, not the maximum.
*   **Escape Route Validation:** Never rely solely on the mapper for egress routes. All escape paths must be validated by current smoke observations and wind direction reported by personnel on the ground within the last 5 minutes.
*   **Discrepancy Reporting:** Establish a rapid feedback channel (e.g., dedicated radio frequency or simple interface button) for crews to report "Map Mismatch" incidents where observed fire behavior contradicts the satellite output. These reports trigger an immediate manual review flag on the dashboard.

### 3. Operational Governance
*   **Human-in-the-Loop Gate:** The system will not auto-push alerts to mobile devices of ground firefighters without explicit acknowledgment of the latency warning by the Incident Commander.
*   **Owner Accountability:** The Product Owner must sign off on the residual risk that a 15-minute delay could result in containment line breaches during extreme weather events. This risk is **UNVERIFIED** by live field testing and must be accepted by command leadership prior to rollout.
*   **Transparency Artifact:** A one-page "System Limitations Card" must be distributed to all crews, detailing the 15-minute lag, the satellite source, and the specific verification steps listed above. Absence of this card at briefings prohibits system use.

**Note:** This plan addresses the known latency constraint; it does not certify the system as safe for all fire behaviors. Legal counsel should review if additional regulatory disclosures are required for life-safety tools in your jurisdiction.
