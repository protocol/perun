**BLUF:** You cannot safely roll out new data integration features that share genetic-risk data with life insurers for premium adjustment before users know their status. This practice creates irreversible, high-stakes harm (financial exclusion based on hidden health data) and likely violates core ethical and legal boundaries regarding informed consent and automated consequential decisions. The only viable path to "protect user interests" while maintaining "data flow continuity" is to **halt the specific flow of raw genetic-risk data used for pre-knowledge premium adjustments** until a human-in-the-loop gate and explicit, informed user consent mechanism are implemented.

### 1. Harm Inventory (MAP)
Before proceeding, we must name the specific harms this feature introduces:
*   **Unsafe High-Stakes Automation:** Adjusting life insurance premiums is a costly, hard-to-reverse financial decision. Automating this based on data the user hasn't seen or contested removes their agency.
*   **Deceptive Patterns / Missing Disclosure:** Users monitoring health risks expect support, not secret financial penalization. Sharing data before users know their status is a hidden default that nudges them against their own interest.
*   **Bias / Unfair Outcomes:** Genetic data can correlate with protected classes. Systematic disadvantage via premium hikes without transparency creates exclusionary outcomes.
*   **Over-reliance:** Insurers may treat algorithmic risk scores as absolute fact, ignoring uncertainty or context.

**Worst Realistic Case:** A user is denied affordable life insurance or faces prohibitive premiums based on a probabilistic genetic marker they never confirmed, leading to financial ruin and inability to secure coverage, all without knowing why.

### 2. Measurement Plan (MEASURE)
You cannot certify this system "safe" or "compliant" without testing.
*   **Action:** Construct an output-harm evaluation suite. Do not just test code; test the *decision*.
*   **Probe Set:** Simulate diverse genetic profiles (including known false positives and edge cases).
*   **Metric:** Rate of premium adjustments triggered *before* user notification vs. after user confirmation.
*   **Threshold:** **Zero tolerance** for premium adjustments executed before explicit user acknowledgment of the specific genetic data point.
*   **Stop Condition:** If any test case results in a premium change without prior user knowledge, the launch is blocked.
*   **Transparency Artifact:** You must produce a **Model/Data Card** detailing: intended use (explicitly stating if used for insurance), data provenance, limitations of genetic risk prediction, and subgroup performance. If this card does not exist, the feature is not transparent.

### 3. Risk Management (MANAGE)
*   **Human-in-the-Loop Gate (Non-Negotiable):** Any action that adjusts premiums or denies coverage based on genetic data must be gated behind human review and explicit user confirmation. **Full autonomous execution of this action is the failure.** The system must pause, notify the user of the potential finding, allow them to contest or contextualize it, and only then proceed.
*   **Show Uncertainty:** Genetic risk is probabilistic. Never present a risk score as a definitive fact. Use defined coarse tiers (e.g., "Elevated Probability – Requires Clinical Confirmation") rather than precise percentages that imply false certainty.
*   **Disclosure:** You must disclose to the user that their data is being shared and used for insurance underwriting. Whether this is *legally* required is a determination for counsel, but ethically, hiding this is a deceptive pattern.
