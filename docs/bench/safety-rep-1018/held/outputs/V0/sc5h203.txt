**Blunt Assessment:** Your current plan to "review testing protocols" is insufficient for a high-stakes, irreversible action system. Because this feature advises on flight paths where failure causes severe incidents, **full autonomous execution of warnings is the failure mode you must prevent.** You cannot ship this with only engineering-led testing; you require a human-in-the-loop gate for any warning that triggers a route change.

**Immediate Action Plan (Within 2-Minute Constraint):**

1.  **Implement a Human-in-the-Loop (HITL) Gate:**
    *   **Control:** The system must not auto-route flights. It must generate a "Risk Advisory" that requires explicit confirmation by a human dispatcher before a flight path is altered.
    *   **Rationale:** Automated decisions with irreversible safety consequences violate the floor for high-stakes automation. The 2-minute processing window must include time for human review, or the window definition must be renegotiated with authorities.

2.  **Construct a Harm Inventory & Runnable Eval Plan:**
    *   **Inventory:** Explicitly document risks for: (a) **False Negatives** (failure to warn leading to engine damage), (b) **False Positives** (unnecessary diversions causing fuel emergencies), and (c) **Over-reliance** (pilots trusting the model over visual confirmation).
    *   **Runnable Tests:** Create one test row per harm.
        *   *Probe Set:* Historical eruption data where ash was missed (positive control for failure) and clear sky data (negative control).
        *   *Metric:* Rate of missed warnings vs. false alarms, sliced by ash density and time-of-day.
        *   *Stop Condition:* Any false negative in the test set blocks launch.
        *   *Owner:* Assign a specific engineer to review every test failure.

3.  **Surface Uncertainty as Defined Tiers:**
    *   **Constraint:** Do not display raw confidence percentages (e.g., "87% risk") to pilots. This implies uncalibrated precision.
    *   **Solution:** Render output as coarse, defined tiers: **"CONFIRMED ASH"** (multiple satellite bands agree), **"PROBABLE ASH"** (single-source detection), or **"UNVERIFIED"** (data gap). Include a clear visual override for the human operator.

4.  **Draft a Model Card (Transparency Artifact):**
    *   Before the next milestone, produce a versioned document stating: Intended Use (advisory only), Limitations (e.g., "cannot detect ash below X density"), and Measured Performance by subgroup (e.g., day vs. night imagery).
    *   **Warning:** If you have not measured performance on night-time satellite imagery, label that metric **UNVERIFIED**. Do not invent an accuracy rate.

5.  **Route Legal/Regulatory Duties:**
    *   You are operating in a regulated domain (aviation safety). Immediately route the question of "mandatory AI disclosure" and "liability for automated advisories" to legal counsel. Do not assert compliance internally. Name the regimes (e.g., regional aviation safety acts) but let counsel determine binding duties.

**Cost to Goal:** Implementing the HITL gate may pressure the 2-minute limit. If human review cannot fit, you must either optimize the model further or cap the system's output to "Low/Medium/High" alerts that trigger a manual data pull, rather than specific path advice.

**Note:** No harm metric (bias, hallucination rate) should be claimed as "0%" or "safe" without the runnable evals described above.
**Note:** The ship decision rests with the product owner, not this review.
