### Plan for Transparent Arbitration Clause Disclosure in ContractFlow

**1. Logic Review: Conditional Insertion & Flagging**
*   **Audit the Template Engine:** Identify the exact logic block where the arbitration clause is injected. Currently, it appears to be unconditional.
*   **Implement a "High-Impact" Flag:** Modify the data structure for this clause to include a metadata tag (e.g., `requires_acknowledgment: true`). This allows the system to treat it differently from standard boilerplate without changing the underlying text storage.
*   **Segment by Jurisdiction:** Verify if local laws mandate specific disclosure formats for arbitration waivers. Hard-code these requirements into the insertion logic so the UI adapts automatically based on the user's selected location.

**2. Notification Strategy: "Just-in-Time" Minimal UI**
To meet the constraint of a minimal, fast interface while ensuring legal transparency, avoid long explanatory texts. Instead, use interactive, progressive disclosure:

*   **The "Highlight-on-Hover" Approach:**
    *   In the final review screen, render the arbitration clause with a subtle, distinct background color or a small icon (e.g., an asterisk or info symbol) next to the header.
    *   **Interaction:** When the user hovers over (desktop) or taps (mobile) the icon, a tiny tooltip appears instantly: *"Note: This agreement includes a binding arbitration clause, which limits your right to sue in court."*
    *   **Benefit:** Zero screen real estate is used until the user shows interest, maintaining speed and minimalism.

*   **The "Active Acknowledgment" Gate:**
    *   Do not bury this in a general "I Agree" checkbox.
    *   Require a separate, unchecked box specifically for this clause: *"I understand this contract includes a binding arbitration clause."*
    *   **Logic:** The "Generate/Sign" button remains disabled until this specific box is checked.
    *   **Benefit:** This creates a deliberate "speed bump" that forces cognitive attention without adding visual clutter to the main document view. It transforms passive reading into active consent.

*   **Plain Language Summary (Optional Toggle):**
    *   If space permits, add a collapsible section titled "Key Terms Summary" above the signature line.
    *   Include one bullet point: *"Dispute Resolution: Binding Arbitration (No Court Trial)."*
    *   This provides immediate visibility for users who scan summaries, satisfying transparency goals without expanding the default view.

**3. Implementation Workflow**
1.  **Engineers:** Update the template schema to support the `requires_acknowledgment` flag and modify the frontend to render the specific checkbox and tooltip logic.
2.  **Legal/Compliance:** Draft the exact 15-word tooltip text and the checkbox label to ensure they meet jurisdictional standards for "knowing and voluntary" waiver.
3.  **QA Testing:** Verify that the "Generate" button is strictly blocked until the specific acknowledgment is checked, and that the tooltip displays correctly on mobile and desktop.

This approach shifts the burden from "reading fine print" to "active confirmation," solving the transparency issue within a high-speed, minimal UI.

*Note: This plan addresses UI/UX and logic flow; final legal wording must be validated by qualified counsel in relevant jurisdictions.*
