### Legal Accuracy Audit Framework for GovAssist Translation Plugin

**Objective:** Systematically verify that translated outputs preserve the mandatory nature of legal obligations, ensuring no "must" statements are diluted into "may" or "suggestion" language.

#### 1. Establish the "Golden Source" Lexicon
Before auditing outputs, define the immutable rules within your current engine's constraints.
*   **Mandatory Keyword Mapping:** Create a strict lookup table pairing English legal imperatives (e.g., "must," "shall," "required to," "failure to will result in") with their only acceptable translations.
*   **Forbidden Softening List:** Identify and flag specific target-language phrases that imply optionality (e.g., "should," "it is recommended," "you can," "if possible"). Any occurrence of these in response to a mandatory source text is an automatic failure.
*   **Consequence Preservation:** Ensure that sentences describing penalties (deportation, rejection, fines) retain their definitive causal link (e.g., "If X is not done, Y *will* happen" must not become "Y *might* happen").

#### 2. The Three-Tier Audit Process
Given the team size of eleven, divide the audit into parallel workflows to meet the one-month deadline.

**Tier A: Automated Deterministic Checks (2 Team Members)**
Since external API upgrades are not possible, use simple script-based string matching on the output files.
*   Scan all translated outputs for the "Forbidden Softening List."
*   Cross-reference every instance of a "Mandatory Keyword" in the source text. If the source contains "must" and the translation lacks the corresponding mandatory equivalent, flag it immediately.
*   Generate a "Risk Report" listing every file and line number where mandatory language is missing or weakened.

**Tier B: Blind Pair Review (6 Team Members)**
Conduct human reviews using a "Blind Reconstruction" method to remove bias.
*   **Step 1:** Reviewer A reads *only* the translation and writes down what they believe the user is legally required to do.
*   **Step 2:** Reviewer B compares Reviewer A's summary against the original English legal text.
*   **Pass Criteria:** The summary must match the legal obligation exactly. If Reviewer A believes an action is optional when it is mandatory in the source, the translation fails.
*   **Focus Area:** Prioritize sections regarding deadlines, document submissions, and eligibility criteria.

**Tier C: Adversarial Edge-Case Testing (3 Team Members)**
Simulate confused users to find subtle dilutions.
*   Create test scenarios where following a "softened" instruction leads to application rejection.
*   Manually trace the logic of complex conditional sentences (e.g., "Unless X, you must Y"). Verify that the negation and the obligation are both preserved in the translation.
*   Review all error messages and help-text tooltips to ensure they do not contradict the main instructions.

#### 3. Remediation and Sign-off Protocol
*   **Severity Classification:** Label errors as "Critical" (changes legal obligation), "High" (ambiguous consequence), or "Low" (stylistic). Only "Critical" and "High" blocks release.
*   **The "Safe Harbor" Rule:** If a translation is ambiguous, the default fix must be the more restrictive/mandatory interpretation, not the softer one. It is safer to be overly stern than overly permissive in immigration contexts.
*   **Final Attestation:** For every form section, two team members must sign off confirming that the "Mandatory Keyword Mapping" was respected and the "Blind Reconstruction" test passed.

#### 4. Deployment Guardrails
*   **Freeze Non-Essential Changes:** With one month remaining, halt all updates except those fixing "Critical" mandatory language errors.
*   **User Warning Layer:** If any low-risk ambiguities remain unresolved by the deadline, inject a static, hard-coded disclaimer in the UI near those sections stating: "This section contains legal requirements. Please review the original English text if unsure."

By strictly separating automated keyword enforcement from human logical verification, this framework maximizes your team's efficiency while minimizing the risk of life-altering translation errors.

*Note: This framework relies solely on internal human review and basic string matching, requiring no new software or API access.*
*Prioritize forms with the highest deportation risks first if time becomes critical.*
