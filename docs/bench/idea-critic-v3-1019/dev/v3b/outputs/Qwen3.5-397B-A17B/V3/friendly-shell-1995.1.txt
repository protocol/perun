**Steelman:** A cartoon-house shell makes computing intuitive for novices, creating a new entry-level market segment before the next OS release.

**Attack:** The proposal fails on three verified blockers. First, the hardware requirement ("high-end PC") contradicts the target demographic ("many new home users"); in 1995, most homes possess mid-range or legacy machines incapable of running memory-intensive graphical shells smoothly. Second, the timing is fatal: a "major new operating-system release" arriving within months renders a $100 stopgap product obsolete immediately upon launch, destroying its value proposition. Third, the "patronizing" risk for experienced users limits the addressable market strictly to novices, while the lack of third-party add-ons prevents ecosystem growth, trapping the product as a dead end.

**Alternatives:** The "do nothing" option is superior because it preserves capital for the upcoming native OS update, which will likely address interface issues without requiring separate hardware or creating fragmentation. A cheaper alternative would be improving documentation or offering a simplified mode within the existing OS, rather than building a separate, resource-heavy application.

**Pre-mortem:** Six months post-launch, sales are near zero. The installed base was too small to support the high-end requirement, early adopters mocked the cartoon aesthetic, and the new OS release made the product redundant. The company is left with unsold inventory and a distracted engineering team.

**Blockers:** 
1. Hardware mismatch: Target users lack the required high-end PCs.
2. Obsolescence: Imminent OS release cannibalizes the product before ROI.
3. Market ceiling: Alienates experienced users; no ecosystem potential.

**Edge:** None identified. Being first to a "cartoon interface" is not an advantage if the hardware base cannot support it and a better solution is imminent.

**Kill Criteria:** If the target user base owns <20% high-end PCs, or if the new OS release is <6 months away, the project must stop. Both conditions are met here.

This plan commits resources to a product that the target audience cannot run, which will be obsolete almost immediately, and which offers no strategic advantage over the impending native update.

DECISION: NO-GO
