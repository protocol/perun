**Steelman:** A $100 cartoon house shell simplifies computing for novices on high-end PCs, creating an immediate on-ramp before the next OS release.

**Attack & Options:**
The proposal fails the fit and evidence tests. First, the hardware constraint is a blocker: "high-end PC" excludes the majority of 1995 home users who cannot afford the required memory, shrinking the addressable market to near zero. Second, the timing is fatal; a "major new operating-system release" arriving in months renders a separate $100 shell obsolete before it gains traction. Users will wait for the built-in solution rather than pay for a temporary bridge. Third, the "patronizing" risk alienates the growing segment of users gaining literacy, while the lack of third-party add-ons confirms no ecosystem exists to sustain it.

**Alternatives:**
1.  **Do Nothing:** Wait for the upcoming OS release to integrate accessibility features natively at no extra cost.
2.  **Software Only:** Release a simplified "mode" within existing software rather than a standalone $100 product.
3.  **The Proposal:** High cost, high hardware barrier, imminent obsolescence.

**Pre-mortem:**
Six months post-launch, sales are negligible. The installed base of high-end PCs was too small to support development costs. The new OS release included a "friendly" interface, making this product redundant. Retailers are stuck with unsold inventory.

**Blockers:**
1.  **Hardware Mismatch:** The target audience (new home users) statistically lacks the "high-end PC" required to run the software.
2.  **Imminent Obsolescence:** The confirmed upcoming OS release cannibalizes the value proposition immediately.
3.  **No Ecosystem:** Lack of add-ons indicates no developer interest or user demand for this specific metaphor.

**Edge:**
None identified. Being first with a cartoon interface is not an edge when the underlying hardware isn't there and a superior, integrated solution is imminent.

**Kill Criteria:**
If the current install base of high-end PCs is <10% of the target market, or if the new OS release date is <6 months away, the project must stop. Both conditions appear true based on the proposal's own facts.

**Decision:**
The plan relies on hardware users don't have and solves a problem the core OS will solve for free shortly.

DECISION: NO-GO
