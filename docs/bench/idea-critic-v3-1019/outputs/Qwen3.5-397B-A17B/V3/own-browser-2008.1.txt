Steelman: Releasing a fast, multi-process, open-source browser in 2008 secures the web's future against OS vendor lock-in, directly protecting the search company's core revenue dependency.

**Blockers:** NONE. The proposal explicitly addresses the primary technical hurdles (speed via a new engine, stability via separate processes) and the distribution hurdle (open-source leverage). The risk of straining the partner relationship is real but secondary to the existential threat of a single OS vendor controlling access; diversification is a strategic imperative, not an optional feature. The lack of prior desktop software experience is a execution risk, not a factual blocker, mitigated by the open-source model inviting community contribution.

**Risks:** Execution complexity is high given no prior desktop shipping history; partner friction may temporarily reduce search deal leverage; user inertia is significant. However, these are manageable risks compared to the cost of inaction (total dependence on one vendor's whims).

**Edge:** The company uniquely possesses the financial runway to fund a free product, the technical depth to build a superior JavaScript engine, and the strategic desperation (revenue dependence) to prioritize this over short-term harmony. Competitors lack the specific incentive to save the open web for their own survival.

**Decision Method:**
1.  **Do Nothing:** Reliance on the OS vendor increases; if they degrade third-party search, revenue collapses.
2.  **Alternative (Fund only):** Continuing to fund the existing open-source browser leaves the ecosystem fragile if that project stalls or if the OS vendor crushes it. Building a new, faster engine creates a competitive benchmark that forces the entire market to improve, benefiting the search company.
3.  **Fit:** Directly aligns with the North Star of "maximizing web usage."
4.  **Pre-mortem:** If this fails, it will be due to poor UI/UX adoption, not technology. The open-source nature limits financial loss.
5.  **Evidence:** The premise that revenue depends on web usage is factual. The market dominance of the OS vendor is factual.

The plan beats "do nothing" because it actively shapes the distribution layer rather than passively hoping for the best. It is a two-way door: if adoption fails, the code remains open source with limited sunk cost relative to total revenue at stake.

DECISION: GO
