The claim is that a merged real-time communication tool should launch to 100,000 users in 2009 to replace email. The steelman: a limited preview validates demand for unified collaboration before competitors do.

However, the proposal fails the blocker test. The stated facts reveal a fatal dependency loop: the tool is only useful if contacts join, yet invitations are scarce. Without existing density, the network effect cannot ignite, rendering the product useless to early adopters. This is a classic "cold start" failure that a 100,000-user blast cannot solve if those users cannot find anyone to talk to.

Furthermore, the environment is hostile. In 2009, browser performance is a hard constraint; running slowly guarantees abandonment before value is realized. The lack of interoperability with existing email severes the lifeline to the outside world, forcing a hard silo rather than a gradual migration. The confusion over the tool's purpose indicates a lack of product-market fit; scaling a confusing product simply amplifies confusion and churn.

The "better way" is to halt the broad preview. The path forward requires a closed alpha with pre-formed groups (high density) to solve the contact scarcity, performance optimization to meet 2009 browser limits, and clear positioning before any expansion. Releasing now wastes the invitation capital on a broken experience.

Blockers:
1. Network effect failure: Utility requires contacts, but invitations are scarce.
2. Technical viability: Performance is insufficient for current browsers.
3. Value proposition: Users are confused about the tool's purpose.

Edge: NONE. Being first to merge these features offers no advantage if the execution prevents usage. The risks are not theoretical; they are observed facts in the proposal.

DECISION: NO-GO
