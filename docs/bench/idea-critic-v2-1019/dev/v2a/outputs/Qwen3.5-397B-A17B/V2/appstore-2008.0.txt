The claim is that a closed, curated native app store will succeed where the CEO previously argued web apps sufficed, despite security risks, carrier friction, and review bottlenecks. The steelman: a single controlled store balances developer reach with product polish and security, creating a monetizable ecosystem that web apps cannot match in 2008.

Alternatives:
1. **Do nothing (Web Apps only):** Zero review load, no carrier conflict, but fails to unlock device hardware or high-performance experiences; likely cedes market to rivals with native ecosystems.
2. **Open Distribution (Sideloading):** Maximizes developer freedom, minimizes review cost, but invites malware, destabilizes the device, and guarantees carrier rebellion.
3. **Multiple Stores:** Dilutes curation, fragments user experience, and complicates revenue sharing without solving security.

The proposal beats "do nothing" because native code accesses sensors and GPU in ways 2008 web tech cannot, driving device differentiation. It beats open distribution by preventing the "race to the bottom" on security that would trigger carrier bans.

Pre-mortem: The store fails if the review process becomes a bottleneck that stifles innovation, or if the 30% fee drives top developers to rival open platforms. However, the "one-way door" of opening the OS is irreversible; once opened, closing it destroys trust. The cost of delay is catastrophic: rivals are already building ecosystems. Waiting for perfect security or carrier consensus means launching into a market where user habits are already formed elsewhere.

Evidence suggests users value functionality over theoretical polish, and carriers prioritize network stability over controlling services if the device sells. The 30% fee aligns incentives: the platform only wins if developers win. The review burden is a feature, not a bug, ensuring the "it just works" promise remains intact against untrusted code.

The strongest attack is that the review queue will stall innovation. This fails because a curated launch window creates scarcity and quality signaling, attracting premium developers first, while the alternative (chaos) repels them.

DECISION: GO
