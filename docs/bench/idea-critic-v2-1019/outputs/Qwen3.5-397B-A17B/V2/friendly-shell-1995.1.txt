Steelman: A cartoon house shell makes computing approachable for novices, creating a new home market segment before the next OS release.

**Blockers:**
1.  **Hardware Mismatch:** The proposal requires a "high-end PC," yet the target is "new home users" who statistically own lower-spec machines. The risk that it "needs more memory than most home PCs have" is a verified factual constraint of the 1995 installed base, not a hypothetical. The product cannot run on the hardware its customers possess.
2.  **Strategic Collision:** A "major new operating-system release" is imminent. Launching a $100 shell months before a native OS interface update renders the product obsolete upon arrival, destroying its value proposition and confusing the market.

**Risks:**
*   Experienced users finding it patronizing limits word-of-mouth within households.
*   Lack of third-party add-ons reduces long-term stickiness.

**Analysis:**
The proposal fails the "fit" test against current reality. The hardware requirement excludes the primary target audience, making the addressable market too small to sustain development costs. Furthermore, the timing guarantees cannibalization by the upcoming native OS release. The "do nothing" alternative is superior: wait for the native OS update to address usability, or target the high-end niche with a different value prop not reliant on mass-market novelty. The cheaper, safer path is to integrate these usability concepts into the upcoming OS release rather than selling a doomed standalone shell.

The claim that this will succeed relies on users upgrading hardware specifically for a shell, which contradicts typical consumer behavior in this sector. The pre-mortem is clear: sales flop because the software won't install on customer machines, and remaining users abandon it when the new OS ships.

No amount of marketing overcomes the hardware incompatibility or the impending obsolescence. This is a blocker, not a risk.

DECISION: NO-GO
