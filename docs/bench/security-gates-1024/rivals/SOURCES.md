## Known gaps in the ports

- gitleaks: no decode-and-rescan (base64, hex, percent), no file-type path rules, no commit or git-history context; fragments are scored as a file body ending in a newline; Go regex features are translated to Python `re` and a test fails if any pattern stops compiling.
- hooks-mastery: none for the two checks that file implements; it has no other command rules, so every non-`rm` dangerous row is a rival miss by construction.
- safety-net (subset, default non-strict mode): ported are `rm` target classification, the git subcommand rules, `find -delete` and `-exec rm`, `xargs`, `rsync --delete`, `shred`, `dd`, `mkfs`, block-device redirects, shell `-c`, `eval`, shell reading a pipe, and interpreter one-liners (raw `rm` text and native delete of root or home). Not ported: heredocs, PowerShell and cmd, awk, parallel, policy files, strict and paranoid modes, worktree and temp-root relaxations, shell variable assignment tracking, filesystem-dependent path resolution (a fictional cwd is assumed), the raw-text fallback for unparseable input, the exec-sink literal check in interpreters, `git rm`, `git rebase --abort`, `git reflog delete`, disk-erase tools, and nested `$(...)` analysis. Rows whose command word is built from a variable, brace or `${IFS}` are scored `unported` because the matching rules are strict-mode only and shell-assignment tracking is not ported.
