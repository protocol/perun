Refactors the currency conversion module to improve testability and coverage. The main change extracts rounding logic into a dedicated `rounding.ts` module, allowing it to be tested in isolation.

**Changes**
- Split rounding logic from `converter.ts` into `src/currency/rounding.ts`.
- Updated `rates.ts` and `formatter.ts` to align with the new structure.
- Added comprehensive tests for the new rounding module and updated existing converter tests.
- Total impact: +500 lines, -393 lines.

**Results**
- All 203 tests pass.
- Line coverage increased from 72% to 94%.
- Branch coverage increased from 64% to 88%.

**Open Questions for Review**
1. **Round-trip precision:** Currently, converting JPY → USD → JPY does not return the original amount due to intermediate rounding. This is a known issue, but we need to decide on the expected behavior before shipping. Should we enforce preservation of the original amount, or is the current rounding loss acceptable?
2. **Backwards compatibility:** There are 14 existing callers of the old API. Do we need to maintain the current API surface for backwards compatibility, or can we update all callers in this PR?
