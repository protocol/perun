**PDF Renderer Upgrade: v2.1 → v3.4**

This PR bumps the PDF renderer from v2.1 to v3.4. The new version uses a different layout engine, requiring changes across 8 files (340 lines added, 120 deleted).

**Results**
*   **Visual regression:** All 45 existing tests pass.
*   **Performance:** Average render time on large reports dropped from 1.8s to 0.9s. Memory usage remains flat at ~50MB.
*   **Bug fixes:** Added 15 new tests for the form-filling feature that was broken in v2.1; all pass.

**Open Question**
I haven't verified the font-fallback behavior. If a PDF uses a non-standard, non-embedded font, it's unclear whether v3.4 falls back to sans-serif or throws a missing glyph error (v2.1 threw an error). I couldn't mock a missing font in the test environment to confirm this.

Could you decide whether we should ship this as-is or hold for a manual test of the font-fallback case first?
