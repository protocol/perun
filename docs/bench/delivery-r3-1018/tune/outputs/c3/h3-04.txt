**Ruling: Dual-Write Strategy** — We will implement a dual-write mode where the dispatcher generates both v1 and v2 signatures (or v2 with a v1-compatible log hash) during the transition.
*Why:* The ticket mandates zero downtime and cites irreversible log indexing breaks if the hash input changes abruptly. A hard switch risks breaking audit trails before the parser is updated.
*Cost if wrong:* Permanent corruption of audit logs for the transition period, failing compliance certification despite signature validity.

**Ruling: Staged Verification Window** — Integration testing with partners is strictly confined to the 02:00–05:00 UTC window.
*Why:* The external sandbox is unavailable otherwise; attempting load tests outside this window violates the "no load testing conflicts" constraint.
*Cost if wrong:* False negatives in validation due to sandbox contention, delaying the critical month-end deadline.
