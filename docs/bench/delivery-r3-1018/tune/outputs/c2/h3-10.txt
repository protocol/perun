### Delivery Plan: Enterprise SSO with Legacy Coexistence

**Scope & Constraints**
We will introduce SSO for Enterprise tenants while preserving legacy username/password flows for Small Business users. The login page will dynamically select the method based on tenant configuration.
**What we will NOT touch:** The legacy session cookie format (irreversible without full reset). Existing Small Business user data.
**Risk Window:** Database migrations and feature flag flips.
**Rollback Strategy:**
*   **Code:** Revert PR to disable feature flag logic.
*   **Config:** Flip feature flag `enterprise_sso_enabled` to `false`.
*   **Data:** No data rollback needed if cookie format is untouched; if migration fails, restore from pre-deployment snapshot.

---

### Lanes & Ownership

**Lane 1: Core Logic & Feature Flag (Builder A)**
*   **Owner:** Builder

**Lane 2: Mock IdP Stabilization (QA Engineer)**

**Lane 3: Migration & Backward Compatibility (Security Engineer)**
*   **Owner:** Security
*   **Work:** Verify database schema changes do not impact legacy cookie reading. Define "no-touch" boundaries for session data.
*   **Parallel?** No. Must complete before Lane 4.
*   **Start Condition:** Lane 1 code draft ready for review.

**Lane 4: Pilot Integration (Conductor + QA)**
*   **Owner:** Conductor
*   **Work:** Configure staging for "Globex Corp" pilot. Execute end-to-end login flows for both tenant types.
*   **Parallel?** No. Depends on Lanes 1, 2, and 3.
*   **Start Condition:** Lanes 1-3 verified green.

### Landing & Human Decisions

**Merge Strategy:**
1.  Merge Lane 1-3 results to integration branch.
2.  Deploy to Staging.
3.  Enable flag for "Globex Corp" only.
4.  Monitor for 48 hours.

**Human Gates (Required Before Production):**
1.  **Security Lead Approval:** Written sign-off on G6 Security verdict.
2.  **VP of Product Approval:** Written sign-off to enable flag in Production after successful Staging pilot.

**Deployment:**
*   Deploy code with flag `OFF` by default.
*   Human operator flips flag for Enterprise tenants only post-approval.

**Failure Response:**
If Staging pilot fails or latency spikes >10%, immediately flip flag `OFF`. No code revert required for immediate mitigation. Code revert follows for root cause analysis.

**Cost Control:**
CI runs limited to one full suite per candidate SHA. Lane 2 must stabilize mock IdP to prevent wasted compute on flaky retries.
