To call the `optimize_tier_prices` endpoint in the OpenTariff REST API, you must send a `POST` request to the specific resource URL. This endpoint typically accepts a JSON payload containing current tariff structures, usage data, or optimization constraints, and returns a refined pricing model.

### 1. Authentication
OpenTariff generally uses Bearer Token authentication (OAuth 2.0). You must include the `Authorization` header in every request. Ensure your token is valid and has the necessary scopes (e.g., `tariff:write` or `optimization:execute`).

**Header Format:**
```http
Authorization: Bearer <YOUR_ACCESS_TOKEN>
Content-Type: application/json
```

Assume the base URL is `https://api.opentariff.io/v1`. The specific endpoint for this operation is usually `/tariffs/optimize_tier_prices`.

      {"kwh": 100, "time": "peak"},

    ]

### 3. The Response
Upon successful execution (HTTP 200 OK), the API returns a JSON object containing the optimized tier structure. While specific fields may vary by version, the standard response includes the following key fields:

*   **`optimization_id`**: A unique identifier for this specific calculation run.
*   **`status`**: Indicates the result state (e.g., `completed`, `partial`, `failed`).
*   **`original_cost`**: The total cost calculated using the pre-optimization tiers.
*   **`optimized_cost`**: The projected total cost using the new tiers.
*   **`savings_percent`**: The percentage reduction achieved.
*   **`tiers`**: An array of objects defining the new price breaks. Each object typically contains:
    *   `tier_level`: The sequence number (1, 2, 3...).
    *   `threshold_kwh`: The usage limit where this tier ends.

*   **`metadata`**: Optional object containing timestamps, algorithm version, or warning messages if constraints were relaxed.
