Several critical errors are evident in the provided readout based on the raw numbers.

First, there is a clear **SRM** (Sample Ratio Mismatch). While the user counts are nearly identical (~407k vs ~406k, consistent with 50/50 randomization), the session counts are drastically different. Control has 587,775 sessions while Treatment has only 460,904.
Calculation: Total sessions = 1,048,679. Expected per arm = 524,340.
Control deviation: (587,775 - 524,340) / 524,340 ≈ +12.1%.
Treatment deviation: (460,904 - 524,340) / 524,340 ≈ -12.1%.
A 12% deviation in session volume despite equal user allocation indicates broken logging or assignment logic at the session level, invalidating the experiment.

Second, there is a **DENOM** error. The metric is "order conversion rate," and users were randomized by user ID. Therefore, the denominator must be users. However, the reported rates match the session-based calculation, not the user-based one.
Calculation (User-based): Control = 12,218 / 407,274 ≈ 3.00%. Treatment = 12,877 / 406,514 ≈ 3.17%.
Calculation (Session-based, matching report): Control = 12,218 / 587,775 ≈ 2.079%. Treatment = 12,877 / 460,904 ≈ 2.794%.
The team divided orders by sessions instead of users. Since the session counts are mismatched (see SRM), this artificially inflates the treatment lift.

Third, there is **NOVELTY**. The daily lift data shows high volatility but no consistent fading trend; however, the projection applies the current lift to the next twelve months. More critically, the SRM and DENOM errors make the lift itself spurious. But looking strictly at the daily numbers provided (39.4% down to 32.6% with fluctuations), there isn't a definitive monotonic fade to prove novelty purely from the trend line alone without more statistical testing on the trend. However, the SRM and DENOM are definitive.

Wait, re-evaluating **SIMPSON**.
Desktop Lift: (7879/148063) / (7476/148340) - 1 ≈ 5.64% / 5.04% - 1 ≈ 11.9%.
Mobile Lift: (4998/258451) / (4742/258934) - 1 ≈ 1.93% / 1.83% - 1 ≈ 5.5%.
Both segments show positive lift (~12% and ~5.5%). The pooled reported lift is 34.4% (which is wrong due to DENOM). If we calculate the correct pooled user-based lift: (3.17% / 3.00%) - 1 ≈ 5.6%.
The segments (11.9%, 5.5%) and the correct pooled (5.6%) are all positive. The reported 34.4% is an artifact of the denominator error, not Simpson's paradox reversing the sign. So SIMPSON is not the primary issue, DENOM is.

The SRM and DENOM errors are fatal. The session count mismatch suggests the treatment group users are generating fewer sessions, or control users are generating more, which biases the session-based rate. Using sessions as the denominator when randomization is by user is a fundamental methodological failure.

ERRORS: SRM, DENOM
DECISION: HOLD
