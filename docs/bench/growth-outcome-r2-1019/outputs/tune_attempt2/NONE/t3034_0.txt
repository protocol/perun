**SRM Check**: Total users = 43,566 (Control) + 43,304 (Treatment) = 86,870. Expected per arm = 43,435.
Difference = 131 users. Standard Error ≈ $\sqrt{86870 \times 0.5 \times 0.5} \approx 147$.
The deviation is $< 1$ standard error. This is well within chance; no SRM.

**PEEK Check**: Planned duration was 28 days. The readout date is 2026-08-19, which is 20 days after the start (2026-07-30). The test was stopped 8 days early. Stopping before the planned duration based on interim results inflates false positives. **PEEK flagged.**

**POWER Check**: Baseline 6.0%, target lift 8% (absolute 0.48%).
Required sample size per arm (approx) for 80% power, $\alpha=0.05$:
$n \approx \frac{16 \times p(1-p)}{\Delta^2} = \frac{16 \times 0.06 \times 0.94}{0.0048^2} \approx \frac{0.9024}{0.00002304} \approx 39,166$.
Actual sample sizes (~43k) exceed the requirement. The test is adequately powered. No POWER error.

**SIMPSON Check**:
Control Rate: Desktop = $1851/20296 \approx 9.12\%$; Mobile = $763/23270 \approx 3.28\%$.
Treatment Rate: Desktop = $1986/22446 \approx 8.85\%$; Mobile = $664/20858 \approx 3.18\%$.
In both segments, Control > Treatment (negative lift).
However, the reported aggregate shows Treatment (6.12%) > Control (6.0%) (positive lift).
The direction reverses when pooling data. **SIMPSON flagged.**

**DENOM Check**: Randomized by user ID. Metric is order conversion rate (Orders/Users). The denominator matches the randomization unit. No DENOM error.

**NOVELTY Check**: Daily lift values hover consistently between 1.4% and 2.3% with no visible downward trend over the 20 days. There is no evidence of fading. No NOVELTY error.

The test has critical flaws: it was stopped early (PEEK), and the aggregate result is misleading due to Simpson's Paradox (the treatment actually performs worse in both device segments). The recommendation to roll out is unsupported.
