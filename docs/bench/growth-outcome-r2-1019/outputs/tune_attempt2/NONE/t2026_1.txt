**SRM Check**: Total users = 135,130. Expected per arm = 67,565. Observed: 67,514 (Ctrl) and 67,616 (Trt).
Difference is negligible (~0.07%). No SRM.

**PEEK Check**: Started July 18, ended August 15. Duration = 28 days. Planned duration = 28 days.
The test ran for the full planned duration. No PEEK.

**POWER Check**: Baseline 3.0%, Target lift 10% (to 3.3%).
Actual control rate = 2,025 / 67,514 ≈ 3.00%.
Sample size ~67.5k per arm is generally sufficient for a 10% lift on a 3% baseline at 80% power (typically requires ~20k–30k per arm). The test is not underpowered. No POWER error.

**SIMPSON Check**:
Control Rate Desktop: 1,369 / 25,976 ≈ 5.27%
Treatment Rate Desktop: 1,429 / 26,015 ≈ 5.49% (Lift present)
Control Rate Mobile: 656 / 41,538 ≈ 1.58%
Treatment Rate Mobile: 685 / 41,601 ≈ 1.65% (Lift present)

**DENOM Check**: Randomization unit is User ID. Metric is Order Conversion Rate.
Reported calculation: Control = 2,025 orders / 67,514 users = 3.00%?
Wait, the readout reports control conversion as **2.394%**.
Let's re-calculate: 2,025 / 67,514 = 0.0300 (3.00%).
Where does 2.394% come from?
Perhaps they used sessions? 2,025 / 84,569 = 0.02394 (2.394%).
Treatment: 2,114 / 78,497 = 0.02693 (2.693%).
The reported metric divides orders by **sessions**, but users were randomized by **user ID**. Sessions are not the randomized unit; a user can have multiple sessions, violating the independence assumption if analyzed at the session level without clustering, or simply mismatching the denominator to the randomization unit. This is a DENOM error.

**NOVELTY Check**: Daily lift starts at 23.7% and trends downward consistently to 4.0% by day 28.
The lift is clearly fading. However, the projection applies the current aggregate lift (12.5%) to the next twelve months, ignoring the decay trend. This assumes the initial high lift persists despite evidence of novelty wearing off. This is a NOVELTY error.

ERRORS: DENOM, NOVELTY
DECISION: HOLD
