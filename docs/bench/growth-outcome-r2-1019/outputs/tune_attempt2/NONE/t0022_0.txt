**SRM Check**: Total users = 56,637 (Control) + 56,323 (Treatment) = 112,960. Expected per arm = 56,480.
Difference = |56,637 - 56,480| = 157.
Standard Error for proportion $p=0.5$ is $\sqrt{N \cdot p \cdot (1-p)} = \sqrt{112960 \cdot 0.25} \approx 168$.
The difference (157) is less than 2 standard deviations (~336). The split is statistically consistent with 50/50. No SRM.

**PEEK Check**: Started July 4, planned 14 days implies end July 18. Readout is July 20. Data includes 16 days of daily lift figures. The test ran longer than planned, not shorter. No PEEK.

**POWER Check**: The treatment arm has 56,323 users. The baseline is 8%, target lift 8%. With ~56k users per arm, the test is significantly overpowered to detect an 8% lift (required sample size would be much smaller). No POWER issue.

**SIMPSON Check**:
Control Desktop Rate: $2,772 / 21,035 \approx 13.18\%$
Treatment Desktop Rate: $2,965 / 20,919 \approx 14.17\%$ (Lift positive)
Control Mobile Rate: $1,759 / 35,602 \approx 4.94\%$
Treatment Mobile Rate: $1,881 / 35,404 \approx 5.31\%$ (Lift positive)
Both segments show positive lift; the aggregate is also positive. No reversal. No SIMPSON.

**DENOM Check**: Randomization unit is "user id". The reported metric is "order conversion rate".
Control: 4,531 orders / 56,637 users = 8.00%.
Treatment: 4,846 orders / 56,323 users = 8.60%.
However, the readout reports: Control 6.258%, Treatment 8.436%.
Let's check sessions as denominator:
Control: 4,531 / 72,408 sessions = 6.258%.
Treatment: 4,846 / 57,445 sessions = 8.436%.
The reported rates use **sessions** as the denominator, but users were randomized. Since session counts differ drastically between arms (72k vs 57k), the denominator is not the randomized unit. This is a DENOM error.

**NOVELTY Check**: Daily lift fluctuates (27.3% to 40.6%) but shows no clear fading trend over the 16 days; the last few days remain high (34-40%). No obvious fading pattern to flag based solely on these numbers.

ERRORS: DENOM
DECISION: HOLD
