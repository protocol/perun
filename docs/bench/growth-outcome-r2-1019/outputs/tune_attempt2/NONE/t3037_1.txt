**SRM Check**: Total users = 28,578 (Control) + 28,734 (Treatment) = 57,312. Expected per arm = 28,656.
Difference = 78 users. Standard Error ≈ $\sqrt{57312 \times 0.5 \times 0.5} \approx 119.6$.
The deviation is $78/119.6 \approx 0.65$ standard deviations. This is well within chance (typically < 1.96 SD for 95% confidence). No SRM.

**PEEK Check**: Planned duration = 28 days. Final readout date = 2026-08-12. Start date = 2026-07-23.
Duration elapsed = 20 days (July has 31 days: 8 remaining in July + 12 in August).
The test was stopped at 20/28 (71%) of the planned duration. The p-value (0.0604) is not significant, but stopping early without reaching the sample size required for the planned power invalidates the statistical guarantees if the decision relies on the current p-value crossing a threshold later or if the stop was driven by seeing "good enough" numbers. However, the specific error definition states "stopped... before planned duration, which inflates false positives." Since the result is not significant ($p > 0.05$), the team isn't claiming a win based on a false positive from peeking *yet*, but the analysis itself is flawed because the sample size is smaller than designed. More critically, the recommendation is to "roll out," implying they are treating the 6.3% lift as real despite $p=0.06$. Stopping early often leads to overestimating effect sizes (winner's curse). Given the strict definition, stopping at day 20 of 28 constitutes PEEK.

**POWER Check**: The test is underpowered if it cannot detect the target lift.
Target lift = 8%. Baseline = 6%.
Observed lift = 6.3%. P-value = 0.0604.
With ~28k users per arm, can we detect 8%?
Standard error of difference in proportions $\approx \sqrt{2 \times 0.06 \times 0.94 / 28600} \approx 0.00198$.
Detectable lift (8%) = $0.06 \times 0.08 = 0.0048$.
Z-score for target lift $\approx 0.0048 / 0.00198 \approx 2.42$. This corresponds to high power (>80%). The sample size seems sufficient for the *target* lift, but the *observed* lift is smaller. The definition asks if the arm is "too small to detect the target lift". Calculations suggest n=28k is enough for 8% lift. No POWER error based on design parameters.

**DENOM Check**: Randomized by user id. Metric is order conversion rate (Orders / Users).

The denominator matches the randomization unit. No DENOM.

**NOVELTY Check**:
Daily lift trend: 11.6% (Day 1) down to 2.8% (Day 19), slight uptick to 4.1% (Day 20).
Clear fading trend (11.6 -> 2.8).
The team projects the *reported* average lift (6.3%) for the next twelve months.
Applying a fading novelty lift as a permanent gain is a classic NOVELTY error.
