First, I check for Sample Ratio Mismatch (SRM). The total users are 56,320 (control) + 56,362 (treatment) = 112,682. The expected split is 50%, so 56,341 per arm. The observed difference is only 42 users. This is well within the range of chance for this sample size (standard deviation $\approx \sqrt{112682 \times 0.5 \times 0.5} \approx 168$; $42 < 2 \times 168$). No SRM.

Next, I check for PEEKing. The planned duration was 21 days. The readout date is March 25, and the start date is March 3. This is exactly 22 days of data (inclusive counting or slight overrun), which aligns with completing the 21-day plan. The daily lift data shows 22 data points. There is no evidence the test was stopped early based on interim looks; it ran to completion. No PEEK.

Next, I check for POWER. The baseline is 8%, target lift 8%. With ~56k users per arm, the sample size is generally sufficient to detect an 8% lift on an 8% baseline at 80% power and 0.05 alpha. The p-value (0.0044) confirms significance. No POWER issue.

Next, I check for SIMPSON's paradox. I must calculate the conversion rates per segment.
Desktop Control: $3,112 / 22,601 \approx 13.77\%$.
Desktop Treatment: $3,755 / 29,626 \approx 12.67\%$.
Lift Desktop: Treatment is lower than Control ($12.67 < 13.77$).

Mobile Control: $1,394 / 33,719 \approx 4.13\%$.
Mobile Treatment: $1,017 / 26,736 \approx 3.80\%$.
Lift Mobile: Treatment is lower than Control ($3.80 < 4.13$).

In both segments, the treatment performs worse than the control. However, the aggregated report claims a positive lift (8.467% vs 8.001%).
Aggregate Control Rate: $4,506 / 56,320 \approx 8.00\%$.
Aggregate Treatment Rate: $4,772 / 56,362 \approx 8.47\%$.
The direction of the effect reverses when pooling the data because the treatment arm has a much higher proportion of Desktop users (who have higher baseline conversion) compared to the control arm.
Treatment Desktop Share: $29,626 / 56,362 \approx 52.6\%$.
Control Desktop Share: $22,601 / 56,320 \approx 40.1\%$.
This is a clear case of Simpson's Paradox. The pooled result is misleading.

NOVELTY: The daily lift fluctuates (4.7% to 7.0%) but shows no clear fading trend over the 22 days.
DENOM: The metric is order conversion rate. The denominator implies orders per user (since randomized by user ID). The counts provided are users and orders. $4506/56320$ matches the reported %. The denominator matches the randomization unit.

The critical error is SIMPSON. The aggregate lift is positive only because the treatment group was skewed toward high-converting desktop users, while the treatment actually hurt performance on both desktop and mobile individually. Rolling this out would likely decrease overall conversions.
