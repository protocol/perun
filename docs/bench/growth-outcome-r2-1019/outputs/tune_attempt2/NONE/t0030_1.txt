**SRM Check**: Total users are 225,943 (Control) vs 226,169 (Treatment). The split is effectively 50/50 (difference < 0.1%). No Sample Ratio Mismatch.

**PEEK Check**: Planned duration was 21 days; the readout covers 23 days (Aug 1 to Aug 23). The test ran slightly longer than planned, not shorter. No early stopping evidence.

**POWER Check**: With ~226k users per arm and a 5% baseline, the sample size is massive compared to the target 5% lift. The test is not underpowered.

**SIMPSON Check**: Let's calculate segment conversion rates (Orders / Users):
- Desktop Control: 7,767 / 99,135 ≈ 7.83%
- Desktop Treatment: 8,212 / 99,234 ≈ 8.28% (Lift positive)
- Mobile Control: 3,530 / 126,808 ≈ 2.78%
- Mobile Treatment: 3,732 / 126,935 ≈ 2.94% (Lift positive)
Both segments show a positive lift. The pooled result is not reversed. No Simpson's Paradox.

**DENOM Check**: Randomization was by **user id**. The reported metric is "order conversion rate."
- Control Rate Calculation: 11,297 orders / 225,943 users = 5.00%.
- However, the readout reports Control as **3.598%**.
- If we divide by sessions: 11,297 / 313,939 ≈ 3.598%.
The reported rate uses **sessions** as the denominator, but users were the randomized unit. This violates the unit of analysis, invalidating the p-value and confidence intervals because session counts differ significantly between arms (313k vs 248k), introducing bias.

**NOVELTY Check**: Daily lift drops from 81.9% (Day 1) to 7.7% (Day 22). Despite this clear fading trend suggesting a novelty effect, the team projects the current aggregate lift (33.4%) for the next twelve months. This ignores the decay.

Two errors are present: DENOM (wrong denominator) and NOVELTY (ignoring fade).

ERRORS: DENOM, NOVELTY
DECISION: HOLD
