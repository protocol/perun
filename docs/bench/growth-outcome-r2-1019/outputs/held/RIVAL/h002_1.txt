The test stopped on day 28 of a planned 28-day duration, but the sample size is insufficient for the target 5% lift. With a baseline of 8%, detecting a 5% relative lift (to 8.4%) requires ~150k users per variant. While total users exceed this, the analysis uses sessions (133k/135k) while randomization was by user ID, creating a DENOM error risk if users have multiple sessions. More critically, the daily lift shows no fading pattern (ruling out NOVELTY), and segment data doesn't show reversal (ruling out SIMPSON). However, stopping exactly at planned duration without confirming final sample size adequacy for the actual observed variance suggests PEEK risk if interim checks influenced the stop. The session-vs-user mismatch (DENOM) invalidates the conversion rate calculation since the unit of analysis differs from randomization unit.
