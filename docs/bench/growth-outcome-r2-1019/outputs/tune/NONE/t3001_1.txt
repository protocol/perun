The randomization unit is user ID, but the reported metric uses sessions as the denominator (control: 239,806 sessions vs. ~168k users; treatment: 233,522 sessions vs. ~168k users). This violates the requirement that the analysis unit matches the randomization unit, risking bias from users with multiple sessions. This is a DENOM error.

Additionally, the segment data shows conversion rates calculated per user (orders/users), while the overall rate uses sessions. For example, desktop control rate is 4,562/69,870 ≈ 6.5%, not matching the pooled session-based 4.0%. This inconsistency confirms the denominator mismatch.

No clear evidence of SRM (user counts are nearly equal), PEEK (ran full duration), POWER (sample sizes appear sufficient), SIMPSON (segment lifts align with overall), or NOVELTY (daily lift is stable).
