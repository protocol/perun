The readout shows a clear Sample Ratio Mismatch (SRM). With a 50/50 allocation by user ID, the arms should have roughly equal session counts. However, Control has 70,038 sessions while Treatment has only 62,261. This ~11% difference is far too large to be due to chance, indicating broken assignment or logging.

Additionally, the metric denominator is Sessions, but randomization occurred by User ID. If users generated different numbers of sessions across arms, this violates the unit of analysis, triggering a Denominator (DENOM) error. The daily lift data appears stable, ruling out NOVELTY. Segment data sums correctly to totals, avoiding SIMPSON. The test ran for the planned 28 days (Oct 8 to Nov 6), avoiding PEEK. Given the fundamental data integrity issues from SRM and DENOM, the results are unreliable.

ERRORS: SRM, DENOM
DECISION: HOLD
