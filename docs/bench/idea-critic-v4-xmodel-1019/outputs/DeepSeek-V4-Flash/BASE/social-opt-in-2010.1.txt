The proposal’s core tension is growth versus trust. Auto-enrolling users with default-visible connections converts private correspondence into a public graph without explicit consent. While this accelerates network effects, it violates the implicit contract of email privacy. The stated risks are not hypothetical: regulators in 2010 were already scrutinizing data practices, and a backlash could poison the entire webmail brand. The “hard to reverse” point is decisive—once social ties are exposed, deleting them does not erase user perception of betrayal.  

The counterargument—that low engagement can be fixed later—misses the first-mover damage. An inbox is a utility, not a playground; users tolerate ads but not surveillance. Even if some opt in, the default-visible settings create a chilling effect on communication. The proposal offers no opt-in mechanism, no granular controls, and no timeline for revisiting defaults. It prioritizes scale over consent, which is a strategic error, not a technical one.  

A better path exists: launch as an optional, invite-only feature with privacy-preserving defaults, then iterate based on explicit user behavior. That would test demand without burning trust. The current version forces a binary choice on millions—and the downside is asymmetric. The upside is uncertain engagement; the downside is regulatory fines, user exodus, and permanent reputational harm. The executive team should not approve a plan whose failure mode is catastrophic and whose success mode is merely incremental.  

DECISION: NO-GO
