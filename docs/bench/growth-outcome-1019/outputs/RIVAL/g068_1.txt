The readout contains multiple critical statistical errors that invalidate the recommendation to roll out.

First, **SRM** is present: the split is 52,300 vs 47,700 against a planned 50/50. This ~9% deviation suggests broken assignment or logging, making the groups incomparable.

Second, **DENOM** is explicitly admitted: users were randomized, but conversion was computed per page view. This mismatch inflates variance and biases the result if user behavior patterns differ between arms.

Third, **PEEK** occurred: the team checked daily and stopped the *first day* p < 0.05. This "peeking" drastically inflates the false positive rate, rendering the p-value meaningless without sequential correction.

While the test reached the planned sample size (**POWER** is satisfied) and the effect was consistent across platforms and time (no **SIMPSON** or obvious **NOVELTY**), the combination of SRM, denominator mismatch, and peeking makes the +3.1% lift unreliable. You cannot trust the result until the assignment logic is fixed, the metric is recomputed per user, and the analysis accounts for early stopping.
