The readout contains two critical methodological errors that invalidate the results.

First, **PEEK**: The team "checked the dashboard every day and stopped the test the first day p fell below 0.05." This is classic optional stopping (peeking), which drastically inflates the false positive rate. A p-value of 0.05 is only valid if the sample size was fixed in advance and analyzed once at the end. Monitoring daily and stopping at the first sign of significance renders the p-value meaningless.

Second, **DENOM**: The readout states, "Conversion is computed per page view although users were the unit randomized." When randomization occurs at the user level, the analysis must also be at the user level. Using page views as the denominator treats multiple views from the same user as independent data points, violating statistical independence assumptions and artificially narrowing confidence intervals.

While the sample size met the power requirement (**POWER** is not flagged) and the split appears balanced (**SRM** is not flagged), the combination of optional stopping and the wrong analysis unit makes the reported "significant" lift unreliable. The consistent lift over 28 days does not cure the peeking problem if the stopping rule was based on daily p-values.

ERRORS: PEEK, DENOM
DECISION: HOLD
