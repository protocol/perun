The readout contains three critical analysis errors that invalidate the recommendation to ship.

First, **SRM** is present: the arms received 52,300 and 47,700 users against a planned 50/50 split. This significant deviation suggests broken assignment or logging, making the groups incomparable.

Second, **DENOM** is explicitly admitted: users were the randomized unit, but conversion was computed per page view. This mismatch inflates false positives because multiple views from a single user violate independence assumptions.

Third, **PEEK** occurred: the team checked the dashboard daily and stopped the moment $p < 0.05$. This "peeking" behavior drastically inflates the false-positive rate far above the nominal 5%, rendering the significance claim unreliable. While the test reached the planned sample size (addressing POWER) and the lift was consistent over time (mitigating NOVELTY) and across segments (avoiding SIMPSON), the combination of sample ratio mismatch, denominator error, and sequential peeking makes the result untrustworthy.

You cannot roll out a change based on a test where the groups were likely biased from the start, the metric calculation was mathematically flawed, and the stopping rule guaranteed a false win. Recompute the metrics using the correct denominator (users), investigate the cause of the traffic imbalance, and re-evaluate significance using a proper sequential testing bound or a fixed-horizon analysis without peeking.
