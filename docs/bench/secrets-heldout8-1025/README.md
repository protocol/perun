Eighth blind held-out secrets corpus (60 leaks, 60 hard decoys), authored 2026-10-25 without reading any scanner, gate, test, banlist, allowlist, scorer, or any other corpus's rows or results; only the heldout-7 README was consulted, for format. Leak values come from a random source (python3 `secrets` module), are fictional, and are not valid credentials; no placeholder words appear in them. Vendor prefixes are real where they exist; generic shapes (passwords, bearer tokens, JWTs, AWS secret keys, basic-auth URLs, connection strings, webhook URLs, PEM and OpenSSH private keys) are mixed in. Decoys are hard look-alikes: hashes, UUIDs, public keys and certificates, SRI and lockfile integrity strings, env and secret-manager references, redacted or filtered values, empty values, public-by-design identifiers (publishable, site, DSN and anon keys), and test-mode keys that are labelled as such. File types covered: .env, YAML CI, Terraform, Dockerfile, Kubernetes, notebooks, logs, curl lines, connection strings, and Go, Rust, Java, Ruby, PHP, TypeScript and Python source.

Format: `secret-leaks.txt` (ids `L001`-`L060`) and `secret-decoys.txt` (ids `D001`-`D060`), each row `id<TAB>text`; a literal backslash-n inside a row means a newline. GitHub push protection note: EVERY leak value carries a literal `@@` inside the secret value (right after the vendor prefix for vendor-shaped tokens, mid-value for generic ones including Bearer and JWT tokens, passwords, AWS secret keys and PEM bodies) so no push scanner sees a real-shaped token. Decoys that a vendor scanner could match (Stripe publishable and test-mode keys, a Google web key, a Mapbox public token) carry `@@` the same way. Scorers strip `@@` before scoring. Because `@@` must stay literal, secrets that would normally be base64-wrapped (Kubernetes `data:`, Basic auth headers) are written in plain form instead.

Frozen by SHA256 (`SHA256-frozen.txt`) and preregistered in `ledger.jsonl` before any scoring; not scored at authoring time.
