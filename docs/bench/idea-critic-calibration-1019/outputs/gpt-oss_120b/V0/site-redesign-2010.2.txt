**Steelman claim:** Rebuilding the site from scratch with a redesigned front page and publisher‑favored surfacing will modernize the experience, attract new traffic, and give publishers a stronger incentive to contribute, solving the current slowdown.

**Skeptical attack**

1. **Community core value:** The loyal community is built on open voting that determines story prominence. Changing that mechanic risks alienating the most engaged users, which historically drives traffic and content quality.  
2. **Engineering risk:** A full rewrite is a large, unproven effort. Historical data for similar projects shows a 30‑40 % chance of major delays or missed deadlines, especially when legacy data and scaling concerns are involved.  
3. **Rollback impossibility:** Deploying the new version to all users at once eliminates a safe fallback. If the new surfacing algorithm fails, the entire user base could experience a degraded experience with no quick revert path.  
4. **Competitive pressure:** A rival site is gaining momentum; a disruptive launch that harms existing users could accelerate user migration.

**Better‑way alternatives**

- **Incremental redesign:** Introduce UI changes gradually while preserving the voting engine, measuring impact via A/B tests.  
- **Phased rollout:** Deploy the new version to a small, opt‑in cohort first, allowing a controlled rollback.  
- **Hybrid surfacing:** Add publisher‑boosted slots without removing community voting, preserving the core value proposition.

**Kill‑criteria (pre‑mortem)**  

- If active daily users drop >20 % within two weeks of launch, abort and revert.  
- If engineering exceeds a three‑month timeline, halt the rewrite.  
- If no safe rollback mechanism can be built before launch, do not proceed.

**Conclusion:** The proposal’s risks outweigh its potential upside without mitigating steps. The safer path is an incremental, test‑driven approach.

DECISION: NO-GO
