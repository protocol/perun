**Diagnosis Plan: Mobile Dashboard Rollout (Nov 3)**

**Immediate Call:** Do not roll out to 100%. The 15% drop in mobile session duration is a critical retention signal that contradicts the desktop gain. Treat the mobile result as `UNVERIFIED` regarding cause (usability vs. content) until the specific slices below are analyzed. The assumption of "cramped layout" is a hypothesis, not a fact; validate it before choosing between a revert or a hotfix.

**Data Slices to Examine (Answering Named Questions)**
Instrument or query these specific cohorts immediately. Do not look at aggregate averages; they hide the failure mode.

1.  **The "Bail-Out" Rate (Activation/Retention Seam)**
    *   *Question:* Do mobile users abandon the session immediately upon loading the new dashboard, or do they engage briefly then leave?
    *   *Slice:* Compare **Time-to-First-Interaction** and **Bounce Rate** (sessions with 0 clicks) for Mobile New View vs. Mobile Control (if any remaining) or Pre-Rollout Baseline.
    *   *Interpretation:* A spike in immediate bounces suggests a rendering crash or such severe usability friction that users quit instantly (supports "cramped/broken"). If time-to-interaction is normal but total duration drops, users are failing to find value after starting (supports "content relevance" or "workflow mismatch").

2.  **Core Action Completion by Device**
    *   *Question:* Are mobile users failing to complete the specific "core action" the dashboard enables?
    *   *Slice:* Funnel conversion for the top 3 primary actions (e.g., "View Detail," "Export," "Filter") segmented by Device Type and View Version.
    *   *Interpretation:* If desktop conversion rose while mobile conversion fell, the layout specifically blocks the core value on small screens. If both dropped (but desktop time rose), the content itself may be irrelevant, and desktop users are just confused (reading longer but not acting).

3.  **Error & Rage Click Taxonomy**
    *   *Question:* Is the drop driven by technical failure or interaction frustration?
    *   *Slice:* Correlate the session duration drop with client-side JavaScript errors specific to mobile viewports and "rage click" events (multiple rapid taps on non-interactive elements).
    *   *Interpretation:* High error rates or rage clicks on specific UI components confirm a rendering/usability defect. Low errors with low duration suggests the new view simply doesn't fit the mobile "quick check" use case.

4.  **Segment by User Tenure/Power**
    *   *Question:* Is this hurting new users (onboarding leak) or power users (retention leak)?
    *   *Slice:* Cohort the drop by "New vs. Returning" mobile users.
    *   *Interpretation:* If power users (who know the old flow) are the ones leaving, the change broke their muscle memory (usability). If new users are unaffected, the issue is specific to experienced workflows.

**Decision Framework for Tuesday**
*   **Revert Immediately If:** Mobile bounce rate > +10% baseline OR core action conversion drops > 5% AND error/rage-click rates spike. This indicates a broken experience.
*   **Hotfix (Iterate) If:** Bounce rate is stable, but session duration and actions drop. This indicates a design mismatch (e.g., too cramped) that can be tuned without a full revert.
*   **Proceed with Caution If:** Mobile metrics are flat but desktop is up. The "dip" may be noise or a temporary novelty effect; extend the 50% holdout and monitor retention cohorts for 7 days.

**This Week's Step:** Run the four slices above on the Nov 3–Today data. Present the **Mobile Core Action Conversion Rate** and **Bounce Rate** delta to the engineering lead. If conversion is down, draft the revert plan. If only duration is down, prototype a "compact mode" toggle for the next build.
