## Phase 2: Event Taxonomy Criteria (Day 3)
**Goal:** Define rules for restoring vs. retiring legacy events. Present this matrix to the CTO.

| Criteria | Restore Event | Retire Event |
| :--- | :--- | :--- |
| **Decision Impact** | Directly informs a product or marketing decision (e.g., "Should we push Super Likes?") | Was purely vanity or never used in a report/dashboard |
| **Funnel Integrity** | Required to calculate a step-to-step conversion rate in the core journey | Represents a dead-end or redundant UI interaction |
| **Hypothesis Testing** | Essential for validating current Q2 growth hypotheses (e.g., Super Like → Conversion) | Related to deprecated features or old UI versions |
| **Data Quality** | Has clear, consistent properties (e.g., `location`, `device_type`) | Historically suffered from high null rates or inconsistent firing |

**Rule of Thumb:** If an event does not map to a specific question in your current growth backlog, it remains retired.

## Phase 3: Validation Protocol (Day 4-5)
**Goal:** Ensure data reliability before scaling acquisition spend.

1.  **Define the "Golden Path":** Map the exact user flow for a free user becoming a subscriber. List the 5-7 events that *must* fire in order.
2.  **Implement Staging QA:**
    *   Create test accounts for each user type (Free, Subscriber, Churned).
    *   Execute the Golden Path manually.
    *   Verify events fire in the correct order with correct properties using GA4 DebugView or your analytics tool's real-time stream.
3.  **Shadow Comparison:** If possible, run the new tracking alongside a small subset of traffic (5%) and compare aggregate counts against historical baselines (adjusted for seasonality) to spot massive deviations.
4.  **Sign-off Gate:** Do not increase ad spend until the "Swipe-to-Chat" conversion rate stabilizes within a 5% variance of pre-refactor benchmarks for 48 hours.
