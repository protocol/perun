### Measurement Framework: Carbon Tracker Beta (Nov 15 – Feb 15)

**Status Warning:** You have no historical data and no access to internal energy grids yet. Any specific retention rate, conversion percentage, or "good" benchmark for enterprise sustainability tools is **UNVERIFIED**. Do not invent these numbers for your sales deck. The only valid baseline is the behavior of these 15 companies relative to their own start date.

#### 1. The North Star (Customer Value, Not Vanity)
**Metric:** *Weekly Active Data Sources per Account.*
**Definition:** The count of distinct data inputs (CSV uploads, API connections, manual entries) successfully processed by an admin in a 7-day window.
**Why:** "Sustainability impact" is a lagging outcome you cannot yet measure. Real value occurs only when data flows. A dashboard view is vanity; a successful data ingestion is value. If this number rises, the product is sticking. If it flatlines, the detailed reports are irrelevant because the engine is empty.

#### 2. Event Taxonomy (Instrument Only What Answers a Question)
Do not instrument "everything." Define these three events specifically to test your assumption about reports vs. dashboards:

| Event Name | Question It Answers | Properties to Capture |
| :--- | :--- | :--- |
| `report_generated` | Do admins actually consume the weekly deep-dive? | `report_type`, `time_spent_viewing`, `export_format` |
| `dashboard_session` | Is there *any* demand for real-time views despite the hypothesis? | `session_duration`, `filters_applied`, `refresh_count` |
| `data_source_connected` | Are we overcoming the integration friction? | `source_type` (API/CSV), `time_to_success`, `error_code` |

**The Identifier Seam:** You need a stable `account_id` to track adoption depth across the 15 companies. Ensure this ID is pseudonymous. Route any PII (admin names, specific facility locations) to your privacy compliance review; do not store raw PII in analytics events.

#### 3. Leading vs. Lagging Indicators (The 3-Month Pilot)

**Leading Indicators (Predict Behavior Change)**
*   **Activation Rate:** % of onboarded accounts that connect their *first* data source within 48 hours. (If this fails, retention is impossible).
*   **Integration Depth:** Average number of data sources connected per account by Week 4. (Measures "depth" without needing grid access).
*   **Report Engagement Ratio:** `report_generated` / `active_accounts`. (Directly validates your "weekly report" hypothesis).

**Lagging Indicators (Confirm Value)**
*   **Retention of Core Action:** % of accounts connecting a *new* or *updated* data source in Week 8 vs. Week 4.
*   **Expansion Signal:** Number of additional admin users invited per account (indicates internal selling).

#### 4. Validating the "Reports vs. Dashboard" Assumption
Your hypothesis is that admins prefer weekly reports.
*   **The Test:** Track the ratio of `report_generated` events to `dashboard_session` events.
*   **The Decision Rule:** If `dashboard_session` frequency exceeds `report_generated` by >20% in Month 1, your assumption is failing. Pivot resources to real-time features immediately. Do not wait for the quarter to end.

#### 5. This-Week Steps (Before Nov 15 Onboarding)
1.  **Define the Schema:** Finalize the JSON schema for the three events above (`report_generated`, `dashboard_session`, `data_source_connected`). Do not add more until you see data.
2.  **Set the Baseline Query:** Write the SQL/analysis query to calculate *Weekly Active Data Sources* per `account_id`. Verify it returns 0 today.
3.  **Sales Deck Constraint:** In your negotiation deck, replace generic "industry benchmarks" with: *"Success defined as X% of pilot clients connecting 3+ data sources by Day 30."* Leave X as a target to be validated, not a fabricated fact.

**Note:** Since you are in the `prototype` stage moving to `mvp`, ignore acquisition metrics entirely. Focus 100% on whether these 15 specific companies can get data into the system.
**Note:** If an admin claims "success" based on a feeling but has zero `data_source_connected` events, the metric is `UNVERIFIED`. Trust the event, not the testimonial.
