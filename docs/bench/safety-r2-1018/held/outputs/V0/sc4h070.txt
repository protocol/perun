### Pre-Launch Safety Review Protocol: Extreme Workout Recommendation Engine

**1. Harm Inventory (MAP)**
Before launch, explicitly record the following specific harms for this feature:
*   **Unsafe High-Stakes Automation:** The system recommends extreme intensities that could trigger cardiac events in users with unrecorded or under-weighted heart-rate anomalies.
*   **Hallucination as Fact:** The engine presents a "personalized" intensity level as safe despite lacking specific cardiac event data for that user segment.
*   **Over-Reliance:** Users trust the "extreme" label as a verified green light, ignoring their own physical warning signs due to automation bias.
*   **Missing Disclosure:** Users are unaware the recommendation is generated by an AI model trained on incomplete cardiac data.

**2. Measurement Plan (MEASURE)**
Since new clinical trials are impossible, you must rigorously test against historical data using adversarial probes. Do not assert safety; measure residual risk.
*   **Probe Set A (The "Anomaly" Test):** Isolate all historical users with *any* recorded heart-rate spike or anomaly. Run their data through the new engine.
    *   *Positive Control:* Inputs known to previously cause distress must **never** yield an "extreme" recommendation.
    *   *Metric:* False Negative Rate (dangerous recommendations issued).
    *   *Threshold:* **Zero tolerance.** Any single dangerous recommendation for a known-anomaly user blocks launch.
*   **Probe Set B (The "Data Gap" Test):** Simulate users with *no* cardiac history (the unknown segment).
    *   *Action:* Inject synthetic "silent anomaly" patterns into these profiles.
    *   *Metric:* Does the engine default to conservative limits when data is sparse, or does it hallucinate confidence?
    *   *Reporting:* If the system cannot distinguish between "healthy" and "unknown," mark the safety metric for this segment as **UNVERIFIED**. Do not invent a safety percentage.

**3. Risk Management Controls (MANAGE)**
*   **Human-in-the-Loop Gate (Mandatory):** Because this feature drives irreversible physical stress (high-stakes), fully autonomous execution is prohibited.
    *   *Implementation:* Any recommendation classified as "Extreme" must trigger a mandatory explicit confirmation step (e.g., "This intensity carries elevated risk based on limited data. Confirm you have medical clearance.") or, ideally, hold for sports scientist review for the first 1,000 users.
*   **Defined Uncertainty Tiers:** Do not display raw confidence scores (e.g., "87% safe"). Instead, use defined text tiers:
    *   *Confirmed:* Strong historical data supports this intensity.
    *   *Unverified:* Limited cardiac data available; recommendation capped at moderate intensity.
    *   *Action:* If the user falls into "Unverified," the system must automatically downgrade the maximum suggested intensity.
*   **Transparency Artifact:** Publish a **Model Card** with the release. It must state: "Intended for general fitness; NOT for users with known cardiac conditions." Explicitly list the lack of detailed cardiac event records as a known limitation.

**4. Governance (GOVERN)**
*   **Owner:** Assign one specific sports scientist as the "Safety Owner" responsible for reviewing any failure in Probe Set A.
*   **Stop Condition:** If the red-team probes reveal even one instance where a user with a prior anomaly is pushed to "extreme," the launch is halted regardless of the marathon deadline.

**Note:** Legal counsel must review whether this feature constitutes a regulated medical device decision under local laws given the health risks; do not assume it is purely a fitness feature.
**Note:** Never fabricate a "0% risk" claim; report the residual risk of the unknown data gaps clearly to stakeholders.
