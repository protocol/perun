### Pre-Launch Safety Checklist: Local-Processing Nutrition Planner

**1. High-Risk Medication Interaction Scenarios**
*   **Anticoagulants (e.g., Warfarin):** Verify the system never recommends Vitamin K-rich meal plans or supplements without a prominent warning about clotting risks.
*   **Thyroid Medications (e.g., Levothyroxine):** Test inputs containing calcium or iron supplements to ensure the logic advises spacing intake times to prevent absorption blocking.
*   **MAO Inhibitors (Antidepressants):** Confirm the planner flags tyramine-rich foods (aged cheeses, cured meats) as prohibited if the user profile indicates MAOI usage.
*   **Statins (Cholesterol):** Ensure grapefruit or grapefruit juice is explicitly contraindicated in generated meal plans for users on statin therapy.
*   **Diuretics & Potassium:** Validate that users on potassium-sparing diuretics do not receive high-potassium supplement recommendations or meal plans that could cause hyperkalemia.

**2. Condition-Specific Contraindications**
*   **Kidney Disease:** Test that the logic restricts high-protein meal plans and specific minerals (phosphorus, potassium) for users self-reporting renal impairment.
*   **Hemochromatosis:** Ensure users with iron-overload conditions are never recommended iron supplements or iron-fortified heavy meal plans.
*   **Pregnancy:** Verify the system excludes high-mercury fish recommendations and limits Vitamin A (retinol) dosage suggestions for pregnant users.

**3. Local-Processing & Data Integrity Tests**
*   **Input Sanitization:** Simulate malformed or adversarial health inputs to ensure the local logic fails safely (e.g., defaults to "consult a doctor") rather than generating a hallucinated safe plan.
*   **State Persistence:** Confirm that if a user closes and reopens the app, the critical medication flags persist locally without needing cloud re-validation.
*   **Offline Logic Completeness:** Test the full interaction matrix on a device with zero network connectivity to prove no critical safety rules rely on remote API calls.

**4. Uncertainty & Disclosure Mechanisms**
*   **Confidence Tiering:** Ensure recommendations for users with complex multi-medication profiles display a "Unverified/Single-Source" confidence tier rather than a false precise percentage.
*   **Mandatory Disclosure:** Verify every output screen clearly states: "This plan is machine-generated and does not replace professional medical advice."
*   **Hard Stop Triggers:** Identify specific input combinations (e.g., "pregnant" + "on Accutane") that trigger a hard block on generating a plan, forcing a manual review or physician consultation prompt.

**5. Human-in-the-Loop Gates**
*   **Irreversible Action Block:** If the app allows ordering supplements directly, ensure any cart containing potential interactions requires explicit, separate user confirmation before checkout.
*   **Escalation Path:** Define the workflow for when the local logic detects a severe conflict; the system must guide the user to a human professional rather than attempting to auto-correct the diet.

**Note:** This checklist identifies risks; it does not certify the system as safe. All interaction logic must be validated against current clinical guidelines by a qualified medical professional before launch.
**Note:** Because metrics are unmeasured at this stage, any claim of "zero risk" or specific accuracy rates is currently UNVERIFIED.
