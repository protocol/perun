### Harm Inventory (MAP)
Before testing, we must name the specific harms this feature introduces:
*   **Unsafe High-Stakes Automation:** Remotely locking a door is an irreversible, high-stakes action. If a fire, medical emergency, or false positive billing error occurs, the system prevents escape.
*   **Bias/Unfair Outcomes:** Automated billing errors disproportionately impact vulnerable groups who may lack immediate access to dispute resolution channels, leading to immediate physical confinement.
*   **Missing Human Gate:** The proposed workflow lacks a mandatory human review before executing a physical lockout, violating the floor for high-stakes actions.
*   **Over-Reliance:** Engineering may trust the "unpaid" status as absolute fact, ignoring edge cases like payment processing delays or identity mismatches.

### Measurement Strategy Limitations (MEASURE)
You requested a testing strategy to ensure vulnerable populations are "never" accidentally locked out. **This metric is unmeasurable and cannot be certified.**
*   **No "Zero Harm" Proof:** You cannot test every possible emergency scenario (fire, panic, medical crisis) combined with every billing edge case to prove a 0% failure rate.
*   **Legacy Constraint Risk:** The inability to support two-factor authentication (2FA) for overrides removes the primary technical control for verifying human intent during an emergency override.
*   **Verdict:** Any test plan claiming to validate "safety" for this workflow would be fabricating a clearance metric. The residual risk is **UNVERIFIED** and inherently high because the system design allows fully autonomous denial of egress.

### Risk Management & Required Controls (MANAGE)
To manage this residual risk, the following changes are mandatory before any deployment consideration:
1.  **Human-in-the-Loop Gate (Non-Negotiable):** Fully automated remote disabling of doors for billing reasons must be removed. Any deactivation command must require explicit, real-time human verification by a support agent who confirms the resident is not currently attempting to exit and no emergency services are active.
2.  **Fail-Safe Default:** The system must default to "unlocked" in the event of network loss, billing system ambiguity, or hardware uncertainty.
3.  **Physical Override Independence:** Since digital 2FA is impossible on legacy hardware, a purely mechanical, non-networked override accessible to residents (e.g., a physical key that cannot be remotely disabled) must be guaranteed by law and design. If the remote disable feature can defeat the physical key, the feature is unsafe.
4.  **Defined Uncertainty Tiers:** If the system displays status to staff, it must use coarse tiers (e.g., "Payment Disputed – Do Not Lock") rather than precise binary states that invite automatic action.
