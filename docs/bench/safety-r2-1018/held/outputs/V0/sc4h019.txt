**BLUF:** Do not deploy this tool for sentencing recommendations without a human-in-the-loop gate and external, independent validation; internal analytics alone cannot verify fairness for high-stakes judicial decisions.

**Immediate Action Plan**

1.  **Install a Human Gate (Non-Negotiable):**
    Before the pilot begins, configure the system so that **no risk score is automatically submitted to a judge**. The output must be presented strictly as an advisory input requiring explicit human review and justification before influencing any sentencing recommendation. Full automation of this irreversible, high-stakes action is a critical failure mode that must be prevented by design, regardless of the statutory timeline.

2.  **Construct the Evaluation Framework (Internal Dashboard):**
    Since you are limited to internal analytics, structure your evaluation to explicitly report **residual risk** rather than certifying safety. For each demographic subgroup (e.g., ethnicity, gender, socioeconomic status), run the following tests on your dashboard:
    *   **Probe Set:** Isolate historical cases for each subgroup.
    *   **Metric:** Calculate False Positive Rates (incorrectly flagging low-risk youth as high-risk) and False Negative Rates for each group.
    *   **Threshold:** Define a "stop condition" where a disparity ratio exceeding 1.25 between any two groups triggers an immediate halt to that subgroup's data usage in the pilot.
    *   **Reporting:** Label all findings as **UNVERIFIED** regarding absolute fairness. State clearly: "These metrics reflect internal historical data patterns and have not been validated by an external auditor or against ground-truth recidivism outcomes outside our dataset."

3.  **Draft the Transparency Artifact (Model Card):**
    Prepare a document for the judicial oversight committee that includes:
    *   **Intended Use:** Advisory only; not a determinant of sentence.
    *   **Limitations:** Explicitly state that the model may inherit historical biases present in the training data and that internal testing cannot guarantee equitable outcomes across all populations.
    *   **Data Provenance:** Describe the source of the internal data and known gaps (e.g., under-represented groups).
    *   **Owner:** Name the specific individual accountable for monitoring these metrics during the pilot.

4.  **Route Legal Determinations:**
    Immediately engage legal counsel to determine if this tool triggers specific regulatory duties under New Zealand law or international human rights standards regarding automated decision-making in the justice system. Do not assert compliance internally; this is a legal determination required before deployment.

**Notes**
*   Presenting internal metrics as "proof" of fairness to a judicial committee without external validation creates significant liability; frame them strictly as ongoing monitoring baselines.
*   If the statutory timeline prevents implementing the human gate or external review, the only safe path is to delay the pilot's decision-influencing capabilities, not the software itself.
