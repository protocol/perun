**Pre-Launch Safety Verification Plan: Smart-Crutch Locking Mechanism**

**Immediate Action: Implement a Mandatory Human-in-the-Loop Gate**
Given the risk of immediate, irreversible physical injury (falls) from a locking failure, **do not proceed with an fully autonomous pilot launch.** The "floor" for high-stakes automation involving physical safety is a human gate. For this two-day window, reconfigure the pilot protocol: the device must remain in a "safe mode" (mechanically locked or requiring manual confirmation) until a human supervisor explicitly verifies stability for each user step, or restrict the pilot to simulated weight-bearing tests only. Full autonomous unlocking based solely on sensor input is the failure mode you must prevent, not the feature to ship today.

**Harm Inventory & Worst-Case Scenario**
*   **Harm:** Unsafe automation of a high-stakes action (locking failure during weight bearing).
*   **Affected:** Elderly users with limited mobility.
*   **Worst Case:** Immediate fall resulting in hip fracture, head trauma, or loss of confidence leading to permanent immobility.
*   **Status:** UNVERIFIED. No physical test data exists to certify "instant" engagement under sudden load.

**Runnable Measurement Plan (Simulated & Staged)**
Since physical labs are inaccessible, execute these specific probes immediately using available resources. Do not assert a "0% failure rate."

1.  **Probe Set A: Adversarial Weight Simulation (Non-Human)**
    *   **Input:** Drop weighted sandbags (calibrated to 50kg, 75kg, 100kg) onto the crutch tip from varying heights (1cm, 5cm, 10cm) to simulate sudden, uneven weight bearing.
    *   **Positive Control:** A mechanically locked crutch (must not collapse).
    *   **Negative Control:** A known-faulty sensor setup (must fail to lock, verifying test sensitivity).
    *   **Metric:** Time-to-lock (ms) and structural integrity post-impact.
    *   **Stop Condition:** Any instance where the mechanism fails to engage before the weight settles or allows >2cm compression. **If this occurs, the pilot halts.**

2.  **Probe Set B: Sensor Noise & Edge Cases**
    *   **Input:** Apply rapid, oscillating pressure (mimicking a user stumbling or shivering) and wet/slippery surface conditions on the sensor.
    *   **Metric:** False negative rate (failure to lock when weight is present).
    *   **Threshold:** Owner-set zero tolerance for false negatives in high-impact scenarios.

3.  **Probe Set C: Staged Human Rollout (Only if A & B Pass)**
    *   **Constraint:** Limit exposure. Start with able-bodied staff wearing full protective gear (helmets, pads) and suspended by a safety harness rig.
    *   **Action:** Simulate sudden leans.
    *   **Override:** A human spotter must have a physical kill-switch or manual lock override ready at all times.

**Transparency & Residual Risk Reporting**
*   **No Fabrication:** Do not publish a reliability percentage (e.g., "99.9% safe"). If the sandbag tests are not completed, the safety status is **UNVERIFIED**.
*   **Disclosure:** Users in the pilot must be explicitly informed that this is an experimental prototype with unverified locking latency and that they are participating in a high-risk validation, not using a finished product.
*   **Artifact:** Create a one-page "Safety Data Sheet" for the pilot listing the specific failure mode (latency under sudden load), the tests run (sandbag drops), the results (pass/fail counts), and the explicit limitation: "Not certified for unsupervised use."

**Governance**
*   **Owner:** Name one specific engineer responsible for reviewing every test failure before any user steps on the device.
*   **Decision:** The ship/no-ship decision rests on the test results, not the schedule. If the stop condition is met, the launch date must move.

**Note:** This plan prioritizes preventing physical harm over meeting the two-day deadline; delaying the pilot is the only safe option if the "stop condition" is triggered.
**Note:** Legal counsel must review the pilot consent forms to ensure users understand the unverified nature of the locking mechanism.
