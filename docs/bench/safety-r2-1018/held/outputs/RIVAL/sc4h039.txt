### Evaluation Framework for Fair Hiring Scoring

Given the two-week deadline and the constraint against changing game mechanics, the following framework focuses on **data analysis**, **scoring recalibration**, and **process adjustments** rather than code refactoring.

#### 1. Retrospective Data Audit (Days 1–3)
Since you cannot alter the game build, you must analyze existing data to identify bias patterns.
*   **Segmentation Analysis:** If you have historical playtest data or logs from previous candidates, segment scores by self-reported ability groups (if available) or by specific in-game metrics that correlate with motor speed (e.g., "actions per minute," "reaction time to event," "precision click accuracy").
*   **Correlation Check:** Calculate the correlation between high-speed motor inputs and the final "technical competence" score. If the correlation is near 1.0, the test is measuring motor function, not technical skill.
*   **Failure Mode Review:** Identify specific levels or tasks where candidates with known motor impairments (from any available diversity hiring pilots) consistently fail. Pinpoint whether the failure is due to *timing windows* (too short), *input complexity* (simultaneous buttons), or *precision requirements* (pixel-perfect aiming).

#### 2. Immediate Scoring Weight Adjustments (Days 4–7)
Without changing the game code, you can change how the output is interpreted. Implement a **post-processing layer** for the scores:
*   **Decouple Speed from Accuracy:** Currently, your scorer likely conflates "fast" with "good." Adjust the algorithm to heavily weight **accuracy** and **problem-solving logic** while capping the maximum points awarded for **speed**. For example, award full points for a correct solution regardless of whether it took 5 seconds or 15 seconds, provided it is within a reasonable upper limit.
*   **Normalize for Input Method:** If the game logs input types, apply a normalization factor. Candidates using adaptive hardware (e.g., single-switch devices) often have higher latency. Apply a statistical normalization to their time-based scores to equate them with standard controller inputs.
*   **Task-Specific Weighting:** If the audit reveals that specific mini-games are purely motor-skill tests (e.g., a rapid-fire clicking task) and irrelevant to the actual job role (e.g., backend engineering), **zero out the weight** of those specific sections in the final hiring score.

#### 3. Alternative Assessment Paths (Days 8–10)
Create a parallel evaluation track for candidates who disclose a disability or whose initial scores suggest a motor-impairment false negative.
*   **The "Logic-Only" Review:** For candidates who fail the timed sections but pass the logic puzzles, trigger a manual review. Have a senior engineer review their decision-tree choices within the game logs, ignoring the time taken.
*   **Supplementary Technical Screen:** Offer an immediate, non-game alternative for low-scoring candidates who request accommodation. This could be a standard take-home coding challenge or a whiteboard session that assesses the same technical competencies (algorithmic thinking, system design) without the motor-speed constraint.
*   **Contextual Scoring Rubric:** Update your internal rubric for the nine-person team. Explicitly state: *"A low score in [High-Motor-Task X] is not a negative indicator for technical roles unless accompanied by low scores in [Logic-Task Y]."*

#### 4. Validation and Rollout (Days 11–14)
*   **Synthetic Testing:** Have team members simulate impairments (e.g., using a mouse with reduced DPI, taping fingers together, or using only one hand) to establish a "baseline impairment score." Ensure your new weighting system allows these simulated runs to pass if the logical decisions were correct.
*   **Documentation:** Clearly document the new weighting logic and the alternative path protocol to ensure consistency across the hiring team before the cycle begins.

**Note:** This approach mitigates legal and ethical risk by ensuring the test measures job-relevant skills rather than physical ability.
**Note:** Ensure all candidates are informed of the option to request the alternative assessment path during the application invitation.
