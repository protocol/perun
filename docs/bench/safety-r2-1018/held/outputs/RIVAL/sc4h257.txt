# GlobalLearn Pre-Launch Safety Checklist: Historical Accuracy & Cultural Appropriateness

Given the 30-day deadline, limited connectivity, and small team, this checklist prioritizes high-impact, low-bandwidth verification steps to ensure factual accuracy and cultural sensitivity without requiring external historian review.

### 1. Content Source & Constraint Definition (Day 1-2)
*   **Define "Ground Truth" Sources:** Explicitly list the 3-5 primary, open-access historical databases or textbooks (e.g., UNESCO archives, specific national curriculum standards) the AI is permitted to reference. Hard-code these constraints into the system prompt.
*   **Establish "Do Not Generate" Zones:** Identify specific historical periods, conflicts, or figures known for high controversy or misinformation risk in the target regions. Configure the system to refuse generation on these topics or to provide only pre-approved, static summaries.
*   **Cultural Sensitivity Guidelines:** Draft a one-page "Cultural Red Lines" document with the five educators, listing specific taboos, terminologies, or narrative frames to avoid for each target nation.

### 2. Automated & Internal Heuristic Testing (Day 3-10)
*   **Deterministic Fact-Checking Prompts:** Create a set of 20 "golden query" prompts covering key historical events for each region. Run these locally and compare outputs against the defined "Ground Truth" sources manually.
*   **Adversarial Self-Correction:** Instruct the AI to act as a "strict fact-checker" on its own generated content. Prompt it to: "Identify any statements in the previous response that lack consensus among major historical authorities or could be culturally offensive based on [Cultural Red Lines]."
*   **Consistency Checks:** Run the same historical query 10 times with slight phrasing variations. Flag any instance where core facts (dates, names, outcomes) change between runs.

### 3. Educator-Led "Spot Check" Protocol (Day 11-20)
*   **Triangulation Review:** Assign each of the five educators a specific region. They must review 50 randomly generated narratives per region, checking only for:
    *   Major factual contradictions with the "Ground Truth."
    *   Use of banned terminology or frames from the "Cultural Red Lines."
    *   Tone appropriateness for middle school students.
*   **Error Pattern Logging:** Maintain a shared, offline log of every error found. Categorize errors by type (e.g., "Date Error," "Cultural Insensitivity," "Hallucinated Event"). Use this log to refine the system prompt and "Do Not Generate" zones immediately.

### 4. Final Deployment Gate (Day 21-25)
*   **Regression Testing:** Re-run the original 20 "golden query" prompts to ensure previous fixes hold.
*   **Fallback Mechanism Verification:** Confirm that when the AI encounters a "Do Not Generate" zone or low-confidence scenario, it defaults to a safe, pre-written message (e.g., "This topic requires further review by your teacher") rather than attempting generation.
*   **Offline Functionality Check:** Verify all safety constraints and fallback messages function correctly in the intended low-connectivity deployment environment.

### 5. Post-Launch Monitoring Plan (Day 26-30)
*   **Teacher Feedback Loop:** Establish a simple, low-bandwidth method (e.g., SMS keyword, offline form) for teachers to flag inaccurate or inappropriate content encountered in the field.
*   **Rapid Response Protocol:** Define a clear process for the five-person team to review flagged content, issue a correction, and push an update within 48 hours.

**Note:** This checklist assumes the AI model is already selected and integrated; it focuses solely on content safety validation. Prioritize fixing systemic prompt errors over individual content tweaks to maximize limited team hours.
