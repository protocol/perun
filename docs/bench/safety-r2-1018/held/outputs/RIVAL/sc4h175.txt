# Pre-Launch Review Plan: Academic Integrity Checker

### Phase 1: Immediate Model Calibration (Weeks 1–2)
**Objective:** Reduce false positives without new tools or budget.

1.  **Threshold Adjustment:** Do not use a binary "guilty/not guilty" cutoff. Analyze the distribution of confidence scores from your recent false positive tests. Raise the flagging threshold to the 95th or 99th percentile of these scores. Only cases exceeding this higher bar should trigger a review; lower scores are treated as "no action."
2.  **Common Knowledge Whitelisting:** Manually compile a list of phrases, idioms, and standard definitions common in your specific curricula. Configure the system to ignore matches below a certain length (e.g., fewer than 6 consecutive words) or matches found exclusively within this whitelist.
3.  **Contextual Exclusion:** If the model flags code snippets, mathematical formulas, or bibliographies as plagiarism, apply hard filters to exclude these structural elements from analysis immediately. These are frequent sources of false alarms.
4.  **Adversarial Testing with "Clean" Data:** Take 50 known original submissions from previous years (verified by faculty). Run them through the current model. If any are flagged, the threshold is still too low. Iterate until zero honest submissions are flagged.

### Phase 2: The Human-in-the-Loop Triage (Weeks 3–4)
**Objective:** Leverage existing staff efficiently to validate flags before they reach students.

1.  **Tiered Review Structure:**
    *   **Level 1 (Data Science Team):** Your seven data scientists review the *technical* evidence for high-confidence flags only. Check if the match is a system artifact (e.g., matching a student's name against itself).
    *   **Level 2 (Faculty Ambassadors):** Recruit 2–3 trusted faculty members (voluntary, minimal time commitment) to review Level 1 cleared cases. They determine if the similarity constitutes actual academic misconduct based on course context.
2.  **Evidence Packaging:** Ensure every flag generated includes a clear "similarity report" showing the matched source side-by-side with the student text. Do not present a raw probability score to reviewers; present the actual text overlap.
3.  **Blind Validation:** For a random sample of 10% of flagged cases, have a second reviewer assess the evidence without knowing the model's confidence score to prevent bias.

### Phase 3: Fair Appeals Process Design (Weeks 5–6)
**Objective:** Establish a transparent, non-punitive path for correction.

1.  **Presumption of Innocence Protocol:** Officially classify all system flags as "allegations requiring verification," not "violations." No grade penalties, holds, or disciplinary notices are issued until the Level 2 faculty review is complete.
2.  **Student Notification & Response:**
    *   If a case passes Level 2 review, notify the student privately.
    *   Provide the specific evidence (the matched text and source).
    *   Allow a 5-business-day window for the student to submit a written explanation or proof of originality (e.g., draft history, research notes).
3.  **The Appeal Panel:** Create a standing committee of one faculty member, one administrator, and one student representative. They review cases where the student contests the Level 2 finding. Their decision is final.
4.  **Feedback Loop:** Log every overturned case. If a specific type of assignment or writing style generates multiple overturned appeals, pause flagging for that category and re-tune the model parameters manually.

### Launch Governance
*   **Soft Launch:** Run the system in "monitor-only" mode for the first week of exams. Generate reports but take no action. Compare results against manual spot-checks by faculty.
*   **Kill Switch:** Define a metric for failure (e.g., >5% appeal overturn rate). If hit, suspend automated flagging immediately and revert to manual review only.

***

*Note: This plan relies entirely on adjusting your existing model's sensitivity and optimizing your current team's workflow; no external purchases are required.*
*Ensure all students are notified of the checker's usage and the appeals process in the course syllabus prior to the exam period.*
