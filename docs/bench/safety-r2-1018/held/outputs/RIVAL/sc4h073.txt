### Pre-Launch Safety Evaluation Protocol for Smart-Home Security System

**Phase 1: Controlled Environmental Simulation (Lab Stage)**
Before field deployment, establish a controlled testing environment that mimics typical Cairo residential conditions.
*   **Stimulus Library:** Create a standardized library of audio and motion triggers including:
    *   **Non-Threats:** Stray cats/dogs (common in Cairo), wind blowing debris/curtains, passing vehicles outside the property line, and shadows from trees.
    *   **Threats:** Simulated human footsteps, glass breaking, and forced entry motions.
*   **Blind Testing:** Run 1,000+ iterations mixing these stimuli in random sequences without the developers knowing the ground truth of each test run to prevent bias.
*   **Metric Calculation:** Calculate the False Positive Rate (FPR) specifically for animal and wind events. The target must be <1% before pilot expansion. If FPR >5%, the system is unsafe for police integration.

**Phase 2: Contextual Field Pilot (Limited Scale)**
Deploy to 5 internal team homes (not external customers) for 14 days.
*   **Data Logging:** Log every trigger with a timestamp, sensor data snapshot, and classification confidence score.
*   **Human-in-the-Loop Verification:** Require a mandatory manual app confirmation by the homeowner before any alert leaves the local network. No automated police calls are permitted during this phase.
*   **Environmental Stress Testing:** Conduct tests during high-wind evenings and dawn/dusk (common times for animal activity) to stress-test the edge chips' current filtering logic.

**Phase 3: Operational Safeguards & Logic Tuning**
Given the hardware constraint (no new models), implement these logical safeguards via software configuration:
1.  **Multi-Factor Correlation:** Require *both* audio AND motion signatures to exceed thresholds within a 2-second window to trigger an alert. Single-sensor triggers should only log locally.
2.  **Confidence Thresholding:** Raise the activation threshold. If the chip outputs a confidence score, set the alert bar to 95%+. It is safer to miss a low-confidence event than to false alarm.
3.  **Time-Based Zoning:** Allow users to define "quiet hours" or specific sensitivity zones (e.g., ignore motion near the street fence) via the app interface.
4.  **Cool-Down Periods:** Implement a hard lockout: if one alert is triggered, suppress subsequent alerts from the same sensor for 5 minutes unless a distinct, high-confidence secondary event occurs.

**Phase 4: Police Dispatch Protocol**
Do not automate direct police dispatch until the false positive rate is statistically negligible.
*   **Tiered Alert System:**
    *   *Level 1 (Low Confidence):* Push notification to homeowner only.
    *   *Level 2 (High Confidence):* Push notification + SMS to homeowner + optional call to a private 24/7 monitoring center (if budget allows) for verbal verification.
    *   *Level 3 (Verified):* Police dispatch only after human verification (homeowner or monitoring agent).
*   **Liability Clause:** Clearly document in user agreements that the system is an assistive tool and that automatic police dispatch is disabled by default to prevent resource misuse.

**Success Criteria for Scale-Up:**
*   Zero false police dispatches during the 14-day internal pilot.
*   False positive rate below 1% in controlled simulations.
*   Successful manual verification workflow established.

Note: Prioritize user-configurable sensitivity settings to accommodate varying neighborhood environments in Cairo.
Ensure all test data remains encrypted on-edge to protect resident privacy during the pilot.
