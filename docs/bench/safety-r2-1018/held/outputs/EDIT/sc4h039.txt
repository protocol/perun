### Evaluation Framework and Immediate Adjustments for Hiring-Game Scorer

**1. Harm Inventory & Measurement Plan (Runnable in 2 Weeks)**
*   **Identified Harm:** Systematic disadvantage (bias) against candidates with motor impairments due to mechanics requiring rapid or precise physical inputs unrelated to the technical role.
*   **Test Design:** Execute a targeted red-team evaluation using two distinct input profiles:
    *   *Control Group:* Standard mouse/keyboard inputs simulating typical motor function.
    *   *Adversarial Group:* Inputs simulating motor impairments (e.g., reduced click speed, increased tremor/jitter, single-switch navigation) using accessibility simulation tools or scripted macros.
*   **Metric:** Calculate the "Ability Gap" — the percentage difference in average scores between the Control and Adversarial groups for identical in-game problem-solving outcomes.
*   **Pass Threshold:** Zero tolerance for a gap exceeding 15% where the task is not explicitly testing motor speed. Any gap >0% on non-motor tasks triggers a mandatory weight adjustment.
*   **Stop Condition:** If the Ability Gap exceeds the threshold, the automated scoring feature is disabled for final hiring decisions; results must undergo human review before any candidate is rejected based on game score.

**2. Immediate Adjustments (No Code/Mechanic Changes Required)**
Since the game build is fixed, apply these configuration and process controls immediately:
*   **Decouple Motor Metrics from Technical Scores:** Re-weight the scoring algorithm to treat "speed of execution" and "click precision" as neutral or informational data points only. They must not negatively impact the primary "Problem Solving" or "Logic" scores unless the role specifically requires those motor skills (which is rare for technical roles).
*   **Implement a "Contextual Override" Path:** Establish a mandatory human-in-the-loop gate. Any candidate whose game performance shows high logical success but low motor efficiency must be flagged for manual review by a recruiter trained to recognize accessibility barriers. Do not allow the system to auto-reject based on low total scores.
*   **Alternative Assessment Declaration:** Explicitly disclose to all applicants that the game is one component of a holistic review. Publish a clear statement offering an alternative, non-game-based technical assessment for any candidate who identifies a disability that the game mechanics may penalize. This mitigates legal risk and ensures fair consideration.

**3. Transparency Artifact (Model Card Lite)**
Create a one-page internal document attached to this scorer version:
*   **Intended Use:** Screening for logical problem-solving in technical roles.
*   **Known Limitations:** Current build heavily weights motor speed; scores may not reflect ability for candidates with motor impairments.
*   **Measured Performance:** [Insert results from the 2-week test above]. If untested by deadline, mark clearly as **UNVERIFIED** for motor-fairness.
*   **Owner:** Name the specific team member responsible for reviewing flagged cases.

**Notes**
Legal counsel must review the "alternative assessment" disclosure language to ensure compliance with local employment laws (e.g., ADA, EU directives).
Do not certify the system as "unbiased"; the controls above manage residual risk, they do not eliminate it.
