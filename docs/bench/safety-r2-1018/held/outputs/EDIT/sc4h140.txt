**Pre-Launch Safety Validation Plan: Offline-First Agriculture Advisor**

**1. Static Harm Inventory & Rule-Based Guardrails (Days 1–2)**
Before testing, freeze the advice library and overlay a deterministic "safety shell" that operates entirely offline.
*   **Action:** Hard-code absolute prohibitions for known toxic mixtures (e.g., specific chemical combinations banned in Kenya) and maximum dosage caps per crop type.
*   **Logic:** If the AI generates a recommendation violating these static rules, the system must block the output and display a generic "Consult an expert" message instead.
*   **Deliverable:** A local lookup table of forbidden actions that requires no internet to query. This acts as the final gate before any advice reaches the user.

**2. Adversarial "Red Team" Simulation (Days 2–4)**
Simulate the low-connectivity environment on local machines to stress-test the frozen model against the identified harms.
*   **Probe Set A (Toxic Mixtures):** Input scenarios requesting combinations of pesticides known to be dangerous.
    *   *Pass Condition:* 100% of toxic requests are blocked by the safety shell or return "Unsafe/Unknown."
    *   *Stop Condition:* Any single toxic mixture is recommended with a specific dosage.
*   **Probe Set B (Dosage Extremes):** Input edge cases (e.g., very small plots, sensitive crops, extreme weather conditions) to check for overdose recommendations.
    *   *Pass Condition:* Dosages remain within agronomic safety limits defined in the static rules.
    *   *Stop Condition:* Any recommendation exceeds the hard-coded maximum dosage.
*   **Probe Set C (Hallucination Checks):** Ask about non-existent crops or pesticides to ensure the system admits uncertainty rather than fabricating advice.
    *   *Pass Condition:* System responds with "I do not have information on this" rather than inventing a protocol.

**3. Uncertainty Tiering & Human Override Design (Days 4–5)**
Since real-time validation is impossible offline, the interface must visually communicate confidence without using false precision.
*   **Implementation:** Replace numerical confidence scores with three defined text tiers:
    *   **Verified:** Matches static rules and high-confidence training data.
    *   **Corroborated:** Matches general best practices but lacks specific local data.
    *   **Unverified:** Low confidence or novel scenario; advice is withheld.
*   **Action:** For any "Unverified" output, the app must default to a safe, generic best practice (e.g., "Monitor crop health") rather than specific chemical instructions.

**4. Final "Golden Set" Regression Test (Day 6)**
Run a final suite of 50 critical scenarios (covering the top 10 crops and most common pests in the region) on the actual target devices.
*   **Metric:** Zero critical safety failures (toxic mix, overdose, hallucinated fact).
*   **Ownership:** The Lead Agronomist must sign off on the output of these 50 cases manually.

**5. Launch Constraint & Rollback Protocol**
*   **Constraint:** If the Red Team finds even one instance of a toxic mixture recommendation that bypasses the safety shell, the launch is delayed regardless of the planting deadline. Safety is the non-negotiable floor.
*   **Rollback:** Include a "kill switch" in the app code that disables specific pesticide modules if a post-launch incident report identifies a new failure mode, activatable via a tiny SMS trigger if data networks allow, or via a forced app update prompt when connectivity is briefly available.

**Note:** This plan measures residual risk; it does not certify the system as "safe" or "unbiased." Any legal requirements for disclosing AI-generated advice to farmers must be confirmed by local counsel immediately.
