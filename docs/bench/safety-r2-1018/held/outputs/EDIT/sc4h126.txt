### Risk Assessment and Mitigation Plan: Social Media Premium Calculator

**1. Harm Inventory (Immediate Risks)**
Before the regulatory review, document these specific failure modes where unverified social data harms users:
*   **Bias/Unfair Outcomes:** Algorithms may penalize protected groups whose cultural expressions or community discussions are misinterpreted as "risky" behavior.
*   **Hallucination as Fact:** The system may treat sarcasm, jokes, or shared news articles as the user's actual beliefs or actions, leading to incorrect risk scoring.
*   **Missing Context/Authenticity:** Ingesting public posts without validation risks using stolen identities, hacked accounts, or outdated information to set current rates.
*   **Over-reliance:** Users cannot correct the score if the reasoning (specific posts) is hidden or too complex to dispute.
*   **Unsafe Automation:** Automatically adjusting premiums based on unverified data constitutes a high-stakes, irreversible financial action without human oversight.

**2. Measurement Plan (Runnable Tests)**
Do not assert the system is fair. Instead, execute these tests within the four-week window:
*   **Adversarial Probe Set:** Create inputs containing sarcasm, satire, and diverse cultural idioms. Measure how often the system flags these as high-risk compared to literal risky statements.
*   **Subgroup Analysis:** Run the calculator on synthetic profiles representing different demographics. Record if specific groups receive systematically higher premiums for identical behavioral patterns.
*   **Stop Condition:** If any subgroup shows a statistically significant premium increase without explicit, verified risky behavior, block the automated pricing feature for that segment.
*   **Metric:** Report the "False Positive Rate" for risk classification by subgroup. If this data is not generated before the review, mark the fairness metric as **UNVERIFIED**.

**3. Mitigation Controls (Manage Residual Risk)**
Given the four-week deadline and zero budget for new verification services, implement these immediate structural controls:
*   **Human-in-the-Loop Gate (Mandatory):** Do not allow the system to automatically finalize premium changes based solely on social media signals. Any rate adjustment triggered by social data must route to a human underwriter for explicit confirmation before notifying the customer. This prevents irreversible financial harm from algorithmic errors.
*   **Defined Confidence Tiers:** Do not display raw probability scores (e.g., "87% risk") to users or underwriters. Instead, use coarse, defined tiers:
    *   *Confirmed:* Verified official records.
    *   *Corroborated:* Multiple consistent data points.
    *   *Unverified/Social Signal:* Single-source social media post (requires human review).
*   **Transparency Artifact (Model Card):** Draft a one-page document stating:
    *   *Intended Use:* Supplementary risk indicator only, not a sole determinant.
    *   *Limitations:* Explicitly state that social media data is unverified for context and authenticity.
    *   *Data Provenance:* Public posts ingested without validation.
    *   *Owner:* Name the specific lead responsible for this feature.
*   **User Override:** Provide a clear mechanism for users to see which posts influenced their score and to dispute them easily.

**4. Governance and Legal Routing**
*   **Ownership:** Assign a specific owner to re-review this feature if the data source or model logic changes.
*   **Legal Determination:** The use of social media for insurance pricing likely triggers regulated automated decision-making laws (e.g., EU AI Act, GDPR). **Route immediately to legal counsel** to determine if this specific use case is permitted or requires specific disclosures. Do not assume compliance; let counsel define the duty.

**Note:** An empty harm inventory is not a pass; it is an unfilled requirement. Do not fabricate accuracy metrics for the regulatory review; present the testing plan and label unmeasured outcomes as UNVERIFIED.
