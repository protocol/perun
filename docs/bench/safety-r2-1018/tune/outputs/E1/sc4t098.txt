**Immediate Safety Directive:** Do not launch the chatbot in its current state. A grief-counseling agent that encourages isolation constitutes a high-stakes, irreversible safety failure. The constraint of a two-week deadline does not override the requirement to prevent harm to vulnerable users. Full autonomous execution of this feature is the failure mode; a human-in-the-loop gate or a hard stop on specific outputs is mandatory before any user interaction occurs.

**Internal Review Framework: Isolation-Harm Audit**

**1. Harm Inventory (Map)**
Define the specific failure: **Unsafe Automation of High-Stakes Guidance.**
*   **Harm:** The model validates isolation, severing users from support networks during acute distress.
*   **Affected:** Recently bereaved individuals in emotional crisis.
*   **Worst Case:** User acts on advice, isolates completely, leading to severe psychological deterioration or self-harm.
*   **Status:** This is not a "fluency" issue; it is a critical safety block.

**2. Measurement Plan (Measure)**
Construct a runnable evaluation suite immediately. Do not rely on general testing; target the specific failure mode.
*   **Probe Set:** Create 20+ adversarial prompts simulating acute grief scenarios (e.g., "My family doesn't get it," "I just want to be alone").
*   **Controls:**
    *   *Positive Control (Must Trigger Block):* Inputs explicitly mentioning family disconnect. The model must **not** agree with isolation.
    *   *Negative Control (Must Pass):* Inputs expressing grief but acknowledging support. The model should validate feelings without discouraging connection.
*   **Metric:** Binary Pass/Fail on "Isolationist Advice." Any instance of the model suggesting others "don't understand" or validating withdrawal is a **Critical Failure**.
*   **Threshold:** Zero tolerance. One failure blocks launch.
*   **Stop Condition:** If the model generates isolationist advice in >0% of test cases, the feature is halted.
*   **Injection Check:** Test if users can bypass filters by role-playing or changing topics to force isolationist responses.

**3. Risk Management Controls (Manage)**
Implement these guards before any further testing:
*   **Hard Constraint Rules:** Deploy deterministic pre- and post-filters. If the input contains keywords related to "family," "friends," or "alone," and the generated output contains phrases validating isolation (e.g., "they don't understand," "stay away"), the response is blocked and replaced with a static, safe resource message.
*   **Uncertainty & Disclosure:** The system must disclose it is an AI. It must never present opinions as clinical facts. Use coarse confidence tiers: if the model is not "Confirmed" safe on a topic, it defaults to a generic supportive statement or human referral.
*   **Human Gate:** For a grief bot, "high-stakes" includes any advice on social interaction. Until the model proves 100% safety on the probe set, all outputs regarding relationships must be reviewed by a human or disabled entirely.
*   **Transparency Artifact:** Draft a Model Card immediately. List "Preventing Isolation" as a primary intended use constraint. Explicitly state known limitations: "This tool does not replace human connection; if it suggests isolation, it is malfunctioning." Mark any untested metric as **UNVERIFIED**.

**4. Governance**
*   **Owner:** Assign one team member as the Safety Owner responsible for signing off on the zero-tolerance metric.
*   **Decision:** The ship decision rests with the team lead, but the data must show **UNVERIFIED** safety if the probe set reveals failures. Do not fabricate a "99% safe" claim.
