**Validation Plan for CardiaCare Rhythm Detection Logic**

Given the 30-day constraint and the irreversible, high-stakes nature of automated defibrillation, the validation plan must prioritize preventing false positives (unnecessary shocks) while maintaining sensitivity to true emergencies. The following methods address the specific risk of faulty detection leading to user harm:

1.  **Adversarial "Stress-Test" Dataset Construction**: Immediately compile a validation set heavily weighted toward "edge cases" that historically trigger false positives in similar devices. This includes motion artifacts (running, falling, sleeping movements), electromagnetic interference, and non-lethal arrhythmias that mimic ventricular fibrillation. Each test row must pair a specific edge-case input with a known-negative control (no shock expected) and a known-positive control (shock required). The pass threshold for false positives in this high-stakes context must be set to zero tolerance for unmitigated errors; any failure triggers an immediate stop to the submission process.

2.  **Human-in-the-Loop (HITL) Gate for Ambiguous Signals**: Since fully autonomous execution of an irreversible action (shock) is the primary failure mode to prevent, the logic must include a "confidence tier" system. If the detection algorithm classifies a rhythm as "Unverified" or "Single-source" rather than "Confirmed," the device must withhold the shock and alert the user or a remote monitoring center for human confirmation. Do not surface raw probability scores (e.g., "87% chance of VF") to the user; instead, use defined coarse tiers (Confirmed vs. Unverified) to prevent over-reliance on uncertain automation.

3.  **Subgroup Performance Analysis**: Measure detection accuracy not just in aggregate, but sliced by relevant user subgroups (e.g., age, body mass index, skin conductivity variations, concurrent medications). A bias finding here could mean the device systematically fails to detect emergencies or falsely shocks specific demographic groups. Report these metrics explicitly; if data for a subgroup is missing, label it "UNVERIFIED" rather than extrapolating from the general population.

4.  **Residual Risk Disclosure Artifact**: Prepare a "Model Card" equivalent for the clinical submission that documents the intended use, the specific limitations of the current validation set, and the known failure modes identified during stress testing. This document must explicitly state that the system is not certified "safe" or "unbiased" but has been measured against specific adversarial probes. Include the owner of the rhythm logic and the version number of the model used in the trial.

5.  **Regulatory Routing**: While this plan addresses technical validation, the determination of whether this automated decision falls under specific "high-risk" AI regulations (such as the EU AI Act) or requires specific legal disclosures is a legal duty. Route this question immediately to counsel alongside the technical documentation to ensure the 30-day submission meets all regulatory obligations beyond clinical safety.

**Note**: Do not invent a "false positive rate" if the adversarial testing described above has not yet been executed; mark such metrics as UNVERIFIED. The decision to ship or submit rests with the product owner based on the residual risk reported, not on a certification of safety.
