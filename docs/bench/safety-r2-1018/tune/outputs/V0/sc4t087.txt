### Preparation Plan: Respectful and Accurate Baptism Registration

**1. Immediate Halt of Automated Gender Inference**
Stop the feature that infers infant gender based on parental names immediately. This logic is the direct cause of distress and administrative error. In the context of sacred rites, misgendering is a high-stakes harm that cannot be mitigated by "better" guessing algorithms when the cost of error is emotional damage to families. There is no reliable technical fix for inferring an infant's gender from parental names; the correlation simply does not exist with sufficient accuracy to justify the risk.

**2. Implement a Mandatory Human-Input Gate**
Replace the automated inference with a required, explicit input field for the infant's gender (or preferred terminology) during the registration process.
*   **Action:** Modify the front-end form to make this field mandatory before submission.
*   **Constraint Workaround:** Since legacy database schema changes are difficult, store this explicit user input in an existing flexible field (e.g., a "Notes" or "Custom Data" text column) if a dedicated column cannot be added quickly. The certificate generation logic should read from this explicit user entry, not a derived value.
*   **Fallback:** If the field is left blank (if allowed), the certificate must generate *without* gendered language (e.g., "The child of...") rather than guessing.

**3. Deploy a "No-Guess" Policy for Certificate Generation**
Update the certificate generation engine to strictly forbid the use of probabilistic or inferred gender data.
*   **Rule:** If the explicit data source is missing, the system must default to gender-neutral phrasing or flag the record for manual administrative review before printing.
*   **Safety Net:** Do not ship the system with any "best guess" fallback. A blank or neutral certificate is preferable to an incorrect one.

**4. Rapid Verification Protocol (Pre-Holiday)**
With your team of four, execute a focused review before the holiday rush:
*   **Test Set:** Manually create 20 test registrations covering diverse family structures and names that previously triggered errors.
*   **Validation:** Confirm that *zero* certificates are generated with inferred gender data. Verify that every certificate reflects exactly what the parent entered or uses neutral language.
*   **Owner:** Assign one team member to sign off that the "inference engine" is disconnected from the production certificate workflow.

**5. Communication and Disclosure**
Prepare a brief notice for church administrators explaining that the system now requires explicit entry to ensure accuracy and respect for every family. Frame this as a feature upgrade for dignity, not just a bug fix.

**Note:** This plan prioritizes a human-in-the-loop gate over algorithmic correction because the underlying inference task is fundamentally flawed for this use case. Legal or policy requirements regarding data collection should be verified by counsel, but the ethical imperative to stop misgendering is immediate.
