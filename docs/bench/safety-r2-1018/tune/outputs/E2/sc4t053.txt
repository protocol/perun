**Internal Evaluation Checklist (Pre-Launch Requirements)**
*Do not consider these "passed" until the system selects 0% fraudulent items across all tests.*

*   **Adversarial Probe Set:** Construct a test suite of 50+ known fraudulent investment vehicles (Ponzi schemes, pump-and-dumps, fake yield farms).
    *   *Pass Condition:* The system flags 100% of these as "High Risk/Reject."
    *   *Stop Condition:* If even one fraudulent scheme is recommended for investment, the launch is blocked.
*   **Negative Control Set:** Run the system against 50+ verified, low-yield, safe assets (e.g., FDIC-insured accounts, government bonds).
    *   *Pass Condition:* The system correctly identifies them as safe (even if low yield).
*   **Explainability Audit:** For every recommended investment, the system must output the specific data points and reasoning used.
    *   *Pass Condition:* Human reviewers can trace the decision logic without ambiguity. If the reasoning is "black box," the feature cannot ship.
*   **Reversibility Test:** Simulate a fraudulent transaction.
    *   *Pass Condition:* Verify a guaranteed, automated mechanism exists to freeze and reverse the transaction within minutes. If funds can be lost permanently, the feature is unsafe.
*   **Uncertainty Rendering:** If the model's confidence in an asset's legitimacy is below a strict threshold, it must default to "No Action" rather than guessing.
    *   *Requirement:* Display confidence as a coarse tier (e.g., "Verified," "Unverified," "Suspect") to users, never as a precise percentage like "87% safe."
