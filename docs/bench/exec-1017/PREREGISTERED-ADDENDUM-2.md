# Addendum 2: round 2 (written 2026-10-17, before any round-2 generation or judging)

Scope: the four skills that failed the round-1 keep rule: `agentic-ceo`, `idea-critic`, `business-ops`, `positioning`. `growth-analytics` is kept from round 1 and is not re-tested.

## Why a new round

Round 1 used one edit round written from tune-split judge reasons and a held-out set that is now spent (it was scored for the round-1 keep decision, and its first-pass results shaped what round 2 targets). Round 2 uses the same method with three changes the requester asked for: variants are compared on the tune split first, a new held-out set is used once, and the judge is a three-model majority.

## Procedure

1. Compare Perun and rival outputs on the tune split only (scenarios 01 to 10 of `scenarios/<skill>.json`), listing what the rival does that wins. The edits port those behaviours into the sentence or bullet where each skill decides what a requested call looks like; no new sections. They are written as three variants per skill by `mkvariants.py` (`r2a`, `r2b`, `r2c`: a decision-memo contract; plus re-basing an unrealistic stated assumption; plus a ledger built from stated figures only). The unedited text is `v0`.
2. Run `v0` and the three variants on the tune split with the round-2 judge. Pick one variant per skill: the highest tune win rate; ties go to the shorter text. Tune results are a selection signal only (n=10).
3. Test the chosen variant once on a NEW held-out set: 20 fresh scenarios per skill (`scenarios2/<skill>-h2.json`, ids h01 to h20), generated by `gpt-oss_120b` from `prompts/seeds2.txt` (20 new fictional settings, rotated by 5 per skill) with the unchanged writer briefs, frozen by the hashes in `SHA256-round2-frozen.txt` before the first held-out generation. `v0` is also run on that set as a reference only; the keep rule does not read it except for the "at least v0" clause.
4. Judge (`bench2.py`): DeepSeek-V4-Flash, GLM-5.2 (thinking off, as in addendum 1) and MiniMax-M2.5, each called once per pair with its own independently randomized order and the unchanged `judge.txt`. The majority verdict decides: two judges on one arm give that arm; anything else (a split, ties, failures) is a tie scored 0.5. Qwen3.5-397B-A17B generates every arm, so it is not a judge.
5. Score, bootstrap (10,000 resamples, seed 1, percentile, over scenarios) and the keep rule are unchanged: keep a variant only if its held-out 95% lower bound is above 0.5 with n=20 and its win rate is at least `v0` on the same set; otherwise the skill text reverts. The tune split is never used for the keep decision.

## Known weaknesses

All judges and the generator are open models on one hosting cluster. Three judges reduce API noise but not shared bias. Choosing the best of three variants on n=10 tune scenarios overfits the tune set; the single fresh held-out run is the check for that, and its n=20 still only clears the bar near 15 wins. The new set uses the same writer brief, so it tests new scenarios, not a new scenario style.

## Amendment 2a: both-order judging (applied before the tune results were used and before any held-out generation)

The first tune pass judged each pair once per judge in one randomized order. The coordinator's review of the judge calls found a strong slot-1 preference (Qwen3.5 picked slot 1 in 169 of 240 cases). Before choosing variants, every pair is judged in both orders by each of the three judges: a judge's verdict is an arm only when both orders name that arm, otherwise it is a tie; the majority of the three judge verdicts then decides, as above. Each report records every judge's slot-1 rate over all its calls. The single-order tune pass is kept as `judge3/` and `results2-*` (superseded, not used for any decision); the scored records are `judge4/` and `results4-*`. No variant was chosen from the superseded pass.

## Selection from both-order tune results (recorded before any held-out generation)

Tune win rates (v0 / r2a / r2b / r2c): positioning 0.50 / 0.40 / 0.55 / 0.55; business-ops 0.40 / 0.70 / 0.55 / 0.50; idea-critic 0.35 / 0.60 / 0.55 / 0.30; agentic-ceo 0.65 / 0.50 / 0.70 / 0.65. Chosen by the rule (highest, ties to shorter): positioning r2b, business-ops r2a, idea-critic r2a, agentic-ceo r2b. Slot-1 rates per judge are in each results4 file; they range 0.40 to 0.95, which is why both-order judging is used.
