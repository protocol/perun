**RapidEnroll Execution Plan for CFO Review (9 Oct 2024)**

**Recommended Work Order**
1.  **Regulatory Dossier (Weeks 1–5):** Start immediately. This is the critical path with an unknown timeline; any delay here blocks the go-live regardless of software completion.
2.  **Patient-Matching Algorithm (Weeks 1–8):** Begin parallel to regulatory work. As the longest build (8 weeks) and highest cost ($1.2M), it dictates the engineering schedule.
3.  **Electronic Consent Integration (Weeks 3–6):** Start only after the Algorithm's core architecture is stable (Week 3) to avoid rework if data schemas change. The 4-week estimate is high-risk as it relies on an unverified assumption about the vendor.
4.  **Pricing Tier Design (Weeks 6–8):** Execute last. This depends on the finalized capabilities of the first two streams to ensure accurate cost modeling.
5.  **Security Audit (Week 8):** Conduct in the final buffer week using the remaining $150k.

**Primary Failure Modes**
*   **Regulatory Block:** The "unknown" timeline exceeds the 5-week buffer, rendering the completed software unusable for the launch date.
*   **Integration Underestimation:** The third-party consent integration takes longer than the assumed 4 weeks (since it is based on a heuristic, not a scoped SOW), causing a cascade delay into the security audit window.
*   **Budget Overrun:** The security audit exceeds $150k or the consent integration overruns its $500k cap, forcing a scope cut or budget approval delay mid-flight.
*   **Performance Gap:** The 30% enrollment speed increase fails to materialize because the 2-week pilot did not capture full-cycle data friction, leading to stakeholder rejection at launch.

**Stop/Re-prioritize Triggers**
*   **Hard Stop:** If the Regulatory Dossier is not provisionally approved by **15 November 2024**, halt all development spending immediately. Without regulatory clearance, the product cannot launch.
*   **Re-prioritize:** If the Consent Integration is not technically feasible by **Week 5**, drop it from Phase II and revert to manual consent processing to preserve the 31 Oct go-live for the core matching algorithm.
*   **Budget Gate:** If cumulative spend exceeds **$2.1M** by Week 6 without a signed change order, freeze non-regulatory work.

**Note:** The current $150k security buffer is insufficient for a full audit if the consent integration requires complex remediation; recommend flagging this as a potential contingency request. The 31 Oct go-live is at extreme risk given the 8-week build time starting in October; a realistic launch date is likely mid-December.
