**Rollout Plan & Recommendation**

**Sequence of Work:**
1.  **Days 1–5:** Draft pricing sheet and secure immediate Legal sign-off (parallel track).
2.  **Days 6–19:** Build CreditScorePro API integration.
3.  **Days 20–40:** Execute 50-merchant pilot (run concurrently with final API testing if possible, but strictly sequential if legal requires full integration first).
4.  **Days 41–45:** Finalize go/no-go decision and prepare launch assets.

**Deferral:** Defer the full 50-merchant pilot volume. Run a **10-merchant "smoke test"** during the API integration phase to validate the workflow. If the smoke test passes, complete the remaining 40 merchants post-launch or in a phased rollout. This compresses the critical path from 11 weeks to 6 weeks, fitting the 30-day window.

**Three Main Failure Modes:**
1.  **Integration Delay:** CreditScorePro API documentation is incomplete or sandbox access is delayed, pushing the start date beyond the 30-day window.
2.  **Underwriting Bottleneck:** The assumption of absorbing 40 extra applications/week without overtime proves false, causing approval delays that frustrate pilot merchants.
3.  **Unit Economics Collapse:** The 10% APR, while lower than the competitor's 12%, fails to cover risk costs because our smaller cohort (800 vs. 1,200) lacks the diversification to absorb early defaults.

**Stop/Pivot Metric:**
Dana should halt or re-prioritize if the **pilot conversion rate is <10%** OR if the **default rate in the first 30 days exceeds 2%**. A conversion under 10% indicates the product-market fit or pricing leverage is insufficient to justify the build cost against the competitor, while a >2% default rate at 10% APR threatens immediate capital loss given the smaller cohort size.

*Note: This plan assumes legal sign-off on the pricing sheet does not require the final API build to be complete. If legal requires a live demo, the timeline is at risk.*
