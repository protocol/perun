# RapidEnroll Execution Plan for CFO Review

**Recommended Work Order:**
1.  **Weeks 1–4:** Parallel start on **Electronic Consent Integration** (critical path, fixed vendor timeline) and **Regulatory Dossier** (highest uncertainty).
2.  **Weeks 1–8:** **Patient-Matching Algorithm** development (longest duration, starts immediately but finishes later).
3.  **Weeks 5–7:** **Pricing Tier Design** (depends on regulatory clarity; shortest duration).
4.  **Weeks 8–9:** **Security Audit** (must follow code completion) and final integration testing.

**Primary Failure Modes:**
*   **Regulatory Block:** The "unknown" timeline for the regulatory dossier could exceed the 5-week buffer, halting the go-live regardless of software completion.
*   **Integration Underestimation:** Assuming the consent integration takes half the time of the last one is a dangerous heuristic; if it drags to 6+ weeks, it blocks the security audit.
*   **Budget Overrun:** The $150k security audit buffer is thin. If the algorithm requires complex remediation post-audit, the $2.5M cap will be breached.

**Stop/Re-prioritize Trigger:**
If the **Regulatory Dossier** is not provisionally approved by **15 October 2024**, or if the **Consent Integration** is not in UAT by **1 October 2024**, you must halt the Phase II pricing design and re-scope the go-live date. The 31 October target is unreachable if these two upstream dependencies slip by more than 10 days.

***

*Note: The 30% enrollment speed projection should be presented as a "best-case pilot metric" rather than a guaranteed outcome, given the limited 2-week data sample.*
