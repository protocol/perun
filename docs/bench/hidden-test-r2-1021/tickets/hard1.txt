### h_rate_window
--- ticket
RateWindow(limit, window) allows at most `limit` events in any sliding window of `window` seconds. allow(t) is called with non-decreasing times; it records the event and returns True if allowed. An event at time e counts toward the window at time t only while e > t - window (an event exactly `window` seconds old no longer counts). A rejected call must not consume quota. retry_after(t) returns how many seconds until a call would be allowed (0 if it would be allowed now) and does not record anything.
Observed: after a burst of rejected calls legitimate callers stay blocked far longer than they should, one extra rejection happens exactly on the window boundary, and retry_after can return negative numbers or a wait when there is room.
--- src
from collections import deque


class RateWindow:
    def __init__(self, limit, window):
        self.limit = limit
        self.window = window
        self.events = deque()

    def allow(self, t):
        self.events.append(t)
        while self.events and self.events[0] < t - self.window:
            self.events.popleft()
        return len(self.events) <= self.limit

    def retry_after(self, t):
        return self.events[0] + self.window - t
--- fix
from collections import deque


class RateWindow:
    def __init__(self, limit, window):
        self.limit = limit
        self.window = window
        self.events = deque()

    def _evict(self, t):
        while self.events and self.events[0] <= t - self.window:
            self.events.popleft()

    def allow(self, t):
        self._evict(t)
        if len(self.events) >= self.limit:
            return False
        self.events.append(t)
        return True

    def retry_after(self, t):
        self._evict(t)
        if len(self.events) < self.limit:
            return 0
        return self.events[0] + self.window - t

### h_token_bucket
--- ticket
TokenBucket(capacity, rate, now=0) starts full. take(n, now) first refills `rate` tokens per second for the time since the previous call (fractional tokens are kept, the total never exceeds capacity), then removes n tokens and returns True if at least n tokens were available (exactly n is enough); otherwise it returns False and removes nothing (the refill still counts). If `now` is earlier than the previous call (clock stepped backwards) no tokens are added or removed and the bucket's notion of the last time does not move backwards.
Observed: taking exactly the remaining tokens is refused, and after a clock step backwards the bucket loses tokens and then refills too slowly.
--- src
class TokenBucket:
    def __init__(self, capacity, rate, now=0):
        self.capacity = capacity
        self.rate = rate
        self.tokens = capacity
        self.last = now

    def take(self, n, now):
        elapsed = now - self.last
        self.tokens = min(self.capacity, self.tokens + elapsed * self.rate)
        self.last = now
        if self.tokens > n:
            self.tokens -= n
            return True
        return False
--- fix
class TokenBucket:
    def __init__(self, capacity, rate, now=0):
        self.capacity = capacity
        self.rate = rate
        self.tokens = capacity
        self.last = now

    def take(self, n, now):
        elapsed = max(0, now - self.last)
        self.tokens = min(self.capacity, self.tokens + elapsed * self.rate)
        self.last = max(self.last, now)
        if self.tokens >= n:
            self.tokens -= n
            return True
        return False

### h_undo_editor
--- ticket
Editor keeps a text buffer with insert(pos, s), delete(pos, n) -> removed text, undo() and redo() (each returns True if something was undone or redone, else False). Rules: each insert or delete is one undoable step. A new insert or delete clears everything that could be redone. At most `limit` steps are kept; when more are made the OLDEST step is forgotten. An insert position past the end appends at the end (and undo must then remove exactly what was inserted). A delete that removes nothing (position past the end or n == 0) is not a step.
Observed: undo after inserting past the end corrupts the text, redo works after a fresh edit, and with a small limit the most recent edit is the one that gets lost.
--- src
class Editor:
    def __init__(self, limit=100):
        self.text = ""
        self.limit = limit
        self.undo_stack = []
        self.redo_stack = []

    def insert(self, pos, s):
        self.text = self.text[:pos] + s + self.text[pos:]
        self._push(("ins", pos, s))

    def delete(self, pos, n):
        removed = self.text[pos:pos + n]
        self.text = self.text[:pos] + self.text[pos + n:]
        self._push(("del", pos, removed))
        return removed

    def _push(self, op):
        self.undo_stack.append(op)
        if len(self.undo_stack) > self.limit:
            self.undo_stack.pop()

    def undo(self):
        if not self.undo_stack:
            return False
        kind, pos, s = self.undo_stack.pop()
        if kind == "ins":
            self.text = self.text[:pos] + self.text[pos + len(s):]
        else:
            self.text = self.text[:pos] + s + self.text[pos:]
        self.redo_stack.append((kind, pos, s))
        return True

    def redo(self):
        if not self.redo_stack:
            return False
        kind, pos, s = self.redo_stack.pop()
        if kind == "ins":
            self.text = self.text[:pos] + s + self.text[pos:]
        else:
            self.text = self.text[:pos] + self.text[pos + len(s):]
        self.undo_stack.append((kind, pos, s))
        return True

class Editor:
    def __init__(self, limit=100):
        self.text = ""
        self.limit = limit
        self.undo_stack = []
        self.redo_stack = []

    def insert(self, pos, s):
        pos = max(0, min(pos, len(self.text)))
        self.text = self.text[:pos] + s + self.text[pos:]
        self._push(("ins", pos, s))

    def delete(self, pos, n):
        removed = self.text[pos:pos + n]
        if not removed:
            return ""
        self.text = self.text[:pos] + self.text[pos + n:]
        self._push(("del", pos, removed))
        return removed

    def _push(self, op):
        self.undo_stack.append(op)
        self.redo_stack.clear()
        if len(self.undo_stack) > self.limit:
            self.undo_stack.pop(0)

    def undo(self):
        if not self.undo_stack:
            return False
        kind, pos, s = self.undo_stack.pop()
        if kind == "ins":
            self.text = self.text[:pos] + self.text[pos + len(s):]
        else:
            self.text = self.text[:pos] + s + self.text[pos:]
        self.redo_stack.append((kind, pos, s))
        return True

    def redo(self):
        if not self.redo_stack:
            return False
        kind, pos, s = self.redo_stack.pop()
        if kind == "ins":
            self.text = self.text[:pos] + s + self.text[pos:]
        else:
            self.text = self.text[:pos] + self.text[pos + len(s):]
        self.undo_stack.append((kind, pos, s))
        return True

### h_keyset_pages
--- ticket
page(items, limit, cursor=None) returns (chunk, next_cursor). items are dicts with "id" (unique, sortable) and "score". The order is score descending, ties by id ascending. The cursor is the (score, id) of the last item of the previous page and the next page starts strictly after that position in this order. next_cursor is None when there are no more items after this page (an exact multiple of the limit must not produce an extra empty page).
Observed: items that share a score with the last item of a page are skipped or repeated, and the final page sometimes returns a cursor that leads to an empty page.
--- src
def page(items, limit, cursor=None):
    ordered = sorted(items, key=lambda r: -r["score"])
    if cursor is not None:
        score, rid = cursor
        ordered = [r for r in ordered if r["score"] < score]
    chunk = ordered[:limit]
    nxt = (chunk[-1]["score"], chunk[-1]["id"]) if len(chunk) == limit else None
    return chunk, nxt
--- fix
def page(items, limit, cursor=None):
    ordered = sorted(items, key=lambda r: (-r["score"], r["id"]))
    if cursor is not None:
        score, rid = cursor
        ordered = [r for r in ordered if r["score"] < score or (r["score"] == score and r["id"] > rid)]
    chunk = ordered[:limit]
    nxt = (chunk[-1]["score"], chunk[-1]["id"]) if len(ordered) > limit else None
    return chunk, nxt

### h_merge_events
--- ticket
merge_events(streams) merges several event streams into one list of (timestamp, payload). Each input stream is already sorted by timestamp. The output is ordered by timestamp; when timestamps are equal, events from the lower-numbered stream come first, and within one stream the original order is kept. An event that appears in more than one stream with the same timestamp AND the same payload is reported once (the first occurrence in output order); events with the same timestamp but different payloads are all kept. Payloads are strings. Streams may be empty.
Observed: events that happen at the same instant disappear from the merged output and equal-timestamp events come out in alphabetical order of payload instead of stream order.
--- src
import heapq


def merge_events(streams):
    out = []
    seen = set()
    for ts, payload in heapq.merge(*streams):
        if ts in seen:
            continue
        seen.add(ts)
        out.append((ts, payload))
    return out
--- fix
import heapq


def merge_events(streams):
    keyed = [[(ts, i, j, p) for j, (ts, p) in enumerate(s)] for i, s in enumerate(streams)]
    out, seen = [], set()
    for ts, _i, _j, p in heapq.merge(*keyed):
        if (ts, p) in seen:
            continue
        seen.add((ts, p))
        out.append((ts, p))
    return out

### h_bank_transfer
--- ticket
Bank(balances) holds integer cents per account. transfer(src, dst, amount, key=None) moves `amount` from src to dst; the source also pays a fee of max(1, amount // 100) cents (the fee disappears, it is not credited anywhere). Rules: amount <= 0 or src == dst raises ValueError; an unknown account raises KeyError and must leave every balance untouched; if the source cannot afford amount + fee the call returns False and changes nothing; otherwise it returns True. When `key` is given, a repeated call with the same key returns the result of the first call (True OR False) and changes nothing.
Observed: money disappears when the destination account does not exist, small transfers are free, and retrying a rejected transfer with the same key sometimes succeeds a second time.
--- src
class Bank:
    def __init__(self, balances):
        self.bal = dict(balances)
        self.done = {}

    def transfer(self, src, dst, amount, key=None):
        if key in self.done:
            return self.done[key]
        if amount <= 0:
            raise ValueError("amount")
        fee = amount // 100
        self.bal[src] -= amount + fee
        if self.bal[src] < 0:
            self.bal[src] += amount + fee
            return False
        self.bal[dst] += amount
        if key:
            self.done[key] = True
        return True
--- fix
class Bank:
    def __init__(self, balances):
        self.bal = dict(balances)
        self.done = {}

    def transfer(self, src, dst, amount, key=None):
        if key is not None and key in self.done:
            return self.done[key]
        if amount <= 0 or src == dst:
            raise ValueError("amount")
        if src not in self.bal or dst not in self.bal:
            raise KeyError("account")
        cost = amount + max(1, amount // 100)
        ok = self.bal[src] >= cost
        if ok:
            self.bal[src] -= cost
            self.bal[dst] += amount
        if key is not None:
            self.done[key] = ok
        return ok

### h_lfu_cache
--- ticket
LFUCache(capacity): get(key) returns the value or None; put(key, value) inserts or updates. When full, put of a NEW key evicts the least frequently used key; among keys with the same use count, the least recently used one is evicted. Every get hit and every put (new or update) counts as one use; a new key starts with count 1. Updating an existing key never evicts. capacity <= 0 stores nothing (put is a no-op, get returns None).
Observed: after updating a key it is still evicted first, ties are evicted in insertion order instead of by recency, and a zero-capacity cache raises.
--- src
class LFUCache:
    def __init__(self, capacity):
        self.cap = capacity
        self.data = {}
        self.tick = 0

    def get(self, key):
        if key not in self.data:
            return None
        self.tick += 1
        v, f, _ = self.data[key]
        self.data[key] = [v, f + 1, self.tick]
        return v

    def put(self, key, value):
        self.tick += 1
        if key in self.data:
            self.data[key][0] = value
            return
        if len(self.data) >= self.cap:
            victim = min(self.data, key=lambda k: self.data[k][1])
            del self.data[victim]
        self.data[key] = [value, 1, self.tick]
--- fix
class LFUCache:
    def __init__(self, capacity):
        self.cap = capacity
        self.data = {}
        self.tick = 0

    def get(self, key):
        if key not in self.data:
            return None
        self.tick += 1
        v, f, _ = self.data[key]
        self.data[key] = [v, f + 1, self.tick]
        return v

    def put(self, key, value):
        if self.cap <= 0:
            return
        self.tick += 1
        if key in self.data:
            _, f, _ = self.data[key]
            self.data[key] = [value, f + 1, self.tick]
            return
        if len(self.data) >= self.cap:
            victim = min(self.data, key=lambda k: (self.data[k][1], self.data[k][2]))
            del self.data[victim]
        self.data[key] = [value, 1, self.tick]

### h_event_bus
--- ticket
Bus lets code subscribe handlers to topics. on(topic, handler, priority=0) returns an unsubscribe function. emit(topic, *args) calls the handlers of that topic with args and returns how many handlers it called. Order: higher priority first; equal priorities in the order they were subscribed. During one emit: a handler that was unsubscribed by an earlier handler in the same emit is NOT called; a handler subscribed during the emit is NOT called until the next emit. Calling an unsubscribe function twice is harmless. The same function subscribed twice is two separate subscriptions and each unsubscribe function removes only its own.
Observed: low priority runs first, handlers get skipped when another handler unsubscribes, and double unsubscribe raises ValueError.
--- src
class Bus:
    def __init__(self):
        self.subs = {}

    def on(self, topic, handler, priority=0):
        self.subs.setdefault(topic, []).append((priority, handler))
        self.subs[topic].sort(key=lambda p: p[0])
        return lambda: self.subs[topic].remove((priority, handler))

    def emit(self, topic, *args):
        n = 0
        for _, h in self.subs.get(topic, []):
            h(*args)
            n += 1
        return n
--- fix
class Bus:
    def __init__(self):
        self.subs = {}

    def on(self, topic, handler, priority=0):
        entry = [priority, handler, True]
        self.subs.setdefault(topic, []).append(entry)
        self.subs[topic].sort(key=lambda e: -e[0])

        def off():
            entry[2] = False
            self.subs[topic] = [e for e in self.subs[topic] if e is not entry]

        return off

    def emit(self, topic, *args):
        n = 0
        for e in list(self.subs.get(topic, [])):
            if not e[2]:
                continue
            e[1](*args)
            n += 1
        return n
