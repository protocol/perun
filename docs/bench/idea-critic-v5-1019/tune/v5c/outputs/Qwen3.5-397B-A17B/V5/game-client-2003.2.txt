First call: GO. The core problems (update delivery, cheating) are unsolvable at scale via physical media; a mandatory client is the only viable technical path, despite friction.

**Steelman:** A mandatory client is the singular control point required to solve update latency and cheat proliferation, creating a defensible ecosystem that eventually monetizes via a third-party store.

**Options:**
1.  **Do nothing:** Cheating escalates, updates fail, popular games rot. High risk of brand collapse.
2.  **Patches via web/retail:** Slow, easily bypassed by cheaters, high support costs.
3.  **Mandatory Client (Proposal):** High initial friction, but solves root causes and unlocks platform revenue.

**Fit:** Aligns with the north star of game longevity and integrity. Assumes broadband adoption will outpace client rollout (reasonable for 2003 PC gamers).

**Pre-mortem:** Failure occurs if the client launches with game-breaking bugs or if retail partners collectively delist titles before the digital base matures. However, these are execution risks, not strategic flaws. The cost of delay is immediate loss of game integrity.

**Evidence & Math:** Physical distribution cannot support frequent binary updates or real-time state verification. The proposal's logic holds: software distribution requires a software channel. The "universal broadband" concern is mitigated by the fact that the target audience (PC gamers playing popular titles) already possesses higher-than-average connectivity.

**Blocker Test:**
*Blockers:* NONE. No fact provided proves the target audience lacks the *minimum* required connectivity to download a client, nor that retailers would drop hits powerful enough to kill the studio.
*Risks:* Retail pushback, user friction, early bugs. These are managed via kill criteria, not reasons to stop.

**Kill Criteria:**
1.  If >15% of active users cannot launch the client due to connectivity within 60 days, pause mandatory enforcement.
2.  If cheat incidence does not drop by >50% in the first popular title within 90 days, re-architect the anti-cheat module.
3.  Leading Metric: Weekly Active Users (WAU) retention post-update vs. pre-update. Review date: Quarterly.

The risks are real but manageable; the alternative is certain degradation of the product. The proposal survives the attack.

DECISION: GO
