The proposal aims to replace a reliable, established mapping app with an unproven in-house version, risking user trust and core phone functionality. The stated risks are severe and immediate: less data, incorrect business info, and forced removal of a working app. The upside—control—is strategic but not urgent, and the fall deadline forces a premature, low-quality launch. The evidence provided does not show the new maps meet a minimum quality bar; it only lists providers, not performance. A better path is a phased rollout: ship the new app as an optional download first, fix data gaps, then switch the default only when metrics prove parity. This preserves control while limiting user harm. The proposal as written is a one-way door into a bad user experience with no kill criterion or pilot. It should not proceed as proposed.
