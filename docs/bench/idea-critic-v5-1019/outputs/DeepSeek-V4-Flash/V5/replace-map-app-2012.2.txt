First call: NO-GO. The stated facts show the new product is materially worse at launch, yet it replaces a working default for every user.

The steelman: owning the default map experience gives the phone maker strategic control, data leverage, and differentiation, and early rough edges can be fixed quickly after launch.

Against that: users lose a proven, superior tool for an unproven one. The proposal itself admits the new maps have far less data and wrong place information. That is not a future risk—it is the current state at the moment of forced replacement. Annoyance is not hypothetical; it is the predictable result of downgrading the default experience for millions of users with no opt-out.

Do nothing: keep the rival app, retain user satisfaction, lose strategic control. Cheaper alternative: ship the new maps as an optional download, build data quality, then switch default later. That reaches the same upside without forcing a worse product on everyone.

The pre-mortem writes itself: users open the new maps, find missing or wrong locations, lose trust in the phone maker, and the press covers the failure. The rival app was not removed for being bad; it was removed for being someone else's. That is a strategic reason, but it does not change the user-facing outcome.

The plan has no pilot, no measured quality gate, no rollback. The commitment is large and one-way for the fall release. The stated evidence—less data, wrong info—already shows the core claim "better control without unacceptable cost" fails on user value.

Blockers: proposal's own facts show the new default is worse than the incumbent, with no mitigation. Risks: strategic loss, but that does not outweigh the certain user downgrade.

DECISION: NO-GO
