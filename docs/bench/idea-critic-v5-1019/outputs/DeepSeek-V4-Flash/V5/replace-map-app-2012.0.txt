First call: NO-GO. The proposal asks users to downgrade from a mature, reliable product to an unproven one with known data gaps, risking trust and loyalty for marginal control.

The steelman: gaining control over a core experience and building long-term capability, accepting short-term friction.

Do nothing: keep the rival app, lose control but retain user satisfaction. Cheapest alternative: keep rival as default, offer new app as optional download, preserving choice and gathering data without forcing a downgrade.

Fit: control is a stated goal, but the plan risks the north star of user trust and satisfaction.

Pre-mortem: users hit wrong addresses and missing data, publicly blame the phone, switch brands. This is a two-way door—reversible—but the cost of delay is low; waiting a quarter to improve data costs little.

Evidence: the proposal itself states the new maps have "a lot less data" and wrong place info. These are facts, not risks. The core claim—that users will accept a worse default for the maker's benefit—is contradicted by the proposal's own admission of degraded quality.

Blockers: the stated facts show the target users (existing phone owners) will experience a worse default with no benefit to them. An alternative—optional app, keep rival default—reaches the same control goal (app exists, data improves) at lower risk and cost.

Risks: user annoyance, data gaps, loss of default rival. These are not speculative; they are stated as near-certain.

Kill criteria: none proposed. The plan lacks a pilot, metric, or rollback trigger.

The proposal fails as proposed: it forces a downgrade on users to serve the maker's interest, with no pilot or fallback. A staged rollout—optional first, default later—would test demand and fix data before forcing the change.

DECISION: NO-GO
