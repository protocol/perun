The proposal trades a proven, data-rich mapping experience for an unproven in-house app to gain strategic control. The risks are concrete and immediate: user trust in core navigation is fragile, and a default downgrade in data quality—especially wrong places or businesses—will generate visible backlash. The fall launch window offers no time to correct data gaps or refine the assistant integration. The rival’s app being removed by default will also invite negative press and user friction, even if users can manually reinstall it.  

While control over a key service is a legitimate long-term goal, the 2012 version of this app is not ready. The data deficit alone is a dealbreaker for a default experience. Users tolerate beta features in niche apps, not in the primary maps on their phones. The proposal’s benefits (integration with voice, 3D, navigation) do not outweigh the cost of degrading the core function for millions of existing users.  

The correct move is to delay until the app meets or exceeds the rival’s data coverage and accuracy, then roll out with opt-in testing or a gradual default switch. Approving now would risk brand damage and user churn. The executive team should not approve this version.  

DECISION: NO-GO
