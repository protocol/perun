First call: NO-GO. The proposal admits critical data deficits and functional gaps in a core utility, risking immediate user backlash and brand damage without a verified safety net.

**Steelman:** Replacing the rival's mature map with a proprietary solution grants strategic control and differentiation, but only if the baseline functionality (data accuracy, coverage) meets user expectations for daily navigation.

**Attack & Options:**
The proposal explicitly concedes "a lot less data," "wrong" business information, and user annoyance. In 2012, maps are a primary smartphone utility; shipping a degraded default is not a "strategic pivot," it is a product failure.
*   **Do Nothing:** Retain the rival's app. Cost: continued dependence. Risk: low.
*   **Dual-Ship:** Keep the rival's app as default, offer the new app as an optional, high-performance alternative for specific features (e.g., 3D views) while data matures. Cost: higher integration effort. Risk: medium.
*   **Proposed Plan:** Force the inferior app as default. Cost: massive user churn, support tickets, brand erosion. Risk: catastrophic.

**Fit & Pre-mortem:**
If the goal is "control," this method achieves it by seizing the leash and strangling the user experience. A pre-mortem reveals users immediately reverting to the web version of the rival's map or switching hardware ecosystems due to unreliability. The "cost of delay" (waiting for data maturity) is negligible compared to the cost of a broken launch.

**Evidence & Blockers:**
The proposal's own risk assessment serves as the blocker. It states as fact that place info "may be wrong" and data is significantly lower. There is no mention of a fallback mechanism (e.g., automatic failover to web maps if local data fails), no phased rollout, and no "escape hatch" for users to easily revert. Shipping a known-defective core feature violates the basic operator principle of "do no harm" to the installed base.

**Blockers:**
1.  **Functional Deficit:** Admission of significantly less data and incorrect business info creates an immediate utility gap versus the status quo.
2.  **No Mitigation:** Absence of a fallback, phased rollout, or easy revert option for a core system app.

**Risks:** User anger, increased support costs, competitor advantage, brand perception shift from "premium" to "broken."

**Kill Criteria:** If accuracy tests show >5% deviation from rival's data in top 50 metro areas, or if beta NPS drops below -10, halt default switch.

DECISION: NO-GO
