First call: NO-GO. The proposal admits the replacement has significantly less data and known inaccuracies compared to the established rival, directly degrading core utility for users immediately upon launch.

Steelman: Replacing a superior, data-rich rival map with an inferior internal build grants long-term strategic control and ecosystem independence, accepting short-term pain for future sovereignty.

Options:
1. **Do nothing:** Retain rival app; maintain user satisfaction but cede strategic control and data ownership.
2. **Dual install:** Keep rival as default, offer new app as optional download; tests data without forcing degradation.
3. **Proposed plan:** Force inferior app as default; maximizes strategic control immediately but guarantees user friction and functional regression.

Fit: While aligning with a "control" vision, it violates the implicit north star of "best user experience" by knowingly deploying a degraded product as the default.

Pre-mortem: Users encounter missing businesses and wrong turns within days; trust erodes; media highlights the downgrade; the rival's app remains superior, making the switch look like a hostile, quality-reducing move rather than an innovation. This is a one-way door; once users lose confidence in native maps, regaining it is exponentially harder. Cost of delay: Low. Waiting allows time to reach parity before forcing the switch.

Evidence: The proposal itself states the new maps have "a lot less data" and information "may be wrong." These are admitted facts, not risks.

Blockers:
1. **Functional Regression:** The core claim (providing navigation) is undermined by admitted data gaps. A navigation tool with wrong data fails its primary function.
2. **User Value Destruction:** Removing a working, superior tool for a known inferior one creates immediate negative value for the user base.

Risks: User annoyance (too mild; this is active harm), rival exclusion (strategic goal, not a risk).

Kill Check: Does the data gap concern the core claim? Yes. Do the facts support it will happen? Yes, admitted in text. Is the commitment irreversible? Yes, default status is hard to walk back without admitting failure. Three yeses: this is a blocker.

The plan commits to a degraded experience without a pilot, cap, or parity milestone. It trades verified user value for hypothetical future control immediately.

DECISION: NO-GO
