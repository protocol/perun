The spec explicitly addresses most output-safety floors: it includes AI disclosure (DISC handled), easy override/appeal (RELY handled), opt-in consent without pressure (DARK handled), and a human-in-the-loop gate for irreversible actions like surgery scheduling or prescriptions (AUTO handled). It also cites internal testing showing equal flagging rates across age groups, suggesting an initial check for BIAS, though long-term monitoring across other protected groups remains necessary post-launch.

However, the spec states answers carry a "stated confidence level" but does not define whether this is a calibrated coarse tier (e.g., "Corroborated") or a raw model probability (e.g., "87%"). If the latter, it risks inviting over-trust via false precision, potentially triggering RELY or HALLU concerns if users misinterpret the number as a guarantee. Additionally, while sources are cited, the spec does not confirm a mechanism to prevent fabricated citations (HALLU) beyond the citation itself; without an eval plan for hallucination rates provided in the text, residual risk remains unquantified.

Despite these nuances, the spec demonstrates awareness of high-stakes gating and user agency. The critical failure modes (un gated automation, hidden AI, dark patterns) are explicitly denied in the design. The remaining risks (confidence precision, hallucination verification) are measurement gaps rather than design flaws requiring an immediate block, provided the pilot includes strict monitoring and the confidence display is verified to be non-numeric or well-defined.
