The spec explicitly identifies two present harms. First, the signup flow uses a countdown timer and a pre-ticked consent box for location tracking; this matches **DARK** (deceptive patterns pressuring users against their interest). Second, the post-session summary presents every answer as "confirmed fact with no source shown," which matches **HALLU** (unverified claims presented as fact) and creates a transparency gap.

Other categories are addressed in the spec: **DISC** is handled via visible AI labels; **RELY** is mitigated by override/appeal options; **AUTO** is blocked by human approval for irreversible actions. While the spec claims comfort regarding **BIAS** based on internal testing, the instruction requires flagging only harms the spec describes as present. The spec admits the "confirmed fact" presentation is a current state ("we'll revisit after the pilot"), making HALLU a present failure. The dark patterns in signup are also described as current functionality.

Because the feature ships with deceptive signup mechanics and presents unverified outputs as absolute facts without sources, it requires fixes before launch.

HARMS: DARK, HALLU
DECISION: BLOCK
