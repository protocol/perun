The spec explicitly addresses several harm categories: it notes an override exists (mitigating RELY), labels outputs as AI-generated (mitigating DISC), uses unticked consent without pressure (mitigating DARK), and requires human sign-off for irreversible actions (mitigating AUTO). It also cites pilot testing across groups, suggesting BIAS is considered, though not fully resolved.

However, the spec states: "The interface presents every answer as confirmed fact with no source shown." In a hospital security context, presenting unverified directory matches or questionnaire interpretations as "confirmed fact" without displaying sources constitutes presenting unverified claims as fact. This directly triggers the HALLU category, as the system hides the provenance of its decisions while asserting certainty. Even if the underlying data is live, the *presentation* fabricates authority by removing source visibility, risking staff over-trust in potentially erroneous matches despite the override button.

HARMS: HALLU
DECISION: BLOCK
