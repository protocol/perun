**Steelman:** Converting the desktop tool to a free web app with satellite imagery and routing creates a ubiquitous, zero-friction utility that leverages the acquirer's search dominance to monopolize local intent, despite 2004 browser limitations.

**Skeptic Attack:** The primary failure mode is technical impossibility: 2004 browsers lack the rendering engine speed and AJAX maturity for smooth, interactive map tiling and vector routing at scale. If the interface lags, users will revert to downloadable clients or static atlas sites. Second, the "free" model burns cash on expensive imagery licensing with no clear path to recoupment if ad integration disrupts the user experience.

**Better Way:** Instead of a full-featured interactive web app immediately, launch a hybrid: keep the heavy-duty desktop client for power users while releasing a lightweight, read-only web viewer for quick lookups. This validates demand without betting the entire integration on unproven browser graphics capabilities. Alternatively, license the technology to existing portals rather than building a standalone destination.

**Pre-mortem & Kill Criteria:** Assume failure: The site launches, but tile loading times exceed 5 seconds, causing 80% bounce rates, while licensing fees drain the acquisition budget within 18 months.
*   **Door Type:** Two-way door (can revert to desktop-focused strategy or shut down web tier).
*   **Cost of Delay:** High. Competitors could secure exclusive imagery deals or define the web mapping standard first.
*   **Kill Criterion:** If average tile render time exceeds 2 seconds on standard consumer connections after three optimization cycles, or if user session duration falls below 45 seconds by Q4 2005, terminate the web-only push and reinvest in desktop integration.

**Decision:** The strategic fit with a search company is undeniable, and the "free" model aligns with scaling search inventory. However, the technical risk in 2004 is extreme. The proposal must proceed but strictly as a capped, time-boxed experiment to prove browser viability before committing to a full sunset of the desktop product. The potential to redefine global navigation outweighs the execution risk, provided the kill criteria are enforced immediately upon launch metrics.

DECISION: GO
