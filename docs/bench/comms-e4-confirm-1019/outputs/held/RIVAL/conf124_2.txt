# TriageFlow: Choose prioritization approach for Feb 12 release

This PR introduces the new **TriageFlow** module (formerly "triage queue") with an updated dashboard using the new color scheme. Before we lock the design for the Feb 12 release, we need to select the core prioritization strategy.

Two approaches emerged from the spike:

*   **Option A: Rule-based prioritizer.** Uses static severity weights. It is fast to implement and requires low infrastructure overhead. However, analysis shows it misses **18%** of at-risk urgent cases (false negatives).
*   **Option B: Lightweight ML scorer.** Leverages our historical data (4,300-case sample) to predict urgency. This reduces the false-negative rate to **7%**, significantly improving safety for at-risk patients. The trade-off is the need for a nightly batch job to maintain model accuracy.

**Decision Required**
@Dana, please review and approve which approach we should take into the sprint.

Given the 11% gap in missed urgent cases between the two options, Option B offers a clear safety advantage, though it adds operational complexity. Option A is simpler but carries a higher risk of overlooking critical cases.

We need your sign-off by **next Friday, Feb 6**, to finalize the architecture and meet the Feb 12 release target.
