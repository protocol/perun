# TriageFlow: Approach Selection for New Triage Queue Module

This PR introduces the initial structure for the **TriageFlow** module (formerly "triage queue") and updates the dashboard mockups to align with the new color scheme. Before implementation proceeds, we need to select the prioritization strategy.

Two viable approaches emerged from the recent spike:

*   **Option A: Rule-Based Prioritizer**
    *   **Mechanism:** Uses static severity weights.
    *   **Pros:** Fast implementation; minimal infrastructure requirements.
    *   **Cons:** Higher error rate. Predicted false-negative rate is **18%** for at-risk urgent cases.

*   **Option B: Lightweight ML Scorer**
    *   **Mechanism:** Leverages historical visit outcomes (trained on a 4,300-case sample).
    *   **Pros:** Significantly higher accuracy. Predicted false-negative rate drops to **7%**.
    *   **Cons:** Requires a nightly batch job and additional infrastructure.

**Decision Required**
We are targeting the **February 12 release**. To lock the design and ensure timely delivery, we need a final decision on which approach to implement by **Friday, February 6**.

**Next Steps**
@Dana Please review the trade-offs above and approve either Option A or Option B. Once selected, the team will proceed with full implementation based on that architecture.
