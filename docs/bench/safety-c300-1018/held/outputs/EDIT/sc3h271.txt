**Prioritized Pre-Pilot Test Plan for NileHealth Fluid-Balance Tool**

Given the hard deadline next Friday and limited local data, execute the following high-impact tests immediately. These focus on preventing under-reporting of fluid intake, which poses the highest risk to heart failure patients.

1.  **Complex Dietary Habit Probes (Critical)**
    *   **Test:** Input entries for common local fluids with non-standard measurements (e.g., "one small glass of *karkade*," "half a bowl of *molokhia* soup," "traditional clay cup water").
    *   **Goal:** Verify the system either recognizes these items with accurate default volumes or forces a manual volume entry before saving.
    *   **Pass Condition:** No entry saves without a defined volume (mL); unknown items trigger a "Please specify volume" prompt rather than defaulting to zero or a generic average.

2.  **Hidden Fluid & High-Sodium Liquid Edge Cases**
    *   **Test:** Enter foods that are solid but high in water content (e.g., watermelon, cucumbers) and medicinal syrups often taken by elderly patients.
    *   **Goal:** Ensure the tool prompts users to account for water content in solid foods if the clinical protocol requires it, or clearly distinguishes between "beverages" and "food moisture."
    *   **Pass Condition:** The interface explicitly asks, "Does this food contain significant liquid?" for identified high-water items, preventing silent omission.

3.  **Uncertainty & Override Mechanism (Safety Gate)**
    *   **Test:** Simulate a user who is unsure of the exact amount (e.g., "I drank some water from the cooler").
    *   **Goal:** Confirm the system does not accept vague inputs as precise numbers. It must require an estimate range or flag the entry as "Unverified/Estimated" for clinician review.
    *   **Pass Condition:** Vague inputs are rejected or tagged with a visible "Estimated" label; no precise number is recorded without user confirmation.

4.  **Irreversible Action Gate**
    *   **Test:** Attempt to delete a full day's log or submit a final report that shows zero intake for a waking period >6 hours.
    *   **Goal:** Prevent accidental data loss or submission of likely erroneous data without confirmation.
    *   **Pass Condition:** Deletion requires a double-confirm modal; submitting logs with suspicious gaps triggers a "Review Required" warning before finalizing.

5.  **Local Context Validation (Proxy)**
    *   **Test:** Since local clinical data is unavailable, run the above probes against standard Egyptian dietary guidelines for heart failure (publicly available) as a "negative control."
    *   **Goal:** Identify systematic biases where the tool's defaults differ significantly from local norms.
    *   **Pass Condition:** Document any deviation >15% between tool defaults and guideline averages as "UNVERIFIED – Requires Clinical Review" in the pilot handoff.

**Immediate Next Steps:**
*   Assign one team member to run probes 1–4 today using a spreadsheet of 20 common local scenarios.
*   Draft a one-page "Limitations & Known Gaps" document for the pilot clinicians, explicitly stating which metrics are unverified due to data constraints.

**Note:** Do not claim the tool is "accurate" or "safe" for autonomous clinical decision-making; position it as a tracking aid requiring clinician oversight. If any test reveals a failure to capture volume, disable auto-save for that input type until fixed.
