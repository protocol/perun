**Content Moderation & Safety Plan for Cairo LinguaTech**

Given the four-week deadline and the constraint against extensive human review of *all* dialogues, we cannot certify the system as "unbiased" or "safe" prior to launch. Instead, we will implement a risk-managed rollout focusing on high-stakes harms with a strict human gate for irreversible actions.

**1. Harm Inventory (MAP)**
Before launch, we will document specific risks for the cultural tutor feature:
*   **Bias/Unfair Outcomes:** The model reinforcing stereotypes about Middle Eastern cultures (e.g., gender roles, religious practices) that disadvantage or offend specific user groups.
*   **Hallucination as Fact:** Presenting fabricated cultural customs or historical events as verified truth.
*   **Over-reliance:** Students accepting AI-generated phrases as authoritative without uncertainty indicators.
*   **Missing Disclosure:** Users unaware they are interacting with an AI, leading to misplaced trust in cultural advice.

**2. Measurement Strategy (MEASURE)**
We will deploy automated evals rather than manual review of every output:
*   **Adversarial Probe Set:** Create a test suite of 50+ prompts targeting sensitive cultural topics (religion, politics, gender). Include "known-bad" positive controls (prompts designed to trigger stereotypes) and "known-good" negative controls.
*   **Metric & Threshold:** Measure the rate of stereotype reinforcement in probe responses. Set a **zero-tolerance threshold** for any output containing hate speech or dangerous misinformation. For nuanced bias, define an owner-set acceptable failure rate; if exceeded, the feature blocks launch.
*   **Transparency Artifact:** Publish a **Model Card** detailing intended use (language learning), limitations (not a substitute for human cultural experts), and known failure modes. Any metric not explicitly measured will be labeled **UNVERIFIED**, never invented.

**3. Risk Management Controls (MANAGE)**
*   **Human-in-the-Loop Gate:** While we cannot review all dialogues, any **high-stakes or irreversible action** (e.g., generating content for public marketing, certifying a user's cultural competency for professional use) requires explicit human confirmation. Automated generation for private practice is permitted but capped.
*   **Uncertainty Display:** The UI will not show raw confidence percentages (e.g., "87% accurate"). Instead, use defined coarse tiers: **"Verified by Educators"** (human-reviewed), **"AI-Generated"** (standard output), or **"Unverified/Experimental"** (low confidence). This prevents automation bias.
*   **Disclosure:** Clearly label all conversational partners as "AI Tutor" to manage user expectations.
*   **Kill Switch:** Implement an immediate rollback mechanism if post-launch monitoring detects a spike in harmful outputs.

**4. Governance (GOVERN)**
*   **Owner Assignment:** Name a specific Product Owner responsible for reviewing harm reports weekly.
*   **Legal Routing:** The question of whether specific cultural disclosures are legally required in target markets is a legal determination. Route this to counsel immediately; do not assert compliance internally.

**Execution Timeline (4 Weeks):**
*   **Week 1:** Finalize Harm Inventory and build adversarial probe set.
*   **Week 2:** Run automated evals; tune filters until thresholds are met. Draft Model Card.
*   **Week 3:** Implement UI uncertainty tiers and disclosure labels. Legal review of disclosure duties.
*   **Week 4:** Staged rollout to 5% of users with enhanced logging; full launch only if stop conditions are not triggered.

**Note:** This plan manages residual risk; it does not eliminate it. If the probe set reveals systemic bias that cannot be filtered without breaking core functionality, the launch constraint must be re-evaluated.
**Note:** Never fabricate a "0% bias" metric; report actual eval results or mark as UNVERIFIED.
