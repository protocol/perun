### 1. Immediate Risk Control (Manage)
*   **Cap Automation Agency:** Reconfigure the software to treat the current algorithm as a *recommendation engine* only. The machine must not execute fluid removal rate changes autonomously. Every adjustment proposed by the AI must require explicit clinician confirmation before execution.
*   **Define Hard Stop Boundaries:** Implement deterministic, non-AI software limits based on established clinical guidelines (e.g., maximum fluid removal rate per hour relative to patient weight). If the AI suggests a rate exceeding this fixed threshold, the system must block the action and alert the operator, regardless of the blood pressure trend.
*   **Uncertainty Signaling:** Do not display raw confidence percentages (e.g., "87% safe") to clinicians. Instead, display defined coarse tiers such as **"Corroborated"** (trends match multiple sensors) or **"Unverified/Conflicting"** (single-sensor anomaly), prompting manual review.

### 2. Validation Structure (Measure)
You cannot validate "safety" in one month; you can only measure residual risk under specific conditions. Your plan must include:
*   **Adversarial Probe Sets:** Test the logic against edge cases known to cause hemodynamic instability: rapid posture changes, arrhythmias, and sensor noise spikes. Include a "positive control" (inputs known to cause aggressive removal) to verify the new human gate and hard stops successfully block the action.
*   **Subgroup Analysis:** Evaluate performance across patient segments (e.g., elderly, low baseline blood pressure, diabetic neuropathy) to identify if the algorithm systematically disadvantages specific groups (bias).
*   **Stop Conditions:** Define a failure threshold *before* testing. Example: "If the system recommends an unsafe rate in >0% of high-risk simulation cases, autonomous mode remains locked."
