# Review cost per real bug caught, and false alarms per case

BLUF: on the one set with per-case data (S1, n=22, patch-only), Perun's real skill catches 13 of 22 bugs at about $0.093 per caught bug against $0.030 for the Anthropic toolkit code-reviewer (3.1 times as much), with the same 0.50 false alarms per case. Recall is not separable (0.591 against 0.545, intervals overlap). In the reported sets Perun costs 1.5 to 2.1 times the cheapest rival or plain prompt per case (3.4 times in S1) at equal or lower recall, so its cost per caught bug is higher in every row except the comparison with `/code-review` plus verifier (S3, where the source shows a recall gain whose interval excludes 0). Generated by `scripts/review_cost_per_recall.py` from committed files only; no model was called and nothing was spent.

## Method

- Recall = caught bugs / seeded bugs (one reference bug per case on every corpus here). False alarm = a finding the verifier did not credit as real or as the reference bug, so `unverifiable` counts as false. Review $ per case = model spend of the review calls only (the verifier is shown separately). $ per caught bug = review $ per case / recall.
- S1 is recomputed from per-case raw outputs: `docs/bench/review-real-skill-1016/outputs/`, `ledger.jsonl` and `results.json`. Crediting is that bench's `driver.tally` (strict match through `.claude/skills/deep-code-review/scripts/score_review.py`, plus the verifier's `real`/`gt_same` verdicts). Per-case means get a percentile bootstrap CI from `scripts/rival_eval.py` (`boot`, 10,000 resamples, seed 1); recall and $ per caught bug are ratios of sums, bootstrapped over cases the same way. The test checks the recomputed counts and recall CI equal the committed `results.json`.
- Every other set is transcribed into `reported.tsv` (column `source` names the file). Those files publish aggregates only, because per-case data for the held-out sets was kept private on purpose, so these rows have no CI. `Caught` is the published recall times n, rounded; the test checks it is within rounding of an integer and that each recall (or k/n) and each dollar figure appears in the cited file. False alarms per case need findings and judged-good counts; where the source does not publish them the cell says `unmeasured`.
- Rows are comparable only within a set: the sets differ in corpus, model, harness and verifier. Do not rank across sets.

## Reading

- Cost per caught bug is Perun's weak axis: toolkit $0.030 against Perun $0.093 (S1); plain prompt $0.160 against Perun $0.238 (S3); toolkit $0.303 against Perun $0.457 at equal recall (S2); plain prompt $0.120 against Perun single pass $0.246 (S5). The one row where Perun is cheaper per caught bug than a rival is `/code-review` plus verifier (S3: $0.238 against $0.466), and there Perun's recall is also higher (+0.118 [+0.029, +0.235] in the source).
- The only rows where cost per caught bug falls are the ones where recall rose: repo access (S6, $0.224 to $0.113). That comes from the harness, not from the review method (`docs/bench/bench90-results.md`: the full skill on top of repo access gave -0.044 recall at 1.5 times the cost).
- Two passes buy recall at the price of cost per caught bug (S5: $0.246 to $0.414; S4: gap pass added 21 findings and no recall, $0.367 to $0.796) and more false alarms (S5 0.76 to 1.13 per case).
- Perun's false-alarm edge shows against the plain prompt in S5 (0.76 against 0.94 per case) and S4 (0.94 against 1.33); against the toolkit in S1 it is a tie (0.50 each). The `/code-review` false-alarm gap in S3 is unmeasured here because the source publishes precision only.

## Limits

- n is 18 to 90 cases, one run per case, one model family per set, a model verifier. Only S1 has a CI, and it is wide: $ per caught bug for Perun spans $0.066 to $0.150 and the toolkit's spans $0.017 to $0.056, so the 3.1 times ratio is real in direction but loose in size (the intervals do not overlap).
- Recall counts one run per case; the sources show run-to-run noise of one or two bugs on these sizes; one bug moves $ per caught bug by about 8 percent at S1 (13 caught) and 20 percent at S4 (5 caught).
- `$ per caught bug` assumes one reference bug per case. S1 confirms it (22 bugs, 22 cases); the other corpora's published recall values are integer multiples of 1/n, which is consistent with it but not proof.
- Unmeasured: false alarms per case for S2, S3, S3b and S6; any CI for S2 to S6; Opus-reviewer rows in README (`$0.17` against `$0.27`) and the with-tools run, for which I found no committed per-run artifact in `docs/bench/`; spend on the verifier for every reported set except where the source states it.
- The bench for the fix this page informs (`review-cost-parity-1017`, token ratchet) ran on free models, so it has tokens but no dollars and is not in the tables.

## Numbers elsewhere that disagree with the computed ones (flagged, not edited)

1. `README.md` line 114 says "Perun cost $0.20 per case against $0.14 to $0.16" for the 37-case head-to-head. `bench-results.md` (same run) says $0.136 against $0.090 to $0.098, and `docs/perun-vs-rivals.md` uses $0.136 and $0.090 to $0.096. No committed file reproduces $0.20, $0.14 or $0.16 (a verifier-inclusive figure would be a guess). The ratio also differs: 1.5 times the toolkit in `bench-results.md`, 1.25 to 1.43 times in the README sentence.
2. `README.md` line 49 gives the 39-case cost per case as $0.06 plain and $0.12 Perun (2.0 times); `bench-results.md` says the 37-case run used the same harness on 37 of those 39 cases and gives $0.098 plain and $0.136 Perun (1.4 times). Plain-prompt cost differs by 1.6 times between two runs of one harness and one case set, so the plain-prompt cost used as the baseline moves the "about 2 times" claim.
3. H7b cost ($0.0537 against $0.0153, 3.5 times) is the mean over all non-error review calls in the ledger (27 REAL and 25 TK calls on 22 cases, because some cases were re-run). Averaged per case it is $0.0551 against $0.0162 (3.4 times); total review spend divided by 22 is $0.0659 against $0.0174 (3.8 times). `results.json` `cost.REAL.calls` says 35, which counts the zero-cost error rows too. The published figure is a correct mean of calls, not of cases; state the basis when citing it.
4. The roadmap entry `review-cost-per-recall` derives "$0.25 per unit of recall against $0.16 for a plain prompt" from README line 49 (39 cases). Recomputed from the same rounded costs it is $0.246 against $0.156, so it agrees, but it rests on costs that item 2 shows are unstable.
5. `docs/bench/bench90-results.md`: the agentic table labels $0.073 "including verifier" while the high-stakes table shows the same $0.073 as "cost per review". One of the two labels is wrong or the figures differ in basis; the `$ basis` column marks it `unclear`.
