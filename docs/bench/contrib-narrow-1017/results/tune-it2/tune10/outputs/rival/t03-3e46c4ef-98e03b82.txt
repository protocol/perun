Commit locally with your personal email address before pushing. Do not push the commit containing your corporate email.

Here is the safest workflow to ensure no legal ambiguity or implied endorsement:

1.  **Configure Git for this repository only.**
    Navigate to the project folder and run:
    ```bash
    git config user.email "your.personal.email@example.com"
    git config user.name "Your Name"
    ```
    This overrides your global employer settings strictly for this open-source contribution without affecting your other work.

2.  **Amend the existing commit.**
    Since you have already written the commit with the wrong email, rewrite it locally:
    ```bash
    git commit --amend --no-edit --reset-author
    ```
    The `--reset-author` flag updates the author metadata to the personal email you just configured. The `--no-edit` flag keeps your improved error message text exactly as it is.

3.  **Verify the change.**
    Run `git log -1` to confirm the author email is now your personal address. Ensure the corporate email does not appear in the history.

4.  **Push the corrected commit.**
    If you have not yet pushed, simply run `git push`. If you already pushed the version with the corporate email, you must force-push the corrected history:
    ```bash
    git push --force-with-lease
    ```
    Using `--force-with-lease` is critical; it ensures you do not accidentally overwrite any changes if the remote branch was updated unexpectedly.

**Why this is necessary:**
Using a corporate email on an external project can trigger internal legal reviews at your company or imply that "Globex Corporation" stands behind the patch. Open-source licenses generally rely on the individual contributor, not their employer. By using a personal email, you clearly establish that you are contributing as an individual, protecting both you and the project maintainers from potential licensing complications or claims of corporate endorsement.

Note: The project's small team values concise commits; amending locally keeps the history clean with a single, correctly attributed commit rather than adding a "fix email" follow-up.
