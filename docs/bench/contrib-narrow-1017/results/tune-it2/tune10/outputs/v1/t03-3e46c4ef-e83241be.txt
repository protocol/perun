**Deliverable: Safe Submission Plan**

Do not submit the patch with your corporate email address. While a corporate email does not automatically transfer copyright to your employer, it creates immediate ambiguity regarding endorsement and may trigger unnecessary legal reviews by the maintainers. The safest and standard practice is to amend your commit locally to use a personal email address before pushing.

Execute these steps:

1.  **Configure Local Override:** In your specific project directory, set your personal identity without affecting your global work configuration:
    ```bash
    git config user.name "Your Name"
    git config user.email "your.personal.email@example.com"
    ```
2.  **Amend the Commit:** Rewrite the most recent commit to apply this new identity:
    ```bash
    git commit --amend --no-edit
    ```
    *Note: If you have already pushed this branch to a remote, you will need to force-push (`git push --force-with-lease`) after amending. Ensure no one else is working on this specific branch.*
3.  **Verify the Change:** Confirm the author line is updated:
    ```bash
    git log -1 --pretty=format:"%an <%ae>"
    ```
4.  **Internal Clearance (Stop Check):** Before sending, ensure your employer's IP policy allows individual contributions to open-source projects under your own name. If your employment contract requires explicit written permission for *any* code written on company time/equipment, obtain that approval now. The contribution itself should not mention "Globex Corporation," "employer," or any internal ticket numbers.
5.  **Draft the Commit Message:** Keep it concise as per project norms.
    ```text
    Improve error message for corrupt wheel files

    Replace raw traceback with a clear explanation and recovery suggestion
    when a wheel file integrity check fails.

    Fixes confusion for users encountering binary corruption.
    ```
6.  **Draft the PR Body:**
    ```text
    ## Problem
    Users see a raw Python traceback when a wheel file is corrupt, which offers no actionable advice.

    ## Change
    - Catch the specific integrity error.
    - Display a concise message suggesting re-download or cache clearance.
    - Remove the stack trace from the standard user output.

    ## Testing
    - Verified behavior with a manually corrupted wheel file.
    - Confirmed clean exit code and readable message.
    - [Paste specific output snippet here if available]

    ## Note
    Author identity amended to personal address to avoid corporate endorsement ambiguity.
    ```

**Direct Answer to Your Uncertainty:**
You should **amend the commit locally** to use a personal address. Leaving the corporate email creates a "gray zone" where maintainers might fear they are accepting a corporate asset requiring a CLA (Contributor License Agreement) or legal sign-off, potentially delaying or rejecting your helpful fix. A personal email signals an individual contribution, which aligns with the project's existing history.

**Fallback:**
If you cannot use a personal email due to strict employer policies requiring all code to bear the corporate identity, do not open a PR directly. Instead, file an issue describing the problem and the proposed text change, explicitly stating: "I can provide a patch, but my employer requires contributions to originate from a corporate email. Please advise on your preferred process for corporate contributions." This puts the ball in the maintainers' court to request a CLA or provide instructions.

Ensure your patch contains no file paths, variable names, or comments referencing "Globex," internal servers, or proprietary project names. The fix must stand entirely on the public logic of the packaging tool.
