**Proposal Draft for Maintainers**

**Subject:** Proposal: Community-Supported Backport for Critical RCE in Legacy LTS Branch

**Context & Acknowledgement**
We acknowledge the project's current stance discouraging contributions to the legacy LTS branch and the strong recommendation for users to upgrade to the latest version. We appreciate the maintainers' focus on forward development and understand the resource constraints that prevent official testing or support for older releases.

**The Issue**
A severe security vulnerability has been identified in the legacy LTS branch involving remote code execution (RCE) via a malformed header. This flaw poses a critical risk to any deployment still operating on this version.

**The Constraint**
While upgrading is the ideal long-term solution, a significant segment of the user base operates in environments with strict hardware constraints that make immediate migration to the latest version technically infeasible. These users are currently exposed to active exploitation risks with no official mitigation path.

**The Proposal: Community-Driven Backport**
We propose submitting a minimal, surgical backport patch that resolves the RCE vulnerability without altering the public API or introducing new features. Key characteristics of this contribution include:

*   **Scope-Limited:** The change addresses only the specific memory safety issue in the header parsing logic.
*   **Non-Burdensome:** We are not requesting the maintainers to run tests, provide CI support, or officially endorse the legacy branch.
*   **Community-Supported:** Our team will assume full responsibility for validating the patch in our own environments. We seek only permission to merge this change into the legacy branch for the benefit of the wider community who cannot yet upgrade.

**Community Benefit**
Accepting this backport provides a vital safety net for users trapped in legacy environments, preventing potential widespread compromise while they plan their migration strategies. It demonstrates the project's commitment to user security even in end-of-life scenarios, without requiring additional maintenance overhead from the core team.

**Request**
We request approval to submit this patch as a community-supported contribution. We are prepared to provide the diff, a detailed technical explanation of the fix, and our internal validation results upon your go-ahead. We ask only for the opportunity to help secure the ecosystem for those who need it most.
