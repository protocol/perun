**Root Cause Analysis:**
Investigation indicates that the current implementation does not properly encode or escape special characters in the `Content-Disposition` header. While standard filenames process correctly, unescaped characters trigger a rejection. This behavior is exacerbated in network environments where intermediate proxies or firewalls strictly enforce RFC compliance on header syntax, causing the request to be dropped before reaching the application logic.

**Proposed Fix:**
The fix implements proper URL encoding for the filename parameter within the `Content-Disposition` header, ensuring compliance with RFC 5987. This prevents syntax errors in the header string and ensures compatibility with strict network intermediaries.
