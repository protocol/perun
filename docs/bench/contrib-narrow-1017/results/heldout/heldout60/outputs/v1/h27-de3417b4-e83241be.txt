**Title:** fix: Restore graceful degradation for out-of-stock items to prevent checkout crashes

**Problem**
The recent update to StockSync changed the handling of out-of-stock inventory checks to throw a hard exception, causing immediate checkout termination. While this improved performance for strict-inventory workflows, it introduced a regression for retailers supporting backorders or pre-orders. For these users, an out-of-stock status is a valid business state, not a fatal error. The current behavior forces downstream applications to wrap all inventory calls in excessive try-catch blocks or risks production outages during standard sales flows.

**Change**
This PR modifies the inventory resolution logic to distinguish between "unavailable due to error" and "unavailable due to stock level."
- Reverts the hard crash when `quantity == 0` if the item allows backordering.
- Restores the previous behavior of returning a `BackorderStatus` object, allowing the UI to render the appropriate message.
- Preserves the new performance optimizations for the standard in-stock path.
