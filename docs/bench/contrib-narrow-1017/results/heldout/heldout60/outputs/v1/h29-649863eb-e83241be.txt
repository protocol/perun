**Strategy: One Atomic Commit, Pre-Approved**

Do not split this into ten pull requests. Maintainers universally prefer a single, atomic commit for mass cosmetic fixes over multiple small PRs that spam notification channels and fragment history. However, because this touches 40 files, you must secure permission *before* opening the PR to avoid it being closed as "noise."

**Step 1: The Pre-Check (Crucial)**
Open an issue titled "Proposal: Mass fix of 'LIcence' typo in license headers."
*   **Body:** "I noticed a recurring typo ('LIcence') in the license headers of ~40 core files. I propose a single atomic commit to fix this across the codebase to keep history clean. No logic changes. Is this acceptable, or should I wait for a larger refactor?"
*   **Wait:** Do not write code until a maintainer says "Yes" or "Go ahead." This respects their time and validates the effort.

**Step 2: Verification of Changes**
To ensure absolutely no logic was modified, run these commands locally before committing:
1.  **Diff Check:** `git diff -U0 | grep -v "^@@\|^diff\|^index\|^---\|^+++\|^LIcence\|^License"`
    *   This command shows the diff but filters out the header lines. If any output remains, you accidentally changed code. Stop immediately.
2.  **Checksum Verify:** Generate a hash of all `.cpp` and `.h` files excluding comments, or simply rely on the strict `git diff` above. The only lines changing should be the specific comment line containing the typo.

**Step 3: The Commit Strategy**
Once approved, stage all 40 files and create **one** commit.
*   **Command:** `git add <list of 40 files>` followed by `git commit`.
*   **Commit Message:**
    ```text
    docs: fix recurring 'LIcence' typo in license headers

    Corrects a consistent spelling error ('LIcence' -> 'License') found
    in the header comments of 40 core source files.

    - No functional code changes.
    - No logic modifications.
    - Verified via strict diff analysis.

    Closes #<IssueNumberYouCreated>
    ```
