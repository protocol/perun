### Proposal for Community Backport: Critical Security Fix for Legacy LTS Branch

**Subject:** Proposal to merge a non-breaking security fix for the [Project Name] LTS branch without imposing maintenance burden.

**Context & Alignment**
We acknowledge and respect the maintainers' current stance: the legacy LTS branch is end-of-life regarding active feature development and automated testing, and the strong preference is for all users to upgrade to the latest version. We are not proposing to revive this branch for general development, nor are we asking the team to resume regular testing cycles or provide ongoing support for it.

**The Issue**
A severe security vulnerability has been identified in the LTS branch allowing remote code execution (RCE) via a malformed header. While upgrading is the ideal long-term solution, a significant segment of the user base operates in constrained environments where immediate upgrades are physically impossible due to hardware dependencies. Leaving this branch unpatched exposes these users to critical risk.

**The Proposal**
We have developed a minimal, surgical patch that resolves the RCE vulnerability.
*   **Scope:** The fix is strictly limited to the header parsing logic.
*   **API Stability:** It introduces **zero changes** to the public API or ABI, ensuring binary compatibility for existing deployments.
*   **Maintenance Burden:** We request only a one-time review and merge. We do not expect the maintainers to backport future fixes or run CI on this branch.

**Community Benefit & Justification**
Merging this specific fix serves the broader community by:
1.  **Preventing Fragmentation:** It avoids forcing a large user base to fork the project independently to secure their systems, which would scatter expertise and slow down future security coordination.
2.  **Risk Mitigation:** It closes a known RCE vector for users who are temporarily stuck on legacy hardware, protecting the project's reputation even among those not running the latest version.
3.  **Zero Cost:** Since the patch requires no API changes and no new test infrastructure (we will provide our own verification evidence), the merge cost is limited to a single security review.

**Confidentiality & Verification**
While we cannot disclose specific client environment configurations due to confidentiality agreements, we can provide:
*   A detailed technical explanation of the vulnerability and the fix.
*   Reproduction steps using a generic, sanitized test case that any reviewer can run locally.
*   Evidence of our internal verification confirming the fix resolves the RCE without side effects.

**Request**
We ask for permission to submit this single PR against the LTS branch. If merged, we will assume full responsibility for any user support related to this specific patch, relieving the core team of any downstream obligation. This approach balances the project's desire to deprecate the old branch with the ethical necessity of preventing remote exploitation in the wild.
