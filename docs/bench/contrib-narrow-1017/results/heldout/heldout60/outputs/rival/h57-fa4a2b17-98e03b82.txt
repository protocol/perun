For a one-line documentation correction, do not check boxes that require actions you did not perform (like running benchmarks or security audits), as this violates the honesty principle required for open-source contributions. Instead, handle the template by explicitly marking non-applicable items with a clear justification directly in the PR description or next to the checkbox.

Write a brief note at the top of your PR body stating: "This is a documentation-only typo fix. The following mandatory checklist items are marked N/A as they do not apply to text changes: [list specific items]." Then, for each irrelevant checkbox, write "[N/A - Docs only]" or similar next to it. This approach signals to maintainers and bots that you have consciously evaluated the requirements rather than ignoring them. It demonstrates respect for the project's rigor while acknowledging the trivial scope of your change. Most maintainers prefer this transparency over false compliance, and automated bots typically look for human engagement with the template rather than blind checkbox ticking.

Note: If the project strictly enforces checkbox parsing via bots without allowing text explanations, you may need to open a preliminary issue asking for clarification, but explicit labeling is the standard best practice.
