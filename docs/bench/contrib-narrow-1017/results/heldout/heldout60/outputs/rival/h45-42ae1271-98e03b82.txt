## Summary
Fixes an issue where attachment uploads fail silently or return a generic error when filenames contain specific special characters (e.g., `&`, `#`, `%`). This appears to be caused by improper URL encoding of the `Content-Disposition` header, which triggers rejection by strict HTTP intermediaries and standard-compliant servers.

## What
- Sanitizes and correctly URL-encodes filenames in the `Content-Disposition` header before transmission.
- Adds regression tests covering filenames with RFC 5987 special characters.
- Updates error handling to provide a specific failure message rather than a generic timeout or 500 error.

## Why

This blocks file uploads for a significant subset of users operating in secured network environments.
