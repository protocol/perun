**Recommended Approach: Disclose Transparently in the PR Description, Not the Commit Message**

You should explicitly mention the AI assistance in your **Pull Request description**, but keep the **commit message** focused solely on the technical change. Do not hide the tool usage; transparency is the safest ethical path and protects your reputation if the code is ever analyzed later. However, frame the disclosure carefully to emphasize your ownership of the final result.

**Why this strategy works:**
1.  **Commit Messages are Permanent History:** They should describe *what* changed and *why*, not the drafting process. Cluttering them with tooling details dilutes the historical record of the bug fix.
2.  **PR Descriptions are for Context:** This is the appropriate place for process metadata. It allows you to control the narrative before a human reviews the code.
3.  **Shifts Focus to Verification:** By stating you "manually reviewed and tested every line," you signal that the AI was merely a draftsman, while you acted as the engineer responsible for correctness.

**Suggested PR Description Template:**

> **Summary**
> Fixes incorrect timezone offsets during daylight saving transitions in [Function/Module Name]. This resolves the issue where [brief specific symptom, e.g., dates shifted by one hour] affecting users in [affected regions].
>
> **Changes**
> - Corrected the offset calculation logic in `src/date-utils.js`.
> - Added three new test cases covering DST transition edges.
> - Verified all existing tests pass.
>
> **Development Note**
> The initial draft of this fix was generated with the assistance of an AI coding tool to accelerate the boilerplate implementation. **I have manually reviewed, refactored, and verified every line of code.** All test cases were written and validated by me to ensure correctness across edge cases. The final implementation represents my own work and judgment.

**How to Handle Potential Pushback:**
If a maintainer raises concerns, rely on the strength of your verification. Your argument is not "an AI wrote this," but "I used a tool to draft, but I engineered the solution." The existence of passing tests and your manual review proves the code stands on its own merits regardless of its origin. Most modern open-source projects care more about code quality and security than the specific text editor or assistant used to write it, provided the contributor takes full responsibility.

**Final Checklist Before Submitting:**
- Ensure your three new tests clearly demonstrate the fix for the DST bug.
- Double-check that no proprietary code or secrets from your local environment leaked into the diff.
- Submit the PR with the disclosure in the body, ready to discuss the technical merits if asked.
