# Activation Definition Evaluation Framework for AquaSmart

**Objective:** Determine which early user behavior best predicts six-month retention to guide the onboarding flow redesign.

### 1. Candidate Activation Events
We will test three distinct definitions of "activation" against your six-month retention data. Each represents a different hypothesis about where users derive value:

*   **Event A (Setup Complete):** User finishes the Wi-Fi connection and device setup wizard.
    *   *Hypothesis:* Ease of installation is the primary barrier; getting the device online is the core value.
*   **Event B (First Manual Water):** User triggers a watering cycle manually via the app before any automation exists.
    *   *Hypothesis:* Users need to trust the hardware works (see water flow) before trusting it with automation.
*   **Event C (First Custom Auto-Schedule):** User creates and saves a watering plan utilizing local weather data.
    *   *Hypothesis:* True value is only realized when the "smart" promise (weather adaptation) is active; this is your current assumption.

### 2. Evaluation Method: Cohort Retention Analysis
For each definition (A, B, and C), perform the following analysis using your existing data from May 10th to present:

1.  **Segment Users:** Create three cohorts based on whether a user completed Event A, B, or C within their first 14 days. Note that these cohorts will overlap (e.g., a user who did C also did A and likely B).
2.  **Calculate Retention Curves:** For each cohort, plot the percentage of users still actively using the device (e.g., running any cycle) at Month 1, Month 3, and Month 6.
3.  **Compute the "Activation Lift":** Compare the Month 6 retention rate of users who completed the event vs. those who did not.
    *   *Formula:* `(Retention Rate [Completed Event] - Retention Rate [Did Not Complete])`
4.  **Identify the Strongest Predictor:** The event with the highest positive correlation to Month 6 retention is your true North Star activation event.

### 3. Specific Test: The "Manual First" Hypothesis
To address your question on manual vs. automatic paths:
*   **Cohort X:** Users who performed a Manual Water (Event B) *before* creating an Auto-Schedule (Event C).
*   **Cohort Y:** Users who created an Auto-Schedule (Event C) *without* prior manual watering.
*   **Comparison:** Compare the Month 6 retention rates between Cohort X and Cohort Y. If Cohort X retains significantly higher, the onboarding flow should explicitly encourage a manual test run before pushing automation.

### 4. Decision Matrix for Onboarding Redesign
Based on the results, apply this logic to the redesign:

| If this Event predicts retention best | Then the Onboarding Flow must... |
| :--- | :--- |
| **Setup Complete (A)** | Remove all friction post-Wi-Fi. Defer weather features to later. Celebrate "Online" status immediately. |
| **First Manual Water (B)** | Add a mandatory "Test Run" step in the wizard. Block automation setup until water is seen flowing. |
| **Custom Auto-Schedule (C)** | Guide users directly to weather settings. Pre-fill defaults to make the first schedule creation instant. |
