# GlobeChat Q2 Strategy Evaluation Rubric

**Objective:** Determine whether Q2 investment should prioritize further stability engineering or user re-engagement campaigns based on post-fix behavior (Feb 20 – Mar 5).

### 1. The North Star: Core Action Retention (Not Just DAU)
*Definition:* The percentage of users who return weekly to perform GlobeChat's core value action (e.g., sending a message, joining a channel), not just opening the app.
*Why:* DAU is a vanity metric here; it includes users opening and crashing or leaving immediately. Stability only matters if it enables the core action.
*Success Threshold:* A positive trend in **Week-2 Retention of the Core Action** compared to the pre-Feb 20 baseline. If this is flat while crash rates drop, stability is no longer the bottleneck.

### 2. Diagnostic Segments (Answering the "Who" and "Why")
Do not aggregate data. Evaluate these specific cuts to decide the pivot:

| Segment | Metric to Measure | Decision Rule (Action) |
| :--- | :--- | :--- |
| **High-Value Users** (Top 20% by session count) | Crash rate vs. Global average (2.1%) | If their crash rate > 3%, **Invest in Stability**. If ≤ 2.1%, stability is not the blocker for power users. |
| **Churned Users** (Active pre-Feb 20, inactive post) | Re-engagement rate after push/email | If < 5% return despite stability, **Pivot to Re-engagement** (trust/content issue). If > 15%, the fix is working; wait for organic return. |
| **New Installs** (Post-Feb 20) | Activation Rate (Core Action within 24h) | If < Baseline, the onboarding flow is broken (not crashes). **Fix Product/UX**. If ≥ Baseline, acquisition is healthy. |

### 3. The Trust Hypothesis Test
*Question:* Have users lost trust, or do they simply not see value?
*Method:* Compare **Session Duration** and **Depth** (screens per session) for returning users vs. new users.
*Interpretation:*
*   If returning users have flat duration but new users have high duration: **Trust/Ergonomics issue** for legacy users. Launch a "We Fixed It" re-engagement campaign highlighting specific stability wins.
*   If both groups have flat duration: **Value issue**. The app is stable but boring. Do not spend more on stability; invest in feature discovery or content.

### 4. Investment Stop/Tripwire Criteria
*   **Stop Stability Investment If:** Core Action Retention for High-Value Users matches pre-crash baselines AND their specific crash rate is ≤ global average. Further engineering yields diminishing returns.
*   **Continue Stability Investment If:** High-Value User crash rate remains > 3% OR Core Action Retention correlates strongly (r > 0.7) with the remaining 2.1% crash events (verify via event logs).
*   **Pivot to Re-engagement If:** Stability metrics are green across segments, but DAU/Retention remains flat. The bottleneck is psychological (trust) or value-based, not technical.

### Recommended This-Week Steps
1.  **Query:** Run a cohort analysis comparing "Core Action Retention" for users active before Feb 20 vs. after, segmented by "High-Value" status.
2.  **Instrument:** Ensure the "Core Action" event is distinct from "App Open" in your analytics; if not, mark current DAU data as `UNVERIFIED` for value assessment.
3.  **Decision:** Present the VP and Head of Growth with the High-Value User crash rate. If it is low, approve the re-engagement budget immediately. If high, allocate 2 weeks to targeted fixes before marketing spend.

*Note: Do not compare these rates to industry benchmarks; use only GlobeChat's pre-Feb 20 baseline as the truth source. Any metric without a corresponding event ID in your tracker is `UNVERIFIED`.*
