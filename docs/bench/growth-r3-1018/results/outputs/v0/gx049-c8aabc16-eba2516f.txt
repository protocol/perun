### Diagnostic Plan: Custom Workflow Adoption Drop

**Objective:** Differentiate between **discoverability failure** (users cannot find the entry point) and **usability friction** (users find it but abandon the configuration) to inform the December 1st decision.

**1. Define the Funnel & Events**
Instrument or query the following four sequential events from your interaction logs for the period of Nov 5–26, segmented by "Existing User":
*   **E1 (Entry View):** User lands on the main dashboard or project view (the new navigation root).
*   **E2 (Attempt):** User clicks the specific UI element intended to open the "Custom Workflow" creator (e.g., "+ New Workflow" button or menu item).
*   **E3 (Config Start):** The configuration modal/screen successfully loads.
*   **E4 (Config Complete):** User saves a new custom workflow.

**2. Analyze the Drop-Off Points**
Calculate the conversion rates between these steps and compare them to the pre-redesign baseline (Oct 1–31):

*   **Hypothesis A: Discoverability Issue**
    *   *Signal:* A massive drop in **E1 → E2**. If the click-through rate from the dashboard to the "Attempt" event has collapsed (e.g., from 10% to 1%), users are not seeing the button.
    *   *Verification:* Check heatmaps or click coordinates on E1. Are users clicking where the button *used* to be, or ignoring the new location entirely?
    *   *Diagnosis:* The feature is buried or the visual affordance is weak.

*   **Hypothesis B: Usability Friction**
    *   *Signal:* **E1 → E2** remains stable (or drops slightly), but **E2 → E4** has crashed. Specifically, look for a spike in **E3 → Exit** (users opening the config screen and closing it without saving) or an increase in time-to-complete for E4.
    *   *Verification:* Analyze error logs or "cancel" clicks within the configuration flow.
    *   *Diagnosis:* Users find the feature, but the new interface makes the actual work harder.

**3. Immediate Action Plan (This Week)**
*   **Query:** Run the funnel analysis above immediately. Do not wait for more data; the three-week sample is sufficient for a directional verdict.
*   **Segment:** Split the data by user tenure. Did power users (who previously made 5+ workflows/month) drop off faster than casual users? This isolates whether the change broke muscle memory (discoverability) or actual utility (usability).
*   **Decision Matrix:**
    *   If **E1→E2** is the primary leak: Prioritize **UI Revert/Adjustment**. Move the entry point back to a prominent location or increase its visual weight. An guidance campaign will fail if users never trigger the first step.
    *   If **E2→E4** is the primary leak: Prioritize **In-App Guidance**. The path is visible, but the process is confusing. Deploy tooltips or a simplified wizard for the configuration steps.
    *   If both are leaking: Revert the navigation change immediately (high risk) while drafting guidance for the complex steps.

**4. Guardrail Metric**
Monitor **Support Ticket Volume** tagged "Workflow" or "Navigation." A spike here correlating with the drop confirms user frustration and validates the quantitative findings.

**Deliverable to Head of Design:** A single chart showing the pre/post funnel with the specific step where the drop-off exceeds 50% of the total loss. This dictates the fix: move the button (discoverability) or fix the form (usability).

*Note: Ensure user identifiers in these logs are pseudonymous for analysis; route any raw PII handling to privacy compliance protocols. Do not invent industry benchmarks for "acceptable" drop-off; compare strictly to TaskFlow's October baseline.*
