### Activation Evaluation Framework for AquaSmart

**1. Define Candidate Activation Events**
Do not assume a single definition. Test these three distinct events against your six-month retention data to see which correlates strongest with long-term usage:
*   **Event A (Setup Complete):** User finishes the Wi-Fi setup wizard. (Hypothesis: Low barrier, but likely weak predictor).
*   **Event B (First Automated Cycle):** User runs any automated watering cycle within 14 days. (Hypothesis: Current baseline, measures basic functionality).
*   **Event C (Weather-Based Plan):** User schedules a custom plan utilizing local weather data. (Hypothesis: Your assumed "true" activation; measures core value delivery).
*   **Event D (Manual First):** User manually waters once, *then* automates within 14 days. (Hypothesis: Addresses your question on whether a "hands-on" start drives higher retention than straight automation).

**2. The Analysis Method (Retention Cohorts)**
Run a cohort analysis for each event definition using your existing data:
*   **Group users** by whether they completed the specific event within the first 14 days of device connection.
*   **Measure** the retention rate (e.g., % of users still actively watering) at Month 1, Month 3, and Month 6 for each group.
*   **Compare** the retention curves. The correct activation metric is the one where the gap between "Activated" and "Not Activated" users is widest and most statistically significant over time. If Event C users retain 40% better than non-Event C users, but Event A users show no difference, Event C is your North Star input.

**3. Addressing the "Manual First" Question**
Create a specific split cohort for users who performed a manual water event before their first automated cycle versus those who did not. If the "Manual First" cohort shows significantly higher 6-month retention, your onboarding redesign must explicitly encourage a manual test run before pushing automation. If retention is identical or lower, remove friction and push straight to weather-based scheduling.

**4. Decision Criteria for Onboarding Redesign**
*   **If Event C (Weather Plan) wins:** Redesign the wizard to make creating a weather-based plan the mandatory final step before "completion." Do not let users exit setup without it.
*   **If Event D (Manual First) wins:** Insert a guided "Test Water" step in the flow before offering automation settings.
*   **If Event B (Any Auto) wins:** Simplify the weather data integration; it may be too complex for initial activation. Focus on getting *any* schedule running.

2.  Plot the retention curves side-by-side; identify which event creates the largest divergence in long-term behavior.
3.  Draft the new onboarding flow wireframe that forces the winning event to occur before the user leaves the app.

*Note: Do not invent retention benchmarks; use only your historical data to determine the correlation. If the data for "Manual First" is not currently tracked, label that finding UNVERIFIED and instrument it immediately for future shipments.*
