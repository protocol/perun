# ShopViet Mobile Migration Measurement Plan (First 30 Days)

## Executive Summary
To validate the strategic pivot from desktop-web to mobile-app, we will track three core dimensions: **Migration Volume** (are users downloading?), **Migration Quality** (are the right users downloading?), and **Early Retention** (are they staying?). Success in the first 30 days is defined not just by download count, but by identifying the specific web behaviors that predict high-value app retention.

## 1. Core Success Metrics (The "North Stars")

| Metric | Definition | 30-Day Target Logic |
| :--- | :--- | :--- |
| **Migration Rate** | % of active web users who install & open the app. | Baseline for the 40% six-month goal. |
| **App Day-7 Retention** | % of installers who return to the app 7 days after install. | Early proxy for long-term LTV lift. |
| **Incremental LTV Signal** | Average Order Value (AOV) of app users vs. web-only users in first 30 days. | Validates the "30% higher LTV" hypothesis early. |

## 2. Predictive Behavior Tracking (The "Who")
To determine *which* web behaviors predict successful migration, we must tag web sessions with specific events prior to download. We will correlate these pre-install web actions with post-install retention.

**Track these specific web behaviors for all logged-in users:**
*   **Mobile Web Usage:** Frequency of visits via mobile browser (vs. desktop). *Hypothesis: Mobile web users are highest propensity.*
*   **Push-Like Actions:** Users who explicitly opt-in to email/SMS alerts on web. *Hypothesis: Users comfortable with interruptions convert better to push.*
*   **High-Frequency Purchasers:** Users with >2 purchases in the last 90 days. *Hypothesis: Habitual buyers seek frictionless app experiences.*
*   **Feature Seekers:** Users who visit "Order Tracking" or "Wishlist" pages frequently. *Hypothesis: Utility-driven users value app convenience.*

**Analysis Method:** Create a cohort report comparing the **Day-7 Retention** of app installers against their pre-install web behavior tags. The cohort with the highest retention rate identifies your "Ideal Migrator."

## 3. Implementation Requirements
*   **User Identity Resolution:** Ensure your analytics platform (e.g., GA4, Mixpanel) links `web_user_id` and `app_user_id` to the same customer profile. Without this, you cannot track the journey from web behavior to app retention.
*   **Attribution Window:** Set a 30-day lookback window to attribute the app install to the preceding web behaviors.
*   **Event Naming:** Standardize events across platforms (e.g., `purchase_completed` must be identical on web and app).

## 4. Reporting Cadence for Board Review
*   **Weekly:** Migration Rate and Install Volume (by traffic source).
*   **Bi-Weekly:** Day-1 and Day-7 Retention rates.
*   **Day 30 (Board Deck):**
    *   **Migration Funnel:** Web Active → Clicked Download → Installed → Registered → Purchased.
    *   **Predictive Matrix:** A heatmap showing which web behaviors correlate highest with Day-7 retention.
    *   **Early LTV Delta:** Comparison of 30-day spend between "App Users" and "Web-Only Users."

## 5. Critical Risks to Monitor
*   **Cannibalization:** Ensure app sales are not simply shifting web sales without net growth. Track *total* platform revenue, not just app revenue.
*   **Friction Points:** Monitor drop-off at the "Install → Open → Register" stage. High drop-off here indicates technical onboarding issues, not lack of interest.

**Note:** This plan requires immediate implementation of cross-platform user ID linking before launch; otherwise, behavioral correlation will be impossible.
**Note:** Do not optimize for total downloads alone; a high volume of low-retention installs will invalidate the LTV hypothesis and waste marketing spend.
