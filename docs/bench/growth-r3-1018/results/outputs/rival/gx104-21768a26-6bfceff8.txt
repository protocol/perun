### Experimental Approach: Simplified A/B Test with Manual Oversight

Given your constraints (800 daily visitors, 3% baseline, one developer for 4 hours/week), a standard automated A/B test is feasible but requires strict scope control. You can detect a **10% relative lift** (from 3.0% to 3.3%) with statistical significance, but it will take approximately **3–4 weeks** to reach the required sample size.

**The Plan:**
1.  **Test Design:** Run a simple **A/B split** on the donation button copy or layout (one variable only). Use a lightweight client-side tool (e.g., PostHog or Google Optimize alternative) that requires minimal code injection (one snippet David installs once).
2.  **Duration:** Run for **28 days** to capture full weekly cycles (donation behavior often varies by weekday/weekend).
3.  **Sample Size Needed:** ~12,000 visitors per variant (24,000 total). At 800 visitors/day, you will hit this in ~30 days.
4.  **Engineering Effort:**
    *   **Week 1:** David installs the testing snippet and configures the variant (2 hours). QA and launch (1 hour).
    *   **Weeks 2–4:** No engineering work required unless technical bugs arise. David spends 1 hour/week only to verify the tracking snippet is still firing.
    *   **Week 5:** Export data for analysis (1 hour).

**Manual Data Collection (If Automation Fails):**
If the testing tool cannot auto-track conversions, you must manually log these daily in a spreadsheet:
*   **Date**
*   **Variant Name** (A or B)
*   **Total Visitors** (per variant)
*   **Completed Donations** (per variant)
*   **Total Donation Value** (per variant, to check for average gift changes)

**Framing Limitations for the Board:**
Present this as a **"Low-Fidelity Validation"** rather than a definitive optimization engine.
*   **Confidence Interval:** Explain that while the result will be statistically significant, the margin of error is wider than enterprise-grade tests. A "win" might be a 3.2% lift instead of exactly 3.3%.
*   **Risk of Noise:** With limited traffic, external factors (e.g., a news story about water conservation) could skew one week's data. You are mitigating this by running a full 4-week cycle.
*   **The Ask:** Frame the budget request not as "we need more devs to run tests," but as "we need resources to automate this manual oversight so we can run 4x more tests per year, compounding our donation revenue."

**Recommendation:** Proceed with the test. The engineering burden is front-loaded (Week 1), leaving David free for other tasks. The data gathered will be robust enough to justify further investment.

*Note: Do not peek at results before Day 28; early stopping will invalidate the statistical significance. Ensure your donation processor (e.g., Stripe, PayPal) correctly passes transaction data back to your analytics tool.*
