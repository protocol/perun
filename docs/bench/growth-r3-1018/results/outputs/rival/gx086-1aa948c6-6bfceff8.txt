**Tracking Prioritization Plan for FusionFuture Simulation Run**

**Recommendation:** Do not track file upload volume as your primary metric. It is a lagging indicator of storage usage, not collaboration intensity. Instead, implement a "Research Coordination Index" based on three specific, low-overhead data points that directly correlate with scientific progress and team synchronization.

**1. Primary Metric: "Data Reference Events" (The Bridge Between Chat and Files)**
*   **What to track:** A specific trigger when a user pastes a file link or version ID into a chat thread, *not* the chat text itself.
*   **Why:** This solves your pilot finding. Researchers discuss data without uploading new files because they are referencing existing datasets. Counting these references captures the *intellectual engagement* with data without storing heavy chat logs or requiring new uploads.
*   **Infrastructure Impact:** Minimal. You are only logging a timestamp and a file ID reference, not message content.

**2. Secondary Metric: "Version Resolution Rate"**
*   **What to track:** The time delta between a file being checked out/locked for editing and the subsequent check-in of a new version.
*   **Why:** In nuclear research, "version control checks" indicate active refinement. A short delta implies rapid iteration; a long delta with no check-in implies a bottleneck or stalled experiment. This measures *velocity* rather than just volume.
*   **Infrastructure Impact:** Low. Requires logging only two state-change timestamps per file session.

**3. Guardrail Metric: "Synchronous Handshake Count"**
*   **What to track:** Clicks on meeting scheduling links that occur within 1 hour of a "Data Reference Event."
*   **Why:** This validates if asynchronous discussion (chat references) is successfully converting into synchronous coordination (meetings). High references with zero handshakes indicate confusion or unresolved data issues.
*   **Infrastructure Impact:** Negligible. Simple click-through tracking on existing calendar links.

**Implementation Strategy for Dr. Aris:**
*   **Exclude:** Do not log full comment threads or general chat activity. The storage cost outweighs the signal, and privacy risks increase with text logging.
*   **Exclude:** Do not track general page views or login frequency. These are vanity metrics that do not prove scientific coordination.
*   **Dashboard View:** Present Dr. Aris with a daily trend line of "Data Reference Events" overlaid with "Version Resolution Rate." If references spike but resolution slows, the team is discussing data but not progressing—signaling a need for intervention before the September 12 run.

This approach respects your storage limits by logging only structured events (IDs and timestamps) while providing a true proxy for research intensity: the frequency with which data is actively discussed and iterated upon.
