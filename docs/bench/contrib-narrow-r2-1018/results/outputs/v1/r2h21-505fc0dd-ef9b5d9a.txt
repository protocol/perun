### Generalized Proposal Draft

**Problem Statement**
The current test suite relies on fixed time delays to assert message delivery completion. This approach assumes a deterministic network latency that does not exist in real-world environments. Consequently, tests fail intermittently when system load or network conditions cause delivery to exceed the hardcoded window, leading to false negatives in continuous integration.

**Root Cause**
The test logic couples verification to a specific wall-clock duration rather than the actual state of the system. This creates a race condition where the test assertion executes before the asynchronous operation completes under load.

**Proposed Solution**
Replace fixed `sleep` or timeout assertions with event-driven synchronization primitives. The test should block until a specific condition is met (e.g., message received, callback invoked) or a generous, fail-safe timeout is reached. This decouples test stability from environmental latency.

**Synthetic Reproduction Strategy**
To demonstrate the flaw without using internal data:
1.  Create a local test harness that artificially injects variable latency into the message broker mock.
2.  Configure the mock to delay responses by a random amount between 0ms and 200ms.
3.  Show that the original test fails consistently when the injected delay exceeds the hardcoded threshold.
4.  Show that the proposed event-driven test passes regardless of the injected delay.

**Risk Assessment**
The change is scoped strictly to test infrastructure. It introduces no runtime overhead to the production client and reduces maintenance costs by eliminating flaky failures.
