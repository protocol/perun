**Immediate Action: Report via the Private Security Channel**

The safest and most responsible initial step is to send a confidential report to the security email address listed in the library's readme. Do not open a public issue yet.

When cryptographic weaknesses are involved, the potential impact on users outweighs the uncertainty of the severity classification. If the flaw is critical, a public report exposes all users to immediate exploitation before a patch exists. If the flaw is low severity, the maintainers can simply reclassify it and ask you to open a public issue later; this minor delay is a negligible cost compared to the risk of premature disclosure.

**How to Report Without Revealing Confidential Details**

You can fulfill your duty to disclose without violating Acme Security's confidentiality policies by focusing strictly on the observable behavior of the library, not your internal audit process.

1.  **Compose the Email:** Address it to the security contact found in the readme.
2.  **Describe the Symptom, Not the Audit:** State that during routine testing, you observed that the `SecureHash` crate produces cryptographically weak output when configured with a 128-bit key in the specific mode (name the mode if public, otherwise describe the configuration parameters).
3.  **Omit Internal Context:** Do not mention "Acme Security," your specific audit tools, the timeline of your discovery, or the specific internal systems where this was found. These are irrelevant to the fix.
4.  **Provide a Minimal Repro:** Create a small, standalone Rust snippet using synthetic data (e.g., `let key = [0u8; 16];`) that demonstrates the weak output. This proves the bug exists in the library itself, independent of your environment.
5.  **Request Triage:** Explicitly ask the maintainers to evaluate the severity. Phrase it as: "We are unsure if this meets your threshold for a security advisory or a standard bug fix. Please advise on the preferred disclosure timeline."

**Fallback Plan**

If the maintainers do not respond within 7–10 days, send one polite follow-up. If there is still no response after another week, you may then consider opening a public issue stating only that you attempted private contact on [Date] regarding a potential weakness in 128-bit key handling, without revealing the technical specifics until they acknowledge receipt.

**Note:** Never guess the severity yourself; let the library authors, who know the intended security guarantees, make that call.
**Note:** Ensure your reproduction code uses only invented values to avoid accidental data leakage.
