## Summary
Fixes a `NullPointerException` in the HTML parser when encountering dynamic class names in modern tracking page layouts. This update replaces a fragile static selector with a robust attribute-based strategy to ensure stability against upstream site structure changes.

## What
- Refactored the selector logic in `src/parser/TrackingPage.java` (around line 402) to target stable DOM attributes instead of volatile class names.
- Added a regression test case simulating dynamic class name injection to prevent future breakage.
- Updated internal documentation to reflect the new selector strategy.

## Why
Recent updates to several major carrier tracking pages have introduced randomized or dynamic CSS class names, causing the previous rigid selector to fail and resulting in null pointer exceptions during data extraction. This change ensures the library remains resilient to such structural variations without requiring constant maintenance for every minor site update.
