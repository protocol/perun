### Draft Issue: Documentation Generation Source Mismatch

**Title:** Docs: API reference parameter typos persist despite code comments being correct (Generation source mismatch?)

**Summary**
I identified several parameter name typos in the auto-generated API reference for the Aperture Science Converter. While the `README` states docs are generated from code comments, the live documentation contains errors (e.g., `recepticle_id` vs `receptacle_id`) that do not exist in the current source comments. I suspect the generation script is pulling from a cached file, an outdated template, or a disconnected metadata source, but I cannot locate the specific template responsible after a full codebase search.

2.  **Searched Generation Logic:** Grep-searched the entire repository for the misspelled terms and the generation script configuration; no matches found in current templates or config files.
3.  **Local Build Attempt:** Ran the local documentation build script to reproduce the error.
    *   *Result:* The build completed, but I am unsure if my local environment influenced the output (see "Environment Note" below).
4.  **Hypothesis:** The CI pipeline may be using a pinned, outdated version of a documentation dependency, or there is a hidden cache/file in the build process not included in the source tree that contains these legacy typos.
