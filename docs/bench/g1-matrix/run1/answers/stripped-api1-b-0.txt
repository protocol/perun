**notes.py:12 – API1 Broken Object Level Authorization (High).** `read_note` authenticates the caller via `current_user` but never uses `user`. The query `SELECT ... FROM notes WHERE id = ?` filters only by `note_id`, not by `owner_id`. Any logged-in user can request `/notes/1`, `/notes/2`, and so on, and read other users' notes, including the body. The sibling `list_notes` correctly scopes by `owner_id = user.id`, which shows the intended ownership model and that it was missed here. Integer sequential IDs make enumeration trivial.

The response only includes `id` and `title`, so the impact is limited. This is a hardening point rather than a clear defect, and I'm not reporting it as a finding at the confidence threshold.
