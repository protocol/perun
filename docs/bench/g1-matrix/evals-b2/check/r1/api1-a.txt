I found three issues in the files, one of them minor.

1. **BOLA on the receipt endpoint (`invoices.js`, line 37).** `GET /:id/receipt` only checks that the invoice exists and never calls `canAccess`. Any authenticated user can read another user's invoice total, note and status. For example, `tok-a` (u1) can fetch invoice 2, which belongs to u2. The sibling routes `GET /:id` and `PUT /:id` do enforce ownership.

2. **Broken authentication (`auth.js`, lines 1 and 5).**
   - Line 5: `sessions` is a plain object, so `sessions[token]` also resolves inherited properties. A header such as `Authorization: constructor`, `toString` or `__proto__` returns a truthy value, and `requireUser` accepts it as a logged-in user. That user's `id` is a function or object, so it matches no invoice owner. It still passes authentication on every route, including the invoice list. A `Map` or `Object.create(null)` with an own-property check would avoid this.
   - Line 1: sessions are hardcoded, short, guessable tokens (`tok-a`, `tok-b`) with no expiry, rotation or revocation.

3. **Minor, API8 (`invoices.js`, line 29).** `express.json` only populates `req.body` for JSON requests. A `PUT` with another content type or no body leaves `req.body` undefined, so `req.body.note` throws a TypeError. This produces an unhandled 500, and the default Express handler can leak a stack trace when `NODE_ENV` isn't `production`.
