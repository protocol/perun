### Outcome-metric audit (2026-10-19)

Rule: a Perun-versus-rival comparison is judged on a user-felt outcome metric plus guardrails, never on a proxy alone. Each comparison in this document is classified below. Outcome means the metric counts the thing the user wants (bugs found, tickets merged, leaks caught, install time); Proxy means a model judge's preference, a stage metric, a count or a static estimate. A Proxy row can state a preference or a count, but it cannot support a claim of better or worse for the user. `scripts/check_rivals_outcome.py` (run from `scripts/ci-tests.d/rivals-outcome-audit.sh`) fails if a row of the first table has no row here, or if a row here has an empty or inconsistent outcome field.

### Provenance caveat

So the code that ran cannot be shown to equal the preregistered code. The verdicts are unchanged, but their preregistration cannot be verified. Rows, claims and headings that cite these benches are marked (provenance unverified). `scripts/bench_check.py` does not re-hash the files of a bench already on `main`, so it does not flag these mismatches.
