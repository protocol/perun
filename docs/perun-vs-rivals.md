### Provenance caveat

For ten benches cited here, an in-directory file listed in that bench's `SHA256-frozen.txt` fails the hash check, and the audit found its bytes match no commit: `bizops-e-confirm-1018`, `bizops-sup-1018`, `comms-quality-1016`, `comms-r4-1017`, `delivery-r1-1017`, `delivery-sup-1018`, `idea-critic-rep-1018`, `idea-critic-v2-1016`, `pos-1016` and `safety-c300-1018`. In three of them (`delivery-r1-1017`, `idea-critic-rep-1018`, `safety-c300-1018`) the list names the same file more than once and only its last hash matches a commit, so the list was amended after the freeze. So the code that ran cannot be shown to equal the preregistered code. The verdicts are unchanged, but their preregistration cannot be verified. Rows, claims and headings that cite these benches are marked (provenance unverified). `scripts/bench_check.py` does not re-hash the files of a bench already on `main`, so it does not flag these mismatches.

## 4. What Perun has that the rivals do not (as far as the pages we read show)

- **A published paired benchmark with intervals and stated limits.** No rival README we read showed a comparable head-to-head. This is absence of evidence in the pages we read, not proof.
- **Gates for multi-agent delivery.** Per-lane budget gate, exact-SHA receipts, merge-train scripts, independent QA and security roles, and human approval on push, merge and deploy. The agent-teams docs describe none of these and admit that task status lags and that same-file edits overwrite.

- **A pre-owner attack with a verdict** (`HOLD`, `REVISE` or `PASS_TO_USER`). The brainstorming skills we read are generative, not adversarial.

## What was not measured

- Judge independence: every skill and review comparison above except those marked H1g used a judge from the same vendor family as the generator. H1g re-scored the committed rubric-free pairs and the H7 and H7b review runs with one different-vendor judge and one tiebreak; the 2026-10-15 rubric runs, H2 to H6, positioning, contribution and business-ops were not re-judged cross-vendor, the generators stay same-vendor, and no judge was calibrated against human labels.
- Destructive guard: 32-string corpus; no real-agent transcripts, and residual bypasses are known.
- Vacuous-test detection: one 40-test corpus; the static pass was measured on one 20-test held-out set; `mutation_changed.py` was measured on one 40-test Python-only held-out set (20 vacuous, 20 genuine), with JavaScript unmeasured.
- Install: no rival installer was run; the 1.583.0 uninstall, backup and doctor results are release-check claims, not part of the 1.582.0 bench tables; only the Codex native install was run on a real host; the other 18 native hosts are docs-validated or file-placement tested only.
- Merge train: one small fixture and one seed; no rival merge queue was run; no real forge, branch protection or CI timing.
- Delivery on multi-lane work: the fixtures were small, so coordination across lanes and budget gates were not tested.
- Sections 3 and 4 compare documented features only.
- Bundle token counts are static estimates, not API usage. No rival bundle was executed.
- Star counts are single-source page reads and are not quality evidence.
