### Fixed
- `vendor_drift.py` no longer reports a clean install as drift. A canonical file whose first line says "(install placeholder)" is compared as `docs/<same name>` under the canonical source root, the file `install.sh` copies over it. When that docs file is missing, the stub itself is the reference, so an installed full copy reads as drift (fail closed). Before, the check `update-installed.sh` runs after an update flagged the two placeholder reference files on every clean install.
- A version bump of an unedited install no longer leaves a skill backup. `install.sh` now also drops the fresh backup when it equals what the marker says the previous install wrote (read before the new install rewrites the marker), next to the existing "identical to the fresh copy" rule. Only bytecode under `__pycache__` is ignored in that comparison, like `hash_dir`. An edited or extended copy, a pre-Perun copy (no marker entry), a backup holding any other file under `__pycache__` or any entry the previous install did not write (an empty directory, a FIFO), a symlink anywhere in it, and an unreadable marker all keep the backup. Deletion still goes through the existing per-file walk, never a shell `rm` on a computed path.
- Slash commands and `--with-gates` outputs no longer pile up `.new` copies. `write_gate_file` writes nothing when the destination, or an existing `.new` / `.new-N` next to it, already holds the shipped file, so an identical re-run no longer adds `.new-1`, `.new-2` and so on. A command that install wrote and nobody edited (its sha256 still matches the marker) is refreshed in place on a version bump and re-recorded, so uninstall still removes it. Install deletes no file it did not create in that run, so a `.new` / `.new-N` already next to it stays. Only a regular file named exactly `.new` or `.new-N` counts as already holding the shipped file; a symlink or a lookalike name never does. An edited command, a pre-Perun file and any `.new` that differs from the destination are unchanged: the file is never touched and a new `.new` is written. `--with-gates` outputs are not recorded in the marker, so they are never refreshed in place: an unedited one still gets a `.new` when its shipped template changes.
- `scripts/test_install_update_hygiene.py` (registered in `scripts/ci-tests.d/install-update-hygiene.sh`) covers all three on a fictional release source in a scratch directory with a scratch `HOME`: consecutive version bumps add no backup and no `.new`, while an edited skill, a pre-Perun copy, an edited command, a lookalike `.new-<text>` name, a symlinked `.new`, an empty directory in a backup, a pre-existing `.new` of any kind and a differing `.new` are all kept. The existing `scripts/test_install_commands.py::test_existing_file_kept_new_written_and_uninstall_keeps_user_file` pinned the old behavior of a second identical `review.md.new-1` and now expects a single `review.md.new`.
