### Added
- Committed personal-data check. New built-in `committed_personal_data.py` (stdlib only) counts the distinct email-shaped strings in every tracked file, plain binary data (sqlite, pickles) included, and reports a file with 10 or more as one `email-addresses` row: path and count only, never an address, a domain or a line. gitleaks, trufflehog and semgrep look for secrets, so a committed export of real people's addresses passed all of them clean. Not counted: the reserved example and test names (example.com, .net and .org with their subdomains, `.test`, `.example`, `.invalid`, `.localhost`), noreply forms, the ssh account `git@` of git remotes (`git@host:org/repo.git`, `ssh://git@host/org/repo`) and image asset-scale names (`icon@2x.png`, `icon@1.5x.png`, `icon@2x-dark.png`, for png, jpg, jpeg, gif, webp, avif, svg, pdf, ico, bmp, tif, tiff, heic, heif and apng). `--include-reserved` counts them so tests can use fictional example.com fixtures. Flags: `--threshold N` and `--repo-threshold N` (each 1 to 100000), `--strict` (exit 1 when a file or the repository total is flagged; the default is advisory, exit 0), `--stdin` (scan the listed paths instead of every tracked file), `--max-bytes N` (1 to 1 GiB, default 32 MiB; a larger file is scanned over its first bytes and a not-checked row says so). It exits 2 when `git ls-files` fails or a flag is out of range, never a silent pass and never a traceback.
- Addresses spread thin are summed. A leak of one address per file never reaches the per-file threshold, so the distinct addresses of all the scanned files that stay below it are also counted together, and a total of 50 or more (`--repo-threshold`) gives one `email-addresses` row with the path `.` ("69 distinct email addresses across 75 file(s) ..."). A file already reported is left out of the total, an address repeated across files counts once, and in diff mode only the changed files are counted. `--threshold 1` lists the files behind the row. The default 50 is five times the file threshold. The audit behind this check found about 850 addresses; this repository holds 69 distinct ones in 75 files that each stay below 10 (60 of them under docs/bench), so its own `--full` run shows the row as a lead. A default of 100 would stay quiet here but would miss a spread of 50 to 99 addresses.
- Compressed and columnar files do not pass silently, for exactly these formats. A file that stays under the threshold gets a `not-checked` row (path and format, never a value) when it is parquet (`PAR1` at the start and the end, or `PARE` at both for an encrypted footer), an Arrow IPC file (`ARROW1` at both ends), ORC (`ORC` at the start and before the last byte), zip (also docx, xlsx, jar), gzip, zstd, xz, 7z, lz4 frame, bzip2, Avro, PDF, or a zlib stream (a valid header whose data decodes). Parquet, Arrow and ORC need their footer, so a text file that merely begins with "PAR1" or "ORC" gets no row, and neither does a file too short to hold both magics (a bare "PAR1") or text whose first two bytes pass the zlib header check by chance. Every other format (brotli, snappy, rar, Arrow IPC streams, raw deflate, ORC 0.11 files, which lack the end magic) is read as plain bytes and can pass clean, as can UTF-16 text and obfuscated forms (`[at]`, `%40`); names are not detected. A file at or above the threshold is reported as usual, as a lower bound.
- Wired into `review_checks.sh` as the built-in `committed-data` step, right after `invisible-chars`: it scans the changed files in diff mode and every tracked file under `--full`, skips the paths every step skips (node_modules, vendor, build dirs) plus third_party/, Pods/, bower_components/ and *.min.js, as `invisible-chars` does, and is listed under "analyzers ran". A missing script gives one not-checked row. Rows are not tagged `likely-fixture`, because a real address in a fixture is still a leak. The `method-situational.md` analyzer list names the step with its `.` and `not-checked` rows.
- Threshold 10, measured rather than guessed: 5 x 8 MiB of seeded random bytes held 2 email-shaped strings (0.05 per MB); across this repository's 93,711 tracked files at this commit the most distinct non-reserved addresses in one file is 6 (75 files hold any, none is a recognised container), so 10 flags nothing here while a threshold of 5 would flag 3 files (two bench outputs and this check's own unit test); a whole-tree run took 3 to 7 s. A data export holds dozens to thousands. Contributor lists (AUTHORS, .mailmap) reach 10 by design and show up as leads for the reviewer. `--threshold` tunes it.
- New tests `scripts/test_committed_personal_data.py` (31 unit tests, one skipped on macOS: they cover the container rows for every format above, real gzip, bzip2, xz, zlib and PDF data, footerless and overlapping magics and zlib lookalikes, the `git@` and asset-scale names, the repository total with its edges, the flag ranges and the regex memory bound on a hostile dotted run) and `scripts/test-review-checks-committed-data.sh` (12 checks, with vendor/ and node_modules/ files planted and left unflagged, and the repository-total row passing through the hub), registered in `scripts/ci-tests.d/committed-personal-data.sh`.
