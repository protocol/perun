### Added
- Destructive guard wave 20: every review-3 finding and the held-out-25 misses. New blocks: `userdel -r|-f` and `deluser --remove-home|--remove-all-files`; one `sed|perl -i` of `sshd_config` that sets both `PermitRootLogin` and `PasswordAuthentication` (ssh lockout); `iptables|ip6tables -P INPUT|OUTPUT DROP|REJECT`; `chpasswd` fed a `root:` or `0:` line; `vipw|vigr`; attached `usermod -pVALUE root`. Pins in `scripts/test_destructive_guard_w20.py`.
- Cypher scan is now a linear keyword stream over each `;` statement with strings and `//`, `/* */` comments removed: no 300-character window, `;` in a string no longer hides the `MATCH`, `MATCH (a:K), (n)` comma patterns count, and a WHERE with `or|xor|not|true|exists`, a constant comparison or a self-comparison is not a filter (so `WHERE a OR b` deletes are blocked; rewrite as separate statements). A labeled `MATCH ... CALL { DETACH DELETE } IN TRANSACTIONS` is allowed.
- Package removal: an apt short-flag bundle that carries a value flag (`-tstable`, `-ca`) is no preview; the last preview switch and the last root option win (`--simulate --no-simulate`, `-r /mnt -r /`); rpm spellings of the core libraries (`libgcc`, `zlib`, `libselinux`, `python3-libs`, `python3-dnf`, `rpm-libs`, `libdnf`, ...) are blocked while `python3.9-pip` is not.
- `find -exec chown|chmod` start paths cover subtrees of `/etc`, `/usr` (not `/usr/local`), `/bin`, `/lib*`, `/boot`, `/root`, `/System`, `/Library`, `/private/etc`, plus `/home/<user>` and `/Users/<user>`; `find /home -exec chmod go-rwx` stays allowed. `chmod go-rwx` of `/etc`, `/var`, `/home`, `/etc/passwd`, `/etc/group`, `/etc/hosts`, `/etc/resolv.conf` and `/etc/nsswitch.conf` is blocked again (`chmod o-rwx /home` stays allowed as hardening); owner-only carve-outs shrink to secret files (`/etc/shadow`, `sudoers*`, `ssh/*`, `ssl/private`, `/root`, `/home/<user>`).
- Unquoted shell comments (`#` at the start of a word) are removed before tokenizing, so `rm -rf ./build # not /` is judged without the comment; `a#b`, `$#`, quoted and escaped `#` are kept.
- Review fixes: a Cypher `{k:v}` map literal or `SET n:Label` after `MATCH (n)` is no longer a filter (only labels, types and property maps inside the MATCH patterns count); a WHERE filters only when every `OR` branch names a property, label or pattern, so string/`IN`/`id(n) >= 0`/`size(`/`coalesce(` tautologies are blocked while `= true`, `IS NOT NULL`, `NOT (n)--()` and `OR` of real filters are allowed; `find -exec chmod go-rwx` is blocked for subtrees of `/usr`, `/bin`, `/lib*`, `/etc`, `/var` (not `/etc/ssh`, `/etc/ssl/private`); `libstdc++6`, `libcrypt1`, `libaudit1`, `libacl1`, `libattr1`, `libblkid1`, `libmount1`, `libsmartcols1`, `libuuid1` are core names.
- A command over 65536 characters or 2000 lines is blocked (fail closed) instead of scanned; the `_emitted` start pattern no longer backtracks quadratically.
- `kubectl delete namespace.foo.io` (a CRD) is no longer read as a namespace.

Kept false positives: `WHERE exists(n.p)` stays unfiltered (a held-out pin); `git push origin --delete tmp/<name>` stays blocked. Remote branch deletes need a human to confirm; run it yourself with the `!` prefix.

Decided, not changed: `sed -i` of `/etc/fstab`, `/etc/ld.so.conf` and `/etc/pam.d/*` stays blocked (a bad edit stops boot or all logins; copy the file first and ask the owner).

Follow-ups, not in this change: split sshd_config edits across two commands, other package managers (emerge, xbps-remove, snap, rpm-ostree, opkg), `cypher-shell -f` file vetting, `MATCH (a), (b:X) DELETE a` (a later labeled pattern counts as the filter).
