### Added
- `merge_train.py` (#1778): a PR whose precheck ended COULD_NOT_CHECK on some checks can now enter a train with a PARTIAL-PASS receipt (`partial_pass.py write PR --head SHA --unchecked NAME...`, stored in `.perun/partial/<PR>.json` or `$PARTIAL_DIR`). The receipt is valid only for its exact head, names exactly the unchecked checks (plan and verify judge every other check as before) and records the kill criterion `revert-pr-if-an-unchecked-check-fails-post-merge`. A train carries at most one PARTIAL-PASS PR: a second is skipped with `SKIP #N second PARTIAL-PASS (one per train; #M holds the slot)`. `merge --apply` records the landed PR in the train state; the new `partial-kill` subcommand checks its unchecked checks on the merge commit and, when one failed, opens a revert PR (`--apply`; dry run by default; exit 1), keeps it when all passed, and prints PENDING otherwise. The revert is opened through GraphQL `revertPullRequest`, so it still needs the normal merge path and was not exercised against the live forge. A partial pass is never counted as a pass. Tests: `scripts/test_partial_pass.py` (7), `partial_pass.py --selftest`.
