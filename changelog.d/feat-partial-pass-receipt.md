### Added
- `merge_train.py` (#1778): a PR whose precheck ended COULD_NOT_CHECK on some checks can now enter a train with a PARTIAL-PASS receipt (`partial_pass.py write PR --head SHA --unchecked NAME...`, stored in `.perun/partial/<PR>.json` or `$PARTIAL_DIR`, gitignored). The receipt is valid only for its exact head, names exactly the unchecked checks and records the kill criterion `revert-pr-if-an-unchecked-check-fails-post-merge`. A named check is skipped only while it is missing or unfinished on the head; one that ran and failed still blocks. A train carries at most one PARTIAL-PASS PR and only one may be outstanding: a second is skipped (`second PARTIAL-PASS (one per train; #M holds the slot)`, or `merged and undecided` until `partial-kill` decides the landed one), and `merge` HALTs if the recorded plan breaks that rule. `merge --apply` records the landed PR in the train state. The new `partial-kill` subcommand checks its unchecked checks on the merge commit: a failure opens a revert PR (`--apply`; dry run by default; exit 1); a running check, or one absent while CI is still running within `--wait` seconds (default 3600), prints PENDING; a check that never ran, or only skipped or neutral, prints UNVERIFIED (exit 1, record kept, never KEPT); KEPT only when every named check succeeded. The revert is opened through GraphQL `revertPullRequest`, so it still needs the normal merge path and was not exercised against the live forge. A partial pass is never counted as a pass. Tests: `scripts/test_partial_pass.py` (12), `partial_pass.py --selftest`.
