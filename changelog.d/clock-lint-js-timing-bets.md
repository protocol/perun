### Fixed
- `clock_lint.py`: the `timing bet under load` rule now covers JS/TS test files too (it flagged Python tests only, so the same bets passed in `.js`, `.jsx`, `.ts`, `.tsx`, `.mjs`, `.cjs`, `.mts` and `.cts`). It flags a fixed sleep (`sleep`, `delay`, `wait`, `waitForTimeout` with a literal, or a `setTimeout` inside `new Promise(...)` or around an assert) followed by an assertion in the same test block, a `{ timeout: N }` of 5000 ms or less in the options of a wait-style call, and an elapsed-time upper bound (`expect(elapsed).toBeLessThan(N)`, chai `.below`, `assert(elapsed < N)`). `clock-lint: allow` on any line of the call, or on a comment line above it, is the escape; a fake timer or clock marker in the file exempts the file; any failure of the rule fails open as `COULD_NOT_CHECK`. Like the Python rule, `--block-added` blocks it only in newly added files (#2141).
- `scripts/test_clock_lint_reltext.py`: the elapsed-time fixture is a real timing bet, so the test now expects exactly that one finding and still no real-clock or advisory line.
- `verification-handback.md` and `testing-situational.md` name JS/TS beside Python for the timing-bet rule (byte-neutral edits).
