### Added
- trufflehog secrets step in the review hub. `review_checks.sh` now runs trufflehog right after gitleaks. The hub never ran it, even when it was installed, so a second secret detector never contributed. The step scans the changed files in diff mode and every tracked file under `--full` (vendored directories are skipped as for every other step), passed as explicit `./path` arguments, 200 per call like semgrep. It runs fully offline: `--no-verification` never contacts a provider (so every finding is unverified) and `--no-update` skips the version check. `--fail-on-scan-errors` turns an unreadable path into a not-run row instead of a silent clean pass.
- No secret value is read, printed or stored. The step asks for `--sarif`, not `--json`, because the default and JSON outputs print the secret (JSON as `Raw`, `RawV2`, `Redacted` and `SecretParts`); the SARIF document holds the detector name, the file, the line and a fingerprint hash. A row is the detector, file and line with a fixed message of ours, and the parser reads only those three fields, so even a hostile document cannot leak a value into a row. `--log-level=-1` keeps trufflehog's own log lines out of the merged output so they cannot corrupt the document. A test plants a canary secret in the fake binary's `--json` output and proves it never reaches stdout, stderr, the record or any file under `TMPDIR`, and that the same witness does catch the canary when the run is switched to `--json`; the real binary gets the same drill on a runtime-built token.
- Same patterns as the other tools. A missing binary gives the `not installed` row (a `not-checked` finding, listed as not run and fixable, with the `brew install trufflehog` hint). The heavy lease is taken like gitleaks' (a full lease degrades to `nice -n 19` and is named in the summary, `REVIEW_LEASE_FULL=skip` gives a not-run row), and `heavy_gate.py` already classed `trufflehog ... filesystem` as heavy; a test feeds it the exact argv the step ran. A crash, a non-SARIF document or a result without a location fails closed as not run, never clean. trufflehog counts in the closing `ran X / wired Y` line and the record, and rows under fixture paths get the same `likely-fixture` hint as gitleaks' rows.
- `provision_tools.sh` now lists trufflehog (`brew install trufflehog`). It was missing from the installer list, so an absent trufflehog could not be `fixable` and `--print` would not have installed it. `method-situational.md` names the step in the analyzer list, and `tool-hub.md` lists trufflehog among the tools routed before the hub and records why the step uses `--sarif`.
- New test `scripts/test-review-checks-trufflehog.sh` (40 checks, 37 on a host without trufflehog; registered in `scripts/ci-tests.d/review-checks-trufflehog.sh`): a fake `trufflehog` on a hermetic PATH covers the finding row, the offline flags, diff mode against `--full`, the 200-file chunks, the fail-closed cases, the missing binary, the three lease states, the doc rows and the no-secret guarantee. A real-binary smoke runs on a two-file fixture only when trufflehog is installed. 35 of the 40 checks fail on the previous release; the other 5 are negative guards (nothing leaked, nothing scanned) or a self-check of the fake, which hold when the step is absent. `test-provision-tools.sh`, `test-semgrep-pack-fallback.sh` and `test-mode-coverage.sh` gain a clean trufflehog stub (in the first two the scanner counts rise by one; in the third a host without trufflehog would otherwise add a second not-checked row), and `test-review-checks-gitleaks-template.sh` now asserts on gitleaks rows only, because the trufflehog step has no counterpart to the gitleaks template's skip list and reports the `.history/`, `fixtures/` and `testdata/` files the template leaves out.
