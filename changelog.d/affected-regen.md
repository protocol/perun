### Fixed
- `scripts/run-ci-tests.sh --affected` (the pre-push default) now runs `scripts/regen-unlanded.sh` before the suites against the merge-base of HEAD and origin/main, matching CI's rebuild on its merge ref before any gate (a branch cut before the latest land still rebuilds), so a PR that adds a script no longer fails `low-context-index.sh` locally on a stale committed INDEX. After the suites, on any early exit, and on a TERM or INT (deferred until the rebuild ends, so the rebuild cannot write after the restore), it restores the derived files (`GENERATED` in `scripts/land-release.sh`) the rebuild changed to their pre-run bytes, and never touches any other file changed meanwhile: an already-dirty file keeps its edit, a file the rebuild created is removed, and a file edited after the rebuild is kept with a note. Selection, the privacy scan and the receipt tree hash use the tree as it was before the rebuild, and `--list-affected` stays dry. `land-release.sh --regen` no longer takes the land lock, so a land in progress or a leftover lock never blocks a push. Test: seven new cases in `scripts/test-run-ci-tests-affected.sh`, including a TERM sent during the rebuild, and one in `scripts/test-land-release.sh`.
