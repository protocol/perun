### Changed
- `review_checks.sh`: gitleaks `generic-api-key` hits tagged `likely-fixture` now collapse into one low-confidence summary row per top fixture directory when the directory has more than 3 of them ("gitleaks: N generic-api-key hits under tests/fixtures/ tagged likely-fixture (showing 3 of N; REVIEW_FIXTURE_ROWS=all for every row): file:line, ..." with the 3 sorted samples). Only that low-signal rule collapses: every other rule (Stripe, GitHub PAT, OpenAI, Anthropic, private keys, cloud keys, and so on), groups of 3 or fewer, and name-only matches such as `src/payment_test.py` stay per-row findings tagged `[likely-fixture]`. Rows keep the same JSON shape (`file` is the directory, `line` 0, `rule` `likely-fixture-summary`, `hint` `likely-fixture`). `REVIEW_FIXTURE_ROWS=all` (also `ALL`, `1`, `true`) restores per-row output; any other value keeps the default. The findings count on stderr counts output rows.
