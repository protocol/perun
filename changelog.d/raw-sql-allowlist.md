### Fixed
- semgrep-taint: perun.js.raw-sql-concat and perun.py.raw-sql-format no longer report a query value that was allow-listed first. Skipped now: a value that passed an unconditional-exit `!SET.has(x)` / `!ARR.includes(x)` check (JS) or `x not in ALLOWED` check (Python; an `assert x in ALLOWED` still fires, since python -O strips asserts), a value inside an `if (SET.has(x))` / `if x in ALLOWED` block (not its else branch), and a value returned by a single-return helper in the same file whose lookup table is a module constant: `MAP[x] ?? "literal"` (JS) or `MAP.get(x, "literal")` / `MAP[x]` (Python). The allow-list and lookup table must be an UPPER_SNAKE constant, so a request-derived list (`req.query.list.includes(x)`, `request.args.getlist(...)`) and a helper that returns its own input still fire. The check must be on the same variable that is interpolated, must exit unconditionally (a conditional exit or a log-only block still fires), and must not be followed by a reassignment of that variable (`x = ...` / `x += ...` reports again). Limits: the Python guards cover f-strings only (not `%`, `.format()` or concatenation), the helper must be defined in the same file, a guard block with more than one statement before the exit is not recognized in Python, and a constant named in UPPER_SNAKE but built from request data is not detected. Other rules (perun.*.sqli, registry SQL rules) are unchanged and can still report the same lines. Measured on bench/tool-only (offline, `python3 scripts/bench_tool_only.py`): recall 40/40 before, 42/42 after with two new vuln fixtures; false positives 5 before and 5 after. The two Python clean twins keep the allow-listed f-string, so the changed rule is exercised on them and stays silent; the registry rules python.lang.security.audit.formatted-sql-query and python.sqlalchemy.security.sqlalchemy-execute-raw-query still flag that line (4 rows without suppression), so the twins carry an inline `nosemgrep` naming those two rule ids next to their existing `nosec B608` and `noqa: S608`, the way a real codebase would document the allow-list. Test: scripts/test_semgrep_raw_sql_allowlist.py (live ruleid/ok fixtures including the bypass cases and a clean twin for each; skips when semgrep is absent, as the other semgrep tests do).
