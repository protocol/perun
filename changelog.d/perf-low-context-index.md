### Added
- `.claude/skills/INDEX.md` is now the single low-context entry point, still generated by `scripts/skill_index.py`: one line per skill (the first sentence of its description), one per slash command (`/name: purpose — argument hint`) and one per shipped script (`name: purpose — arguments`, with arguments only where the script's own header documents them; scripts with no documented CLI, such as hooks and sourced helpers, are listed by name). It also says where to read next: a skill's `SKILL.md` when its line matches, its `INDEX.md` for references and scripts. It points and never restates a checklist. It covers 11 skills, 5 commands and 90 scripts (60 with a documented CLI, 30 by name) in 10,053 bytes.
- `python3 scripts/skill_index.py --check` now also fails with `NOT IN INDEX: <skill>/<script>` (or `/<command>`) when a shipped `scripts/*.py|*.sh` or `commands/*.md` is not listed in the entry index. Coverage is read back from the file on disk, not from the generator, so a filter added to the generator cannot hide a script; `scripts/test_skill_index_entry.py` proves it with a generator that drops one.
- `scripts/size-budgets.tsv` freezes the entry index at its measured size, 10053 bytes, enforced by the existing `ci-gates.sh size` and `size-ratchet`. Adding a script now costs a visible `size-budget-raise: .claude/skills/INDEX.md <old>→<new> <reason>` marker, so the entry point cannot grow silently.
- `python3 scripts/skill_index.py --tokens` prints the always-loaded surface (skill descriptions, SessionStart host rules, the entry index) in bytes and estimated tokens (`bytes // 4`, this repo's chars/4 convention, not a tokenizer count). On the base commit: 1609 tok in total, of which 904 are injected by the host every session (descriptions 829, SessionStart host rules 75) and 705 are the entry index. After this change: 3417 tok, the whole increase in the entry index (2,823 → 10,053 bytes, 705 → 2513 tok); the 904 tok the host injects are unchanged. Nothing in this repo injects the entry index (no hook, install block, `CLAUDE.md` or `AGENTS.md` line points at it), so an agent reads it on demand instead of opening a skill's `INDEX.md` (agentic-delivery 3,388 tok, deep-code-review 4,924 tok, all eleven 9,893 tok) or its `SKILL.md` (up to 5,993 tok) to find what to run and how.

### Changed
- Per-skill `INDEX.md` script rows now show the CLI for scripts whose header is `name.py ARGS — purpose` (also ` - ` and ` -- `) or that give a call line in the docstring, and no longer repeat the script name in the trigger cell: 22 rows across five skills.

### Fixed
- `land-release.sh --regen` (and the land step) dropped any `size-budgets.tsv` row under `.claude/skills/` that was not a `SKILL.md` or `references/*.md`, so the entry index's budget row vanished on every regen. It now refreshes that row (or adds it when absent) and regenerates the indexes before measuring them.

### Added
- The always-injected host rules (`HOST_RULES`, injected at SessionStart and into every subagent) gain one line, "Find any Perun skill or tool: read .claude/skills/INDEX.md first.", so agents are pointed at the entry index: +16 est. tokens (91 instead of 75; `skill_index.py --tokens` total 3417 → 3433, host-injected 904 → 920).
- `install.sh` copies the entry index to `<host>/skills/INDEX.md` for every host it installs into (refreshed on re-install; recorded in the marker only when written fresh, and `perun_uninstall.py` removes it when unchanged). It lists all eleven skills, including ones the target did not install. `scripts/test_index_pointer.py` pins the pointer line and the install and uninstall behaviour.
