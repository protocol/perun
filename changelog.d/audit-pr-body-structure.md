### Added
- Audit, security and hardening PR bodies (the PR title says audit, security or harden) must now explain the proposed changes before a reviewer opens the diff. `comms_lint.py` has a new kind `audit-pr` (budget 1200 words, 160 lines) with a `sections` rule that fails, at any length, when a required heading is missing (`Summary`, `What changes for reviewers and users`, `Changes by area`, `How to verify`, `Not fixed`; the names live in one constant, `AUDIT_SECTIONS`; `Dependency upgrades` is optional), when `What changes for reviewers and users` is empty (it needs items or `None`), or when `Not fixed` carries a file:line, line reference, HTTP route, URL or file path (counts only, tracked privately). Headings inside fenced code are not sections, sub-headings stay inside their section, and a template hint in an HTML comment is not content.
- Coverage: `comms_lint.py --kind audit-pr --file BODY --range BASE..HEAD` also fails when a file the PR changes is not named under `Changes by area`, by its full path or by a containing directory written with a trailing slash. Nothing is exempt, so `changelog.d` fragments and lockfiles must be named too. `changed_files()` reads the range with a read-only `git diff --name-only` and treats `A..B`, `A...B` and a bare `A` alike (B against the merge-base, the files the PR carries); an unreadable range (or one starting with `-`) exits 2 with the reason on stderr, so a bad range never passes as clean. Many uncovered files are listed as a count with the first five paths. The check stays linear on hostile input (a heading line of 50,000 spaces, a 200,000-character path-like token, 8,000 files against a 50 KB section): the heading and path patterns are bounded, and coverage uses `str.find` with explicit boundary checks. HTML comments are blanked with `str.find` as well, so a body of thousands of unterminated `<!--` stays linear (`scripts/test_comms_lint_comments.py`).
- The check runs by itself: `comms_guard.py` (the existing `PreToolUse` hook, registered by the operating layer) checks a `gh pr create|edit` as `audit-pr` when its `--title` says audit, security or harden. `create` without `--head` also gets the diff against `origin/<--base>` (default `origin/HEAD`; the `origin/` prefix means a stale local branch is never used and a `--base` value cannot act as a git option), so coverage is checked, read in the directory of a `cd` ahead of `gh` (a lane runs `cd <worktree> && gh pr create`, and the hook's own cwd is another checkout); `edit`, `--head` or a missing repo or base check the headings only. It stays advisory and fails open (it adds the exact fix per failing rule and never blocks); a `comms_lint.py` without the new kind keeps the old `pr` check. Other PR titles are unchanged.
- The body template is in `references/artifact-templates.md` (the reference that owns PR bodies, already routed from `communication-structure/SKILL.md`), with the new row in its budgets table. Test: `scripts/test_audit_pr_body.py` (against a throwaway git repo, registered in `scripts/ci-tests.d/audit-pr-body.sh`); `scripts/test_comms_lint.py` lists the new kind and rule.
