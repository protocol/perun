### Added
- audit_sweep.py runs a recurring org (public repos) or local audit sweep. Per repo it keeps the last scanned sha and the fingerprints already reported, and prints only new findings as a hash-only TSV (repo, mode, file, rule, tool, fingerprint; never finding text or a secret). A descendant HEAD gets a plain `--base LAST` scan plus `--base LAST --history`; a first run, a history rewrite, a scanner change, a newly installed tool or a last `--full` scan 7 or more days old gets a `--full` scan, so a new advisory or detector also reaches idle code. Exit 1 with an `ERROR` row means a repo failed to scan and keeps its old state; exit 1 with a `GAP` row per tool means a timeout, crash or unread file blocked the repo, which keeps its old sha (a `--full` scan passes a 600-second per-tool `--timeout`, not the hub's 60-second default); exit 3 means the sweep could not start or could not save its state.
- Fingerprints hash the tool, rule, file and row text with its volatile counters normalized (commit counts, summary-row line numbers, the "; added" and corroboration suffixes), so an unrelated commit does not re-report an old finding, while a finding re-added on a new line is reported again, once.
- Not-checked rows are coverage, never findings: one `COVERAGE` row counts them, a second names the core scanners the host lacks (shellcheck, semgrep, trivy, osv-scanner, ruff/pyflakes: the hub reports their absence only on stderr), and one `ENVGAP` row names each tool with a gap no rescan closes (unverified-flag tools, no `REVIEW_OSV`, a lockfile with no fallback auditor, a "config changed in this diff" row, the node-check JSX row, the project-code gates, and repo layout or host provisioning rows such as no `go.mod`, no `psalm.xml`, a missing go or cargo toolchain, or no local kubescape, cargo-audit or retire data). A missing tool, a noise path or the guarddog `--full` row does not hold the sha, and installing a missing tool (or provisioning the ruby-advisory-db) triggers one rescan. Any other gap holds the sha, so the next run rescans the same range.
- The scanner runs without `GH_TOKEN`, `GITHUB_TOKEN`, the `--token-env` variable, `REVIEW_TEST_CMD`, `REVIEW_FUZZ` or `REVIEW_SCORECARD`, so it gets no token and never runs repo code, and each repo's rows reach stdout before its state is saved.
