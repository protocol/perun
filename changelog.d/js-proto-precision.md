### Changed
- semgrep-taint/js.yml perun.js.prototype-pollution: reports merge/extend shapes only. A key-loop copy must write into a function parameter (a local `{}`, typed or not, and `Object.create(null)` are skipped) and loops over a literal array or UPPER_SNAKE constant are skipped. A sink is suppressed only by a guard on the same key that dominates it in the same block (an `if` on `"__proto__"`, an allowlist or blocklist `.has`/`.includes`, or a target hasOwn check, with a continue/return/throw body), by `if (key !== "__proto__")`, or by a positive hasOwn check wrapping it. New shapes: nested `t[k1][k2] = v` from a key loop or req body/query/params, lodash `_.merge/mergeWith/defaultsDeep/set/setWith` with a req body/query/params or JSON.parse argument, a `x.split()` key-path walk, and a copy whose value derives from `source[key]`. Seeded corpus scripts/fixtures/js-proto-corpus: 26 sinks (including 14 found by review as recall or guard bypasses) and 10 safe controls (two use brace-body exit guards); the old rule found 6/21 of the first 21 sinks and hit 3 controls, the new rule finds 26/26 with 0 control hits. No real-repo precision or recall figure is claimed here: the committed corpus is the only evidence.
- Known misses (false negatives): `Object.entries(s).forEach(([k, v]) => ...)` and `Reflect.ownKeys(...).forEach`, a for-of path walk over `path.split(".")`, bracket request keys (`req.body[name]`, `req.params[0]`), a spread passed to lodash (`_.merge(c, {...req.body})`), `zipObjectDeep`, and an exit guard that ANDs the key test with another condition (`if (k === "__proto__" && x) continue;` still suppresses the sink). Known false positives: a regex-test allowlist, a `switch` that skips `__proto__`, a path walk guarded by scanning the key array, and loop copies whose keys are internal (the rule is search mode and does not prove the key is untrusted).
