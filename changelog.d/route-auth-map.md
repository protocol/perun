### Added
- deep-code-review `scripts/route_auth_map.py DIR`: report-only, stdlib-only lead-finder for missing authentication (CWE-306/862). It inventories every HTTP handler (Next.js `app/**/route` exports, `pages/api/**`, `"use server"` exports, Express/Router/Hono/Fastify `.get/.post/...` calls, FastAPI and Flask decorators) and prints one `path:line: SEV: METHOD route auth=<evidence|token|middleware|public|none>` row each. Evidence is an identity call (editable `IDENTITY` list), a Next `middleware.ts`/`proxy.ts` whose matcher covers the route (the file names an identity check, or can answer 401/403 under any name, so a custom-named session gate counts; a quoted `/path` elsewhere in the file is read as an allow-list entry, so that route and what is under it read none (a trailing `(.*)`, `/*` or `/:name*` is dropped, so a Clerk-style `createRouteMatcher(["/sign-in(.*)"])` list counts; only a route that starts with the literal is taken out, so `includes("/hook")` or `endsWith("/hook")` leaves `/api/hook` reading `middleware`), unless the literal is a prefix of a matcher entry or sits in the condition of an `if` whose body can refuse (a scope check such as `if (p.startsWith("/api/")) { return <401> }`, nested refusals included; a braceless body runs over a line break when the next line starts with `.`, `?`, `:`, `&&` or `||` or this one ends in `?`, `:`, `&&` or `||`); conditions are not evaluated, so a negated refusal reads its path as gated and a literal held in a collection or variable is read as an exemption wherever it is used; a scope check written as a ternary, an `&&` chain, a `switch` `case` or a body that only redirects to a login page is no `if` with a refusing body, so its literal reads as an exemption and the route it gates reads none; a regex or computed allow-list is not read, and a 401/403 that checks no identity (CSRF, geo, rate limit) still reads `middleware`), or a router-level `.use(<auth>)` before the route; a shared-secret header compare counts but reads `token`. A mutating handler with no evidence is HIGH, a GET with none is INFO, and a `route-auth-ok` comment marks a reviewed public route. `--paths` prints the unique GET and ANY-method routes, one per line, for the anonymous GET sweep. Exit 0 on a readable DIR, 2 on a usage error; silence is not proof of authentication.
- `review_checks.sh --full` runs it as tool `route-auth` (HIGH rows as rule `missing-auth`, SKIPPED when the repo has no handler files), and `references/security-appsec.md` routes it from the Anonymous GET sweep. `scripts/test_route_auth_map.py` (registered in `scripts/ci-tests.d`) pins every rule with golden rows over fictional fixtures and mutation-checks each one.
