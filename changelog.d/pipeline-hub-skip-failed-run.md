### Fixed
- `pipeline_hub.py` stopped collecting at the first failed call, so one run whose jobs endpoint always answers HTTP 502 left most sampled runs and every PR uncollected, and the note read `collection stopped: }.`. A failed jobs or attempts call for one run is now named once in the notes (run id, API message and HTTP status) and collection goes on with the next run and the merged-PR pages; a failed runs-list or pulls call still stops, and resuming with the same `--data` file works as before. The error text now takes the API's JSON `message` or gh's `<message> (HTTP nnn)` line instead of the last line of the reply.
