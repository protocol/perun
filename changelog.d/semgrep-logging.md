### Added
- `templates/semgrep-taint/logging.yml` (OWASP A09:2025), five rules with CWE metadata: `perun.js.log-sensitive`, `perun.py.log-sensitive` and `perun.go.log-sensitive` (CWE-532: a password, passwd, api key, SSN, card number, cookie or authorization value, a `user.token` or `clientSecret`-style name, or a whole request body reaches console/logger/log/logging/pino/winston/bunyan/log.Printf), and `perun.py.log-injection` and `perun.go.log-injection` (CWE-117: request input reaches a log call without newline stripping, repr, json.dumps, int or strconv.Quote). `scripts/pii_data_map.py` and `scripts/insecure_defaults.py` do not inspect log calls, so nothing is duplicated. A bare `token` or `secret` is deliberately not matched: in a first 5-clone probe the initial rule gave 4 hits, all false (public board slugs and a secret's name), so it was tightened to 0 hits on the same clones. No real-repo precision is claimed for these rules; the 0-hit probe says only that they are quiet, and the fixtures in `scripts/test_semgrep_logging.py` (a positive and a redacted, masked or sanitized clean twin per rule) are the recall evidence.
