### Added
- `audit_skills.py`: new `control-char` rule flags NUL and other C0 control characters (all but tab, LF, CR, FF) in text files, one finding per character as `path:line: high control-char: control character U+XXXX at col N` (first 20 per file, then a count of the rest). A known binary extension is `unscanned` unconditionally and there is no path skip (the audit has ignore markers); a text-extension file with a NUL in its first 8 KB still gets `unscanned` plus the first control character, since git shows such a file as binary and hides its diff; UTF-16 files (BOM, or NULs on alternate bytes) are decoded and scanned. A NUL past 8 KB used to make the whole file `unscanned`; it is now scanned. Tests: `scripts/test_audit_skills_control_char.py`.
- `review_checks.sh`: new built-in `invisible-chars` step, always on and with no tool to install, flags NUL and other C0 control characters and bidi, zero-width and tag characters in the changed text files of the repo under review (every tracked text file under `--full`). One row per finding in the usual JSON shape (`tool` `invisible-chars`, rule `control-char`, `hidden-unicode` or `not-checked`, message `control character U+001B at col 6`), first 20 per rule and file then a count row, at most 200 rows then one `not-checked` row, and listed under `analyzers ran`. Locale files (`.po .arb .xlf .xliff .properties .strings`, or under `locales/ i18n/ l10n/`) report only bidi overrides and isolates; tag characters inside a flag emoji sequence and ESC in `.snap .golden .ansi .log` or `__snapshots__/` are skipped; a file with an early NUL is reported only under a known text extension (else skipped silently); UTF-16 is decoded, not reported as NULs; only the first 2 MB of a file is read (a `partially scanned` row beyond); file names are scanned too (line 0); `third_party/`, `Pods/`, `bower_components/` and `*.min.js` are skipped. Rows under fixture or test paths are tagged `[likely-fixture]` (the gitleaks FXD/FXB definition) instead of dropped, and a timeout keeps the rows found so far. The rules live in the new `invisible_chars.py` next to the script, which `scripts/audit_skills.py` now imports instead of keeping its own copy; a scan that fails or times out adds a `not-checked` row. Tests: `scripts/test_invisible_chars.py`, `scripts/test-review-checks-invisible-chars.sh`, `scripts/test_invisible_chars_hardening.py`, `scripts/test-review-checks-invisible-chars-hardening.sh`.
- `scripts/test_secret_anthropic_airtable.py`: pins that the privacy gate's secret scanner (vendored gitleaks v8.30.1 rules, identical to upstream master for these four) flags Anthropic API and admin keys and Airtable personal access tokens and legacy keys, and stays quiet on near-misses. No new regex was needed; fixtures are built at runtime.

The gitleaks rules are named by id (`anthropic-api-key`, `anthropic-admin-api-key`, `airtable-personnal-access-token`, `airtable-api-key`), not by repo path.
