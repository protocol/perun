### Changed
- The eight Python taint rules in semgrep-taint/py.yml (sqli, command-injection, path-traversal, ssrf, deserialize, ssti, xss, open-redirect) no longer treat every function parameter, or input(), as a source. Sources are now the parameters of route-decorated handlers (`@x.route/get/post/put/patch/delete/api_route/websocket`, sync or async), Django/DRF views (`def v(request, ...)`, `def v(req, ...)` and class-based `def get(self, request, ...)`, sync or async), any non-self/cls parameter of a function in a module that imports a web framework (flask, fastapi, django, rest_framework, starlette, aiohttp, tornado, sanic, bottle, pyramid, falcon, quart, litestar, werkzeug, chalice, cherrypy), AWS Lambda `def h(event, context)` and WSGI `def app(environ, start_response)` entry points, plus the existing request accessors. CLI and script helpers stop reporting. On 108 real repos the eight rules went from 1602 hits to 58 (path-traversal 1349 to 3, ssrf 162 to 34); all 58 are in 19 files that import a web framework. On a 16-sink handler-to-helper corpus the rules alone find 11 of 16 (the hub 14 of 16). The 5 misses are helpers in modules with no framework import that a handler calls from another file; that flow is not tracked and each rule message says so. Helpers in framework modules that only ever receive constants or fixed values (a function parameter fed a literal) still report, since the rules do not follow call sites (5 rows from the 8 classes on the clean controls, 6 counting unsafe-api-consumption).
