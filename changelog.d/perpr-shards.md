### Changed
- CI job `perpr` is now a matrix of 3 legs (`shard: [1, 2, 3]`, `fail-fast: false`) instead of one serial job, because it was the critical path of every PR: it took 19.0 minutes in CI run 41028470595 (2026-10-30). The slowest leg is predicted at about 7.1 minutes, computed from per-test seconds and not measured on CI. Leg `i` runs only the `scripts/ci-tests.d` registrations that `scripts/ci-tests-shard.sh` lists for `SHARD=i/3`, the spelling `selftests` already uses: sorted in the C locale, `*.sh` and `*.bg.sh` numbered separately so the slow background tests spread over the legs, shard `i` takes the numbers equal to `i-1` modulo 3. The 3 slices are disjoint and cover every registration. The helper fails closed (a malformed `SHARD` exits 2, an empty slice exits 1), the tests themselves never see `SHARD`, and `gates` is unchanged: it still needs `perpr`, and a matrix job fails unless every leg succeeds. Contract for test authors (`CONTRIBUTING.md`): a registration must not rely on another registration having run first. Inserting a registration moves every later one along by one position, so a leg can drift by tens of seconds; a weights file for the split is the upgrade if a leg nears 8 minutes. `scripts/test-ci-shards.sh` now reads only the `selftests` shard count, and `scripts/test-conflict-free-prs.sh` copies the helper into its fixture and runs the steps with `SHARD` unset. Test: `scripts/test-perpr-shard.sh` (the real tree's slices are disjoint and complete, a dotfile in `scripts/ci-tests.d` is not counted (the step globs skip it), a bad `SHARD` fails closed, and `ci.yml`'s own start and per-PR steps run as each leg over a fixture: every registration runs once, `SHARD` does not leak, a failing serial or background test fails only its own leg, and `gates` still needs `perpr`).
