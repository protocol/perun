### Added
- Zero-chat lanes. `subagent_start_inject.py` now always injects `LANE_RULES` (310 characters, about 78 estimated tokens) into every subagent except the built-in types whose chat is the deliverable (`HANDBACK_EXEMPT_TYPES`): tool calls only, with no narration, plans or recaps between them, then a final message of `key=value` fields only (`status`, `sha`, `result`, `tests`, `blockers`, `report`) under 400 characters. `LANE_RULES=0` turns it off and `LANE_RULES_SKIP_TYPES` (comma-separated) skips more types, for a read-only review type that keeps a raised cap. It needs no house file, so an existing install gets it when the script updates.
- `handback_cap.py` is now also a lane audit. Whenever a stop is allowed it appends one JSON line per lane to `$XDG_CACHE_HOME/perun/lane-audit.jsonl` (`HANDBACK_AUDIT_LEDGER` moves or disables it): estimated assistant text tokens (narration between tool calls, and the handback) against tool-call tokens, plus the tool-call count, whether the handback passed the fields check, and how many rewrites the hook forced. Counts only, never transcript content. It reads the subagent's own `agent_transcript_path`; the hooks reference says `transcript_path` is the parent session's file and that the transcript is written asynchronously, so the final message is taken from `last_assistant_message` (or a `SubagentHandback` call) and counted once. The same reference gives no entry format and the sessions page calls it internal and version-dependent, so the parser reads only the `text` and `tool_use` blocks of assistant entries (the shape observed on local transcripts on 2026-10-16) and reports `COULD_NOT_CHECK` instead of zeros when it finds none. Token figures are estimates (characters / 4): the `usage.output_tokens` logged in those transcripts is far below the content size, so it is not used.
- `handback_cap.py --report [LEDGER]` and `--scan PATH... [--since-days N]` print medians, p90, totals, the text share, the fields-only rate and the rewrite rate as aggregates, never content; `--scan` audits transcripts already on disk without writing the ledger.
- `scripts/test_zero_chat_lanes.py` (51 tests, run in CI) covers the fields-only check, both caps and their boundaries, the audit counts against a synthetic transcript in the observed shape, the ledger (one row per lane, no content, disabled, unwritable, XDG path), the report and scan modes, the injected rule and its agreement with the cap, and the docs. CI also now runs `subagent_start_inject.py --selftest`.

### Changed
- `handback_cap.py` defaults drop from 800 characters / 10 lines to 400 characters / 8 lines, and every handback line must now be a field: `key=value` (also `key: value`, optionally bulleted), the older `status | evidence | next` list, or a single token. A sentence is rejected with its line number and the accepted shape. `HANDBACK_FIELDS_ONLY=0` keeps the caps only; `HANDBACK_MAX_CHARS` and `HANDBACK_MAX_LINES` still move them, and the new `HANDBACK_MAX_BLOCKS` (default 3, the old fixed release valve) bounds how many rewrites one lane can be forced into. If you raised the caps for a type whose chat is its deliverable, add `HANDBACK_FIELDS_ONLY=0` to that entry (the template's review-type entry now does). To get the old behavior back set `HANDBACK_FIELDS_ONLY=0 HANDBACK_MAX_CHARS=800 HANDBACK_MAX_LINES=10`.
- The lane preamble now says zero chat between tool calls and a final message of `key=value` fields only. The default `.claude/house-defaults.md` that `install.sh` writes no longer carries its own copy of the handback rule (the injected lane rules own it); an existing file keeps its old hand-back line, so delete that line there.
- `host-enforcement.md`: the review-lane setup now says the default `SubagentStop` entry must exclude that type. Matching hooks run in parallel and any block wins, so the raised cap in a second entry had no effect while the default entry also matched. Matcher and parallel-execution rules are logged from the hooks reference in `docs/standards-index.md` (fetched 2026-10-16, with the sessions and session-storage pages).

### Measured
Reproduce with `python3 .claude/skills/agentic-delivery/scripts/handback_cap.py --scan ~/.claude/projects --since-days 14` (read-only; prints aggregates, never content).
- On 1,839 lane transcripts from the last 14 days on one developer machine (15 more, of the exempt built-in types, excluded), with token figures estimated at characters / 4: median text tokens per lane 220 (p90 996; narration between tool calls median 36, p90 762; handback median 125) against 7,567 tool-call tokens per lane, so text is 3.5% of lane assistant output. Of today's handbacks 59.9% already have the field shape, but the median handback is about 500 characters on one line and 73.6% would be sent back once under the new caps.
- Projection (estimate; assumes every lane complies, meaning no narration and a handback within the cap): median text tokens per lane at most 100, total 156,563 against 798,866 now (-80%). Each forced rewrite re-reads the lane's whole context (median about 111,000 tokens on the last turn), so the hook is a backstop: assuming output costs 5x input and cache reads 0.1x (check your rate card), it pays for itself only while about 1 lane in 7 or fewer needs a rewrite. `handback_cap.py --report` prints the live rate.
- The added lane rules are 310 characters against 161 for a plain caveman-ultra subagent activation line and 3,780 for the full caveman skill file; the whole default injection grows from 783 to 1,094 characters (+78 estimated tokens).
