### Added
- Zero-chat lanes. `subagent_start_inject.py` now always injects `LANE_RULES` (189 characters, about 48 estimated tokens) into every subagent except the built-in types whose chat is the deliverable (`HANDBACK_EXEMPT_TYPES`): tool calls only with no prose between them, then a final message of `key=value` fields only (`status`, `sha`, `result`, `tests`, `blockers`, `report`) under 400 characters. `LANE_RULES=0` turns it off and `LANE_RULES_SKIP_TYPES` (comma-separated) skips more types, for a read-only review type that keeps a raised cap. It needs no house file, so an existing install gets it when the script updates.
- `handback_cap.py` is now also a lane audit. Whenever a stop is allowed it appends one JSON line per lane to `$XDG_CACHE_HOME/perun/lane-audit.jsonl` (`HANDBACK_AUDIT_LEDGER` moves or disables it): estimated assistant text tokens (narration between tool calls, and the handback) against tool-call tokens, plus the tool-call count, whether the handback is fields-only, its target violations (`viol`: `long`, `prose`) and `cut_tok`, the tokens a truncation to the field lines within the target would drop. Counts only, never transcript content. A hook cannot rewrite what the caller receives, so the truncation is measured, not applied. It reads the subagent's own `agent_transcript_path`; the hooks reference says `transcript_path` is the parent session's file and that the transcript is written asynchronously, so the final message is taken from `last_assistant_message` (or a `SubagentHandback` call) and counted once. The same reference gives no entry format and the sessions page calls it internal and version-dependent, so the parser reads only the `text` and `tool_use` blocks of assistant entries (the shape observed on local transcripts on 2026-10-16) and reports `COULD_NOT_CHECK` instead of zeros when it finds none. Token figures are estimates (characters / 4): the `usage.output_tokens` logged in those transcripts is far below the content size, so it is not used.
- `handback_cap.py --report [LEDGER]` and `--scan PATH... [--since-days N]` print medians, p90, totals, the text share, the fields-only rate and the off-target rate as aggregates, never content; `--scan` audits transcripts already on disk without writing the ledger.
- `scripts/test_zero_chat_lanes.py` (50 tests, run in CI) covers the never-a-second-handback rule, the unchanged 800/10 cap, the audit counts against a synthetic transcript in the observed shape, the ledger (one row per lane, no content, disabled, unwritable, XDG path), the report and scan modes, the injected rule, its size and its agreement with the logged target, and the docs. CI also now runs `subagent_start_inject.py --selftest`.

### Changed
- A handback that is off the fields-only 400-character, 8-line target (`HANDBACK_TARGET_CHARS`, `HANDBACK_TARGET_LINES`, `HANDBACK_FIELDS_ONLY=0` to skip the prose check) is logged, never sent back: a rewrite re-reads the lane's whole context, which costs more than a shorter handback saves. The blocking cap is unchanged (800 characters / 10 lines, `HANDBACK_MAX_CHARS`, `HANDBACK_MAX_LINES`, release after 3 blocks).
- The lane preamble now says zero chat between tool calls and a final message of `key=value` fields only. The default `.claude/house-defaults.md` that `install.sh` writes no longer carries its own copy of the handback rule (the injected lane rules own it); an existing file keeps its old hand-back line, so delete that line there.
- `host-enforcement.md`: the review-lane setup now says the default `SubagentStop` entry must exclude that type. Matching hooks run in parallel and any block wins, so the raised cap in a second entry had no effect while the default entry also matched. Matcher and parallel-execution rules are logged from the hooks reference in `docs/standards-index.md` (fetched 2026-10-16, with the sessions and session-storage pages).

### Measured
Reproduce with `python3 .claude/skills/agentic-delivery/scripts/handback_cap.py --scan ~/.claude/projects --since-days 14` (read-only; prints aggregates, never content).
- On 1,863 lane transcripts from the last 14 days on one developer machine (15 more, of the exempt built-in types, excluded), with token figures estimated at characters / 4: median text tokens per lane 222 (p90 996; narration between tool calls median 36, p90 765; handback median 126) against 7,479 tool-call tokens per lane, so text is 3.6% of lane assistant output. Of today's handbacks 59.6% already have the field shape, but the median handback is about 500 characters on one line and 73.5% are off the target.
- Projection (estimate; assumes every lane complies, meaning no narration and a handback within the target): median text tokens per lane at most 100, total 159,102 against 813,965 now. Net per lane, saved minus injected, in raw tokens: 351 saved on average (122 on the median lane) minus 48 for the rule = about +303 on average (+74 at the median). Saved tokens are output and the rule is cached input, so the net is larger in cost than in tokens; it is an upper bound that depends on the lanes following the rule, which only the ledger can show.
- The rule is 189 characters against 161 for a plain caveman-ultra subagent activation line and 3,780 for the full caveman skill file.
