### Added
- `review_checks.sh` marks every row `"new": true|false` in diff mode: `true` when the row's file and line are on a line `REF...HEAD` adds, read from `git diff -U0` of the range the script already uses. It is rename-aware, so a renamed file's old lines are not new; line 0 and file-level rows are `false`. `--full` and `--history` omit the key, no row is ever dropped, and stderr gains one line, `review_checks: N of M rows are on lines this diff adds`. A reviewer can start from the rows the change introduced and treat the rest as pre-existing, instead of re-triaging a touched file's whole backlog. The diff flags are pinned (`-U0 --inter-hunk-context=0 -M -a --no-color --no-ext-diff --no-textconv` and explicit `a/` `b/` prefixes) so a reviewer's git config cannot change which lines count as added; `-a` keeps a text file with a NUL byte (an `invisible-chars` row) from reading as `Binary files differ`, which would mark its added lines pre-existing.
- One sentence in `references/method-situational.md`, where the script's rows are documented for reviewers: verify new rows first, and report a pre-existing row in a touched file only when the diff makes it reachable or worse.
- `scripts/test-review-checks-new-rows.sh` (16 offline cases, wired in `scripts/ci-tests.d/review-checks-new-rows.sh`): a fake shellcheck on a hermetic PATH, in a repo whose git config is hostile (no rename detection, no prefixes, merged hunks, forced colour, an external diff, a line-dropping textconv). It covers an added line, a pre-existing line shifted down between two hunks, a renamed and edited file, a pure rename, a new file, a line 0 row, a path with a space, a NUL byte, the stderr count, and the missing key under `--full` and `--history`. Each pinned flag has a case that fails without it, and the cases that assert the flag fail on the script before this change.
