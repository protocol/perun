### Added
- Pre-push commit identity check. `pre-push-verify.sh` now refuses a push when the author or committer email of any commit it adds is not a noreply form (`<local>@users.noreply.github.com` or `noreply@<domain>`), unless the address is listed in the gitignored `.identity-allow.local.txt` (one email or glob per line). The rules live in one script, `deep-code-review/scripts/identity_gate.py`, which the hook calls and `perun_doctor.py` imports. It checks the pushed commits that neither the remote sha (for an existing branch; ignored when it was never fetched) nor any remote-tracking ref has, so a branch rebased onto a newer main is not blamed for main's commits, masks every address in its output (`jane@example.com` shows as `j***@***.com`), and prints the fix (`git config user.email <id>+<username>@users.noreply.github.com`, `git commit --amend --reset-author`). It runs before the verdict cache and the unset-command handling, so neither a cached pass nor `DCR_PREPUSH_ALLOW_UNSET` skips it. `perun_doctor.py` gains a WARN-only "commit identity" row when the effective `user.email` is not a noreply form but the default branch's last 10 authors all are. Known ceiling: `Co-authored-by:` trailers are not checked, and with no python3 or no `identity_gate.py` the hook prints one notice and the push goes on. New test `scripts/test_identity_gate.py`.
