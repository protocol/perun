### Fixed
- `ready()` in `.claude/skills/agentic-delivery/scripts/flow_alarm.py` counted the train's own progress marker (the `perun/train-stage` status that `merge_train.py stage` posts pending on each PR it queued) as a check, so every PR a train had queued read as not ready. The stop-starting cap and the `symptom` alarm then undercounted the waiting queue exactly while a train was running, and the cap let new work start that it should have held. `ready()` now skips the marker in any state, with the same rule `landing_watchdog.green()` uses; any other pending status still blocks, and a PR whose only status is the marker has no check. Tests: `python3 scripts/test_flow_alarm.py` adds one case (a PR the train queued or dropped stays ready, also with the script's own directory off `sys.path`; another pending status blocks; the cap counts the train's queue).
