### Changed
- `perun.js.cors-reflected-origin` and `perun.py.cors-reflected-origin` are now taint rules: an Origin read (any case, any default or fallback such as `or`, `||` or `.get(h, h)`, through aliases, local variables and string methods) that reaches the Access-Control-Allow-Origin value is reported when credentials are sent in the same function, including a credentials value held in a variable. A single-argument map lookup is the sanitizer; an `in` allowlist guard is accepted noise and is covered as a flagged fixture in `test_semgrep_defaults.py`. It is not a bench clean twin, because the bench scorer discards any rule that fires on a clean twin, which would unscore the CWE-942 hit.
- `perun.js.jwt-decode-unverified` is now a taint rule: any value derived from `jwt`, `jsonwebtoken`, `require("jsonwebtoken")` or an import of it (aliases of any depth, `.default`, `jwt["decode"](t)`, a decode destructured from an alias) is followed.
