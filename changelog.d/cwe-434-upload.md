### Added
- semgrep-taint/upload.yml: five CWE-434 (unrestricted upload of a dangerous file type) rules, each tagged `cwe: "CWE-434"`. JS: multer with no fileFilter (with memoryStorage it is reported only when the same file writes or serves `file.buffer`), and express-fileupload `.mv()` with the client file name. Python: Flask/Werkzeug `.save()` with the request filename. Go: multipart `Filename` into os.Create, os.OpenFile or filepath.Join. Ruby: `original_filename` into File.write, File.binwrite or a write-mode File.open. A rule reports only when the missing check is provable in the same function: a path.extname / os.path.splitext / filepath.Ext / File.extname / .endswith call counts as the check, and in Python so do `.lower().endswith`, `.lower().rsplit`, `Path(name).suffix` and an early exit on a helper defined elsewhere (`if not allowed_file(f.filename): return`, `raise` or `abort(...)`). Werkzeug secure_filename does not: it strips path parts but keeps the extension, so the common `f.save(secure_filename(f.filename))` is reported. Test: scripts/test_semgrep_upload.py (positive case and clean twin per rule). False-positive probe over 27 local clones (run while secure_filename still counted as a check): 1 hit, a memory-only multer upload that never writes the buffer, removed by the memoryStorage rule above (0 after).
