### Fixed
- Per-mode coverage can no longer read as zero findings. `validate_status_claims.py` has a fifth detector: a findings claim for a review mode (security, perf, a11y, privacy, reliability, correctness, ux) fails unless the file carries a `mode: ran (N files)` (N >= 1) or `mode: NOT RUN (reason)` entry for it. A claim is the mode word beside a count or negation word at the start of a line, bullet, table cell or clause ("security: no issues", "security findings: 0", "Security — all clear", "0 new security findings", "No security concerns", "perf: no regressions"); a claim beside a NOT RUN entry, a bare `ran`, `ran (0 files)`, a reasonless or placeholder (`reason`, `x`, `n/a`, `none`) NOT RUN is flagged too. Fenced code is skipped; `ran (12 files, 0 findings)`, `ran (1,200 files)` and a table row `| security | ran (3 files) |` are entries. Closes a dogfood miss where a lane that ran only perf handed back "security 0 new". `report-format.md` adds a required `Mode coverage:` line (repeated in the BLUF and every lane hand-back), `full-map-report.md`'s definition of done names it, and the example report carries one.
- `handback.py --body-file FILE` runs the same check on the hand-back body and stops red (`handback RED: mode coverage`) on an unbacked claim; without `--body-file`, or without deep-code-review installed, nothing is checked. Test: `scripts/test_handback_mode_coverage.py`.
- `review_checks.sh`: a tool that timed out, crashed or lost the lease was listed under "analyzers ran"; it now leaves that list (even when a later file passes) and appears once in a new `NOT RUN: <tool> (<why>), ...` part of the stderr summary (`none` when empty), and a skipped tool that is not a hub tool now also lands a `not-checked` row on stdout, so `[]` never hides it. A tool that is merely not installed stays under "skipped (not installed)". Tests: `scripts/test-mode-coverage.sh`, eval `report-mode-coverage-not-run`.
