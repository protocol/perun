### Added
- `.claude/skills/agentic-delivery/scripts/repo_settings_audit.py OWNER/NAME... [--repos-file FILE] [--json]`: a read-only audit of the GitHub settings a diff review cannot see. Per repository it reads the default branch's classic protection and rulesets together (no protection, force pushes allowed, fewer than 1 required review, no required checks, admins exempt), the Actions token default, review approval and allowed actions, collaborator counts (admins, outside), deploy keys with write, webhooks with `insecure_ssl` or plain http, environments without protection rules, and secret scanning and push protection. Each row is repo, check, severity and a one-line fix. A 403 or 404 is a `not checked (needs admin)` row, never a clean result; so is a reply that lacks a field the check reads, a list holding an item that is not an object, and a list of 1000 or more (lists, rulesets included, are read 100 a page). A 404 `Branch not protected` is a finding only when the repository reply shows `permissions.admin` true. The secret scanning and push protection fixes say a private or internal organization repository needs GitHub Secret Protection. Output is counts and booleans: no login, email, key title, hook URL or API message text is printed. It calls `pipeline_hub.gh_get` (bare `gh api` GETs, TLS fallback through `gh_rest.fallback`), so the getter is injectable, and it writes nothing. Exit 0 once the audit ran; 2 for a bad slug, no repository, an unreadable `--repos-file` or `gh` missing.
- `scripts/test_repo_settings_audit.py` (55 offline tests on fictional acme/widgets fixtures, wired in `scripts/ci-tests.d/repo-settings-audit.sh`): every check, the not-checked rows (a 403 or 404, a missing field, an unreadable item, 1000 or more items), pagination, every wrong-shaped API reply (each must give a not-checked row, never a clean one), the privacy rule on text and JSON output, the CLI, and the default getter end to end through `gh api`.
- A route row in `agentic-delivery/SKILL.md`, one `repo_settings_audit.py` row in `references/tool-hub.md` naming `legitify` (needs an `admin:org` token) and OpenSSF Scorecard as the OSS options, and the GitHub REST pages, the secret scanning and push protection pages, `legitify` and Scorecard sources with their 2026-10-30 fetch date in `docs/standards-index.md`.
