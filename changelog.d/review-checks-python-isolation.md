### Fixed
- review_checks.sh no longer lets a scanned repo's own Python run through the hub's inline `python3` calls. The hub runs from the repo root, where `python3 -`, `-c` and `-m` put the working directory first on `sys.path`, so a committed `json.py`, `shlex.py` or `pyflakes.py` would shadow the stdlib module or the linter. Every inline call now runs with `-I`, and the pyflakes probe and run drop the working directory from `sys.path` before importing pyflakes, which keeps site-packages on any Python 3 (`-P` would need 3.11 or later). Test: `scripts/test-review-checks-python-isolation.sh`.
