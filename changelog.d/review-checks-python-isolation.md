### Fixed
- review_checks.sh no longer lets a scanned repo's own Python run through the hub's inline `python3` calls. The hub runs from the repo root, where `python3 -`, `-c` and `-m` put the working directory first on `sys.path`, so a committed `json.py`, `shlex.py` or `pyflakes.py` would shadow the stdlib module or the linter. Every inline call now runs with `-I`, and the pyflakes probe and run use `-P`, which drops the working directory but keeps site-packages (Python 3.11 or later; an older Python reports pyflakes as not installed). Test: `scripts/test-review-checks-python-isolation.sh`.
