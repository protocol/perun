### Fixed
- Nothing bounded a test's run time, so a test that never returned spun a core until someone killed it, and parallel runs stacked up. `scripts/run-ci-tests.sh` now runs each test under a wall-clock bound, `PERUN_TEST_TIMEOUT_S` seconds (default 900; a missing, non-numeric or non-positive value, or one longer than 9 digits, means 900). A test that outlives it is killed and fails like any other failing test, printing `run-ci-tests: FAIL <test> (timed out after <secs>s)`. The alarm kills the test's own process, not child processes it started, so a caller that pipes the runner's output waits for those; a test that arms its own alarm replaces the runner's.
- `scripts/test_security_gates_corpus.py` now bounds each guard check to 5 seconds, and so do the in-process Python blocks of `scripts/test-destructive-guard.sh`. A check that never returns (catastrophic regex backtracking, say) is a `FAIL` line naming the case or block instead of a hang: the corpus test moves on to the next case, and a destructive-guard block skips the rest of its checks. The destructive-guard test's selftest and hook calls are bounded by the runner only. The privacy-gate call in the Python test has a 120 second timeout, and a timeout is a `FAIL` line, not a traceback (the gate's own child processes are not stopped). Every existing case keeps its result.

### Changed
- Tests: `scripts/test_security_gates_corpus.py` checks its own bound against a catastrophic regex, and the new `scripts/ci-tests.d/run-ci-tests-timeout.sh` covers the runner bound: a test that sleeps far past `PERUN_TEST_TIMEOUT_S=2` fails promptly with the timed-out line and its own process is gone, and a bad value falls back to 900.
