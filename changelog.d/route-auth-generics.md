### Added
- `route_auth_map.py` reads TypeScript type-argument route registrations (`app.post<{ Params: { id: string }; Body: Widget }>("/path/:id", h)`, also on `.all`, `.use` and `.addHook`) through a bounded balanced `<...>` scan: the angle brackets must balance within 2000 characters, no `;`, `&&` or `||` may stand outside brackets, and a `(` must follow. A file whose only registrations are typed is now scanned, and a comparison such as `x.get < y && f(z)` is not a route.
- A Fastify root hook now reads `auth=root-hook`. `x.addHook("onRequest"|"preHandler"|"preValidation"|"preParsing", fn)` on a receiver bound to a `Fastify(...)` call, at any depth (a factory function included), counts when `fn` (inline, or through the same-file declarations it names) can answer 401/403 or names an identity check; `onSend`, `onRoute` and `onListen` never count. It covers what the hook file wires onto that receiver after the hook, in source order and within the block that holds the hook: the routes of a scanned file it passes to `x.register(plugin, opts)` or calls as `fn(x, ...)` with the instance as the first argument (`fn` imported from that file by a relative path), and the non-GET routes declared on that receiver in the hook's own file. A route above the hook, a module that is imported but never registered or called, a call with another instance, and a routes file with any wiring site the hook does not cover stay HIGH.
- What a root hook covers is read from the `if` statements of the hook text up to and including its first refusal. A negated path test with a bare `return` (`if (!req.url.startsWith("/acme-api/")) return;`, also `req.routeOptions.url?.startsWith(...)`) is a scope: only routes under it are covered. A positive path test with a bare `return`, written in the condition or through a same-file declaration it names (`PUBLIC_PATHS.includes(url)`), is an allow-list entry: a route under it keeps its own evidence. A path in the condition of a refusing `if` is a scope, and a `!` before it covers nothing. A quoted path anywhere else (a role table the hook reads, a path test after the refusal) says nothing, and a route-registration literal never counts.
- A root hook's path literals are read by the operator that tests them. A `startsWith` allow-list entry lets through every route whose raw path starts with it, as JavaScript does (`if (req.url.startsWith("/acme-api/health")) return;` also lets `/acme-api/healthz` through, so that route stays HIGH); `===` and `==` against a plain name or member chain (`req.url`) name that path only, whether they allow-list it or scope it (`if (req.url === "/acme-api/admin") return reply.code(403).send();` covers `/acme-api/admin` and not `/acme-api/admin/users`); any other test (`includes`, a collection, a regex, `!==`, or `===`/`==` against a call or an index such as `req.url.slice(0, 15)` or `path.dirname(req.url)`) allow-lists by raw prefix and scopes by the exact path. Known limit: a string `includes` or `endsWith` allow-list entry also lets through a route that only contains or ends with its literal (`/acme-api/health` next to an `endsWith("/health")` entry), and that route can still read covered. A `startsWith` scope still covers the routes under it, by path segment.
- A bare return before the first refusal under a condition that is neither a path test nor an identity check (an identity call, or a comparison with a secret-looking value) is a bypass, and the hook then covers nothing; `done()` and `next()` count as bare returns. Conditions are not evaluated, so a bypass OR-ed with a path test still reads as the path test; the script docstring lists the other limits.
- The refusal test that makes a Next middleware or a Fastify hook count as a gate also reads `.code(401|403)`, `statusCode = 401|403`, `.unauthorized(` and `.forbidden(`.

### Fixed
- `tenant_scope_check.py` no longer crashes with `IndexError` on a file whose last character is a backslash inside an open string; `route_auth_map.py` reads files through the same masker.
