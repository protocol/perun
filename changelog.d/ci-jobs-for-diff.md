### Added
- `ci_cost_advisor.py ROOT --diff BASE`: lists every `pull_request` workflow job the committed diff `BASE...HEAD` fires, with its `run:` lines, so a fix lane knows which CI jobs to run locally (or name `left to CI`) before it pushes to a repo it does not own. It applies the same `types`, `branches`, `paths` and `paths-ignore` rules as the cost model, counts a renamed file under both its paths, reads a lone-string filter as one pattern, joins a backslash-continued command and a folded `run: >` body into one line, and tags a job that builds an image, starts containers or declares `services:` or `container:` (`docker build`, `docker buildx`, `docker compose up`, `build-push-action`) `[runtime]`. BASE is the branch the PR targets: `branches:` and `branches-ignore:` filters are matched against the branch BASE names (`dev`, `origin/dev` and `refs/remotes/origin/dev` all mean `dev`), never against `--default-branch`, so a repo whose PRs target `development` keeps its `development`-filtered jobs. A sha or tag BASE names no branch, so each job a branch filter gates is listed tagged `(branches: unchecked)` instead of dropped. A workflow the parser cannot read but that names `pull_request` (a BOM before `on:`, say) is listed as `UNPARSED` rather than dropped, and one last line names the workflows that start only on `push`, `merge_group` or `workflow_run`, which are not evaluated. An unusable BASE (unknown, empty or option-shaped) exits 2 with no job list. It is read-only and offline: it returns before the visibility probe and never calls the network. `DiffJobs` in `scripts/test_ci_cost_advisor.py` covers each rule.
- One routed bullet in `references/parallel-audit.md` section 6: pass the branch the PR targets, run the listed jobs locally, or name each `left to CI` under the PR body's `How to verify`; a green unit run says nothing about a `[runtime]` job.

### Fixed
- A `**/` at the start of a path segment in a `paths:` filter now also matches no directory, as GitHub's filter pattern cheat sheet specifies, so `**/Dockerfile` matches a root `Dockerfile` (it still does not match `MyDockerfile`). The fix is in the glob matcher shared with the cost model, so the cost estimate stops dropping those workflows too. `Triggers` covers it, and the source and fetch date are logged in `docs/standards-index.md`.
- `scripts/test_ci_cost_advisor.py` no longer leaves a `ci-advisor-test-*` directory in `$TMPDIR` on every run. Each temp dir now comes from one registry that `tearDownModule` removes, and `NoTempLeak` runs the whole file in a child process with a private `TMPDIR` and fails if anything is left behind.
