### Fixed
- `handback_cap.py` now holds a lane's hand-back while a `git commit` from its worktree is still running, not only a `git push`. A background commit with a slow pre-commit hook was not held, so a lane could hand back before its commit existed. The process match is `git [-c k=v] [-C dir] [--opt] push|commit` on a process whose argv[0] is `git`, alone or behind `env VAR=...` or `perl -e 'alarm 30; exec @ARGV'`, so a wrapped `perl -e 'alarm 30; exec @ARGV' git commit -m x` counts while a `claude -p` lane brief, a shell string or a `grep` that only names `git commit` does not, and both words now end with `(?![\w-])`: `git commit-tree`, `git commit-graph`, `git push-x` and `git log --grep commit` do not match (the old `push\b` ending did match `push-x`). The block text reads "A git push or commit from this worktree is still running (its pre-push or pre-commit hook may take 15+ minutes)" and no longer says the lane owns the process (it may belong to another process in the same checkout), read-only agent types (review, investigat, audit, explore) are never held for a live push or commit, the hold still ends after 30 minutes (`HANDBACK_PUSH_MAX_S`), and an unreadable process table still prints `COULD_NOT_CHECK` and passes. The `BACKGROUND WORK` docstring and the `templates/lane-preamble.md` line that describes the rule say push or commit too.
- `handback_cap.py`'s live push or commit check no longer counts its own ancestors. It read `ps -axo pid=,command=` and skipped only its own pid, so a headless `claude -p "<brief that mentions git commit>"` host (the brief is in its argv, its cwd is the lane worktree) looked like a live commit and held every hand-back until the 30-minute cap. It now reads `pid=,ppid=,command=` through `_ps_table` and skips the hook, its ancestors and its descendants with the same `_skip_pids` helper the background-work scan uses; a `git commit` that is not an ancestor still holds. A process table that parses to no rows now prints `COULD_NOT_CHECK` and passes, as an unreadable one does.
- Test: `python3 .claude/skills/agentic-delivery/scripts/handback_cap.py --selftest` (already run by CI) gains cases for a plain `git commit`, `git -C <dir> commit`, a wrapped commit (quoted and as `ps` prints it), a live commit held for its own worktree but not for the checkout that contains it, and no match for `commit-tree`, `commit-graph`, `push-x` and `git log --grep commit`. Five of them (the positive commit cases and `push-x`) fail on the previous regex, so 64 of 69 passed; all 69 pass now. The `ps` mock now emits the `pid ppid command` rows the check reads, and four more cases cover a parent and a grandparent whose argv holds `git commit` (not counted, even with its cwd in the worktree), an unrelated `git commit` (still counted) and a process table that parses to no rows (`COULD_NOT_CHECK`, not a pass as `False`); the two ancestor cases and the empty-table case fail on the previous check, so 70 of 73 passed. Ten more cases cover the argv[0] match (a sibling `claude -p` brief, a `zsh -c` string and a `grep` that name `git commit` are not held; plain, `env`-wrapped, perl-wrapped and path-qualified `git commit` and `git push` are), read-only agent types (not held) and the hold text (no ownership claim); six of them fail on the check before them, so 77 of 83 passed; all 83 pass now.
