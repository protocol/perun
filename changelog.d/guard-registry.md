### Added
- `scripts/guard-registry.tsv`: one row per hook a shipped template runs or `install.sh` writes and per `ci-gates.sh` gate, with columns `id`, `owner`, `reason`, `review-by` and an optional fire log path. A guard is a hook script a shipped `.claude/skills/*/templates/*.settings.json` runs (`hook:<skill>/<script>`), a git hook `install.sh` writes (`hook:.githooks/<name>`), or a `ci-gates.sh` subcommand (`gate:<name>`). A script no template wires (a CI-only gate script, a hook the owner installs by hand) has no row; `ci-gates.sh rails` still covers its `# rail:` header. The owner is a lowercase role slug (`release-owner`), never a person; `Jane Smith`, an email and an `@handle` are rejected.
- `ci-gates.sh guard-registry --registry <file> <root>`: fails closed when a guard has no row, a row has an empty reason, an owner that is not a role slug, or a `review-by` that is not a real `YYYY-MM-DD` date, when a guard has two rows or a row has more than five columns, and when a row names a guard that no longer ships. It also fails when the root has no hook or gate to check, and when `ci-gates.sh` defines a `cmd_` function whose dispatcher line the scan cannot read, so an empty or blind scan cannot pass. A review date in the past never fails the gate; the report below surfaces it. The test below runs it on the real registry on every PR.
- `ci-gates.sh guard-registry --report [--days N] ...`: a read-only list for the owner to confirm. It shows rows past `review-by`, and guards whose fire log has no dated line inside the last N days (default 30). A guard with no fire log, or whose log is missing, unreadable, emptied or holds no dated line, is reported as `unknown`, never as zero fires. It runs the gate first, never deletes or edits a row, and opens every file read-only. Today only `reply_cap.py` has a fire log (`~/.cache/perun/reply-cap.log`, one dated line per block), so it is the one row with a fifth column. That cell names the default location only: `REPLY_CAP_LOG` or `XDG_CACHE_HOME` moves the log, and the report then reads the wrong file.
- `scripts/test-guard-registry.sh` (registered in `scripts/ci-tests.d/guard-registry.sh`): one case per failure mode above, the fail-closed and argument errors, the report's window, `unknown`, `~` expansion and read-only behaviour, and the real registry (row counts, the `reply_cap` log path, and each hook row's owner, reason and review date equal to its script's `# rail:` header).

Decision record: the `# rail:` headers from `ci-gates.sh rails` stay, because they also cover non-hook gate scripts that this registry does not list. Hook rows therefore repeat the header's owner, reason and review date, and the test fails if the two drift apart. If they still disagree after about 30 days, retire one of the two; the follow-up is to let `rails` accept a registry row in place of a header.
