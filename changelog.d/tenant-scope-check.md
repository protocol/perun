### Added
- `scripts/tenant_scope_check.py DIR` (stdlib, report-only): parses `*.prisma` models, treats a model with a `workspaceId`/`orgId`/`tenantId`/`teamId` field as tenant-scoped, and flags `findUnique`/`findFirst`/`update`/`updateMany`/`upsert`/`delete`/`deleteMany` (and `OrThrow`) calls in server code (`app/**/actions.ts`, `app/api/**`, `server/**`, `*.server.ts`) whose `where` has `id` but not the scope field (HIGH, "unscoped tenant access"), plus tenant-linked models with no scope field that server code uses (MED, "model missing tenant key"). False-positive guards: scope field as a top-level `where` key (bare, quoted or computed; also compound keys and a top-level `AND`; not text such as `id: x.workspaceId`, not `OR`), relation key, variable or spread `where`, comments, strings, test files, a `tenant-scope-ok` comment. It is a heuristic lead-finder, not coverage: silence is not proof of tenant isolation (aliased/awaited clients, variable `where`, findMany/count/raw SQL are not seen), and it prints `heuristic; scanned N server files` on stderr. Output is one `path:line: SEV: message` per finding plus a JSON summary; exit 0. `review_checks.sh --full` runs it as an optional step (SKIPPED when no `*.prisma` is tracked). Routed from `references/full-map.md` (domain T row), which stays within its frozen byte budget and the Phase 0-2 must-load floor pin. New test `scripts/test-tenant-scope-check.sh`, eval `audit-tenant-scope-id-only-where`.
