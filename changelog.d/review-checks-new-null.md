### Fixed
- `review_checks.sh` diff mode: a row's `"new"` flag (`true` when its file and line are on a line `REF...HEAD` adds, else `false`) is now `null`, meaning unknown, for every row in a file that differs from `HEAD` in the working tree, whether edited (staged or not) or untracked. Most rows are read from the working tree while the flag comes from the committed diff, so a `true` or `false` there could name the wrong line. `--full` and `--history` still omit the key and no row is dropped. With K null rows the stderr count line reads `N of T rows are on lines this diff adds, K unknown (file differs from HEAD)`; with none it is unchanged. The files come from `git --no-optional-locks status --porcelain -z --no-renames -uall`: it leaves `.git/index` alone (`git diff HEAD` rewrote it for a file that only changed its mtime, even with that flag) and takes no revision, so a root file named `HEAD` cannot break it. If the read fails, `"new"` is omitted from every row and stderr says `review_checks: could not list files that differ from HEAD; "new" omitted`, where it used to vanish silently. Ignored untracked files and `assume-unchanged` edits are not listed. `references/method-situational.md` documents the third value.
- `scripts/test-review-checks-new-rows.sh` gains 16 cases (32 in all): an unstaged edit, a staged edit to a path with a space, an untracked file named by a fake `tsc`, the clean files that keep `true` or `false` (one the diff does not touch), the exact count of null rows and the count line, `.git/index` left alone after a mtime-only change, a root file named `HEAD`, and an unreadable index. Eight of them fail on the script before this change.
