### Changed
- The privacy gate (`scripts/ci-gates.sh privacy`) now runs one prefilter pass before its per-pattern scan: a single `grep -IlE -D skip -f` over every banlist pattern at once, in the same 1000-file batches, lists the only files any pattern can match, and the existing per-pattern greps read just those files. A clean tree is therefore read once instead of once per pattern, which shortens the gate on large trees. The hit set is unchanged: hits are still attributed per pattern with the content withheld, the empty-input ERE probe still runs first so the pattern list holds only valid patterns, the `secret_scan.py` pass is untouched, and a prefilter grep error fails closed (it never reads as "no candidates"). The candidate list is newline-delimited, so a tree holding a path with a newline in its name skips the prefilter and falls back to the full per-pattern scan, which keeps the hit set unchanged there too. The new `scripts/test-privacy-prefilter.sh` pins the unchanged hit set against an independent one-grep-per-pattern oracle, the one-pass cost on a clean tree, that the per-pattern greps see only listed files, both fail-closed paths (an invalid ERE and a prefilter error), and that a hit in a file whose name holds a newline still blocks.
