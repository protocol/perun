### Added
- Operating layer: `landing_watchdog.py`, a `UserPromptSubmit` hook (and a `check` CLI) that tells the model when the merge pipeline has landed nothing while green PRs wait. It fires when the default branch got zero first-parent commits in the last `landing_stall_min` minutes (policy key, default 60) and at least one open non-draft PR has every check green, adding one line: "Landing stalled: 0 merged to <branch> in N min, K green PRs waiting. Fix landing before starting new work." This closes a failure where a coordinator kept spawning work for 40 minutes to several hours while green PRs waited unnoticed. It asks the remote (one `git fetch`, one `gh pr list`) at most once per 15 minutes per repo and replays the cached verdict between, with the cache under `<cache>/perun/landing-watchdog` beside the other hook state. Mode is `warn` (default) or `off` via env `PERUN_LANDING_WATCHDOG` or policy `landing_watchdog`; it never blocks, and no gh, no origin, a failed fetch or any error prints nothing. Wired into the operating-layer settings template, `install.sh`, `perun_doctor.py`, `perun_policy.py`, an agentic-delivery eval and `scripts/test_landing_watchdog.py`.
