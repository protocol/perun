### Changed
- Behavior change on install and upgrade: re-running `install.sh` with the operating layer applied on a repo whose policy has no `role` key now turns the CEO-altitude guard on (warn) and prints `CEO-altitude guard now warns (role=ceo); opt out: perun_policy set role off`. Opt out with `perun_policy.py set role off` (kept on later installs) or `PERUN_ROLE=off`. Cause: `ceo_altitude_guard.py` never warned in a fresh install because the policy default `role` is `off` (it only counted). `install.sh` with the operating layer applied now writes policy `role: ceo` (warn) unless the policy already has a `role` or `PERUN_ROLE` is set; `role=off` and `ceo-strict` stay available via `--policy` or `perun_policy.py set role`. Lanes are unaffected (they carry `agent_id`). Tests: `scripts/test_ceo_guard_default_warn.py` (registered in `scripts/ci-tests.d/ceo-guard-default-warn.sh`).
