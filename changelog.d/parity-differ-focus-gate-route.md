### Fixed
- `parity_differ.py` accept-file trust through `focus_gate.load_record` (the route used wherever `focus_gate.py` imports): the call passed a keyword `load_record` does not have (`commit_only`; commit-only trust is already its default), so it raised `TypeError`, and it passed `resolve_owners()`'s whole `(owners, warning)` tuple as the owner list, so once the keyword was gone every commit, the owner's included, still read as "not the owner" and a missing owner reported that instead of "no owner email configured". It now passes the owner list. CI's `--selftest` never reached the route: `_focus_gate()` loads `focus_gate.py` without registering it in `sys.modules`, so on Python 3.11 to 3.14 (3.15 imports it; no other version was checked) its dataclasses fail to build and the loader falls back; that import is unchanged here. Test: `scripts/test_parity_differ_focus_gate.py`, which imports `focus_gate` normally and hands it to `parity_differ`, so the route runs on every interpreter (it fails on the previous code with the `TypeError`).
