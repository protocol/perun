### Added
- Two bundled JavaScript/TypeScript semgrep rules in `templates/semgrep-taint/js.yml`, for bug classes that hand audits found and the bundled rules missed. `review_checks.sh` already loads the whole template directory, so both run in the default review with no wiring change.
- `perun.js.date-parse-rollover` (INFO, low): a date accepted only because `Number.isFinite` or `isNaN` of an inline `Date.parse(x)`, `new Date(x)` or `new Date(x).getTime()` passed. V8 reads an impossible day such as 2026-02-30 as 2 March instead of rejecting it. The message names the fix: format the parsed date back with `toISOString()` and reject the input unless it matches. A `.toISOString()` call anywhere in the enclosing function counts as that round trip and silences the rule, and test paths are skipped like the credential rules. A check on a variable bound first (`const d = new Date(x); isNaN(d)`) is deliberately not flagged: most of those hits were display, age and TTL helpers, so they cost more precision than they bought recall. Other known ceilings: a function that also stamps an unrelated `toISOString()` is missed, component compares such as `getUTCDate()` are not recognised, and an INFO hit can land on code that parses a date without validating it.
- `perun.js.gcm-no-auth-tag-length` (WARNING, medium): `createDecipheriv` with an `*-gcm` cipher and no `authTagLength` option, so Node accepts an authentication tag shorter than 16 bytes (a 4-byte tag passes; checked on Node 24). That weakens integrity only when the tag length is attacker-controlled, for example when the tag is whatever follows the ciphertext in the message, and the message says so. It names the fix: pass `{ authTagLength: 16 }` as the fourth argument. The cipher may be a string literal or a `const` bound to one; a non-literal cipher name and an options argument that is not an object literal are skipped, not guessed.
- New test `scripts/test_semgrep_js_date_gcm.py` (registered in `scripts/ci-tests.d/semgrep-js-date-gcm.sh`): fictional fixtures annotated `// ruleid:` and `// ok:` in `.js` and `.ts` copies (28 expected hits), with the round-trip form, the `authTagLength: 16` form and a variable-bound check as the clean cases, plus a copy under a test path that must stay clean. The live part needs semgrep and prints SKIP without it, and CI installs none, so offline structural asserts on the YAML back it up: the severities, the named fix, the cipher regex (semgrep anchors `metavariable-regex` at the start, so `gcm$` alone matches nothing), both round-trip suppressions, the test-path exclusion shared with the credential rules, the `authTagLength` exemptions, no variable-bound alternative, and the attacker-controlled-tag wording. Against the previous release's `js.yml` the live check misses all 28 expected hits; seven single-edit mutants of the new rules (no round-trip suppression, no `authTagLength` exemption, an unanchored cipher regex, the wrong severity, no test-path exclusion, a variable-bound form added back, the old overstated message) each fail the test both with and without semgrep installed.
- Precision, measured read-only on audited code, counts only. A true positive (TP) is one reviewer's reading of three lines of context: the check is the only gate deciding whether an externally supplied date string is accepted, in non-test code. Date rule: 40 files pre-selected for an inline `isNaN`/`isFinite` of a date parse (26 distinct file contents, identical copies across clones counted once). A first version that also flagged variable-bound checks gave 42 hits in 34 of the 40 files (34 distinct hits, 23 TP, 68%); this version gives 38 hits in 34 files (30 distinct, 23 TP, 77%), the 4 dropped hits being variable-bound and none a TP. 7 of the kept hits pair a format regex with the parse check on the same value, the clearest TPs; the 7 kept false positives are a bar-highlight computation, two test or check scripts, a coercion helper, an age calculation, a token-payload shape check and a Retry-After header. On 60 other files that contain a date parse and an `isNaN`/`isFinite` anywhere, the first version gave 32 hits in 26 files and this one 0; about 5 of those 30 distinct dropped hits were real input validators (throwing or returning an error on NaN), so the narrowing costs some recall. One audited module that validated a calendar date with an inline `Number.isFinite(Date.parse(...))` plus a format regex: 1 hit on the revision before its fix, 0 on the revision after it (which round-trips with `toISOString()`). Gcm rule: of 10 JavaScript files that call `createDecipheriv` across the audit clones, 1 hit, a TP on the variant without `authTagLength`; the six copies of the fixed variant and the other files stay clean.
