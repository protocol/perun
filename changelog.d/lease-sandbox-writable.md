### Fixed
- The machine-wide heavy-job throttle and the exclusive train lease were inert inside a Claude Code sandbox: `perun_policy.py heavy-acquire` could not create its lease file under the read-only user cache dir, exited 2, and `review_checks.sh` then ran its scanners unleased, so no sandboxed session ever left a lease for the others to count. On macOS only, writers (`heavy-acquire`, `heavy-release`, the `heavy-exclusive*` commands and `stage_run.py`) now use the first writable of the usual lease dir and a per-user fallback dir under the system temp dir, and every reader (the slot count, the exclusive holder, the `heavy_gate.py` hook and `heavy-load`) checks both, deduplicated by real path. The fallback is used only when its root, its `perun` dir and its `heavy` dir are real directories (not symlinks) owned by the current user and the root has mode 0700; otherwise it is skipped and behaviour is as before. On other platforms nothing changes. `PERUN_HEAVY_DIR` still pins exactly one dir; `PERUN_HEAVY_FALLBACK_ROOT` moves the fallback root for tests.
- Every lease, holder-file and queue-marker read now goes through `perun_policy.read_lease`, which opens without blocking or following a symlink and skips anything that is not a regular file, so a FIFO planted in a lease dir can no longer hang a read: the `heavy_gate.py` hook, `heavy-load`, the slot and queue checks of `heavy-acquire`, and `stage_run.py`. `stage_run.py` still drops a stale lease it finds outside the primary lease dir, but never signals the process group such a lease names.
- Accepted limit, documented in `perun_policy._fallback` (the forged holder is pinned by a test): every sandboxed session of the same user can write the shared fallback dir, so one of them can forge a holder (a lease or `heavy.exclusive` naming a live pid) and make the hook and the train gate delay or deny heavy commands, or plant a FIFO where a sandboxed writer is about to create its temp or `.waiting` file and stall that writer. That is a same-user delay, not a way to run or signal anything.
- `scripts/test_lease_sandbox_fallback.py` (registered in `scripts/ci-tests.d/lease-sandbox-fallback.sh`): fixtures only, never the real temp dir; the fallback cases run on macOS only. It covers an unwritable primary falling back and releasing, a fallback holder counting against the slots of a process whose primary is writable, an exclusive fallback holder blocking acquire, the hook seeing fallback holders, a symlinked, foreign-owned or loosely moded fallback being refused, and a pinned dir never using the fallback.
- `scripts/test_lease_sandbox_hardening.py` (registered in `scripts/ci-tests.d/lease-sandbox-hardening.sh`): FIFOs in a pinned dir and in the fallback never block the hook, `heavy-load`, `heavy-acquire`, `stage_run.py` or the train gate (every subprocess has a timeout), `read_lease` rejects symlinks, directories and FIFOs without leaking a descriptor, no fallback is read, written or created off macOS, a symlinked or foreign-owned `perun` or `heavy` component is refused, a writable lease dir under a read-only parent falls back, a forged fallback holder delays as documented, and the orphan reap never signals a group named by a lease outside the primary dir.
- `scripts/test_prepush_gate_cache.py` pins `PERUN_HEAVY_DIR` so the real `stage_run.py` it runs never counts leases from the machine-wide fallback dir.
