### Fixed
- `train_land.sh`: a `train<TAG>.log.cancel` left behind by an earlier run of the same tag no longer stops a fresh run at its first tick (exit 6, nothing landed). A run that owns the tag marker (or runs with `TRAIN_UNIQUE_RUN=off`) clears a leftover cancel file at start; it is kept while a live same-tag twin may own it, so an urgent stop is never swallowed. A cancel that arrives after the run has started is honored as before. The header says to touch the file only once the train runs (#2142).
- `scripts/test-train-stale-self.sh` no longer pre-creates the cancel file before the run (that case encoded the bug; the cancel-during-a-gate case still covers the stop), and `scripts/test-train-stale-cancel.sh` covers the leftover, the in-run cancel, `TRAIN_UNIQUE_RUN=off` and the live twin.
