### Added
- Fixture signals on `committed-data` rows. Each file row of `committed_personal_data.py` (the `committed-data` step of `review_checks.sh`) now ends with counts only, never an address or a domain: how many of the file's addresses have a placeholder-style local part (john, jane, test, user, foo and similar words, alone or back to back, digits and `._%+-` ignored), and how many are on a reserved domain (example.com, .net and .org, plus .test, .example, .invalid and .localhost), out of every address in the file with the reserved names counted back in. The row starts with `likely fixture:` only when the path is a test, spec, fixture or mock path (a whole directory name such as `tests/`, `__mocks__/` or `testdata/`, or a word of the file name such as `people.test.ts` or `mock-users.json`) and at least half of the addresses are placeholder-style or on a reserved domain. docs, examples and samples are not test paths, because real data lives there too. Why: in an audit of 43 repositories the check gave 38 single-file rows; 30 were test or mock data with invented addresses and 8 were real data, and every row needed manual triage.
- The label is a hint, not a verdict, and recall is unchanged. No row is dropped, no threshold or exit code changed, and the first scan, which decides the count and the threshold, is untouched; the second scan (reserved names included, so the signals do not depend on `--include-reserved`) runs only for a file that is already flagged. The repository-total row and the `not-checked` rows carry neither the counts nor the label. Measured on the 38 single-file rows of that audit, the label marks 4 of the 30 fixture rows and none of the 8 real-data rows, and none of the 33 rows of a known real export elsewhere in the audit; most of those fixtures use invented names at realistic domains, outside the word list, so they keep a plain row. `review_checks.sh` still adds no `likely-fixture` hint or tag to these rows, because a real address in a fixture is still a leak. Known ceiling, stated in the script: a test file that mixes real-looking addresses among many reserved ones can carry the label.
- New test `scripts/test_committed_personal_data_fixture_label.py` (13 tests, synthetic addresses only: `.zz` and example.com names, with obviously invented names for the real-looking ones; registered in `scripts/ci-tests.d/committed-personal-data-fixture-label.sh`). A test-path file of placeholder addresses gets the label, a test-path file of real-looking addresses does not (at 5 of 12 placeholder-style, 6 of 12 labelled), a non-test path never does, the row set is unchanged, and no address, domain or local-part word reaches the output. 11 of the 13 fail on the previous release; the other 2 pin the unchanged strict exit code and repository-total row. The existing suites keep every old expectation: their helper strips the new clause from rows, which is the evidence that the rows themselves are the same.
