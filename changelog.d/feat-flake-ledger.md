### Added
- New `agentic-delivery/scripts/flake_ledger.py` (stdlib only): a per-test pass/fail ledger keyed by tree SHA. A test with at least one fail and one pass on the same tree is a flake; after N distinct flake trees (default 3) `quarantine` lists it with an owner-reviewed expiry date (default 14 days). A quarantined test is reported and non-blocking until its expiry, after which it blocks again until `renew`; `quarantine` never extends an entry. A test that fails consistently on a tree (two or more fails, no pass) is never quarantined, and a quarantined test that fails consistently on the checked tree is blocking again (`check`). With `FLAKE_LEDGER_DIR` set, `train_flake.sh` records each `FLAKE`/`REAL` verdict in the ledger (best-effort) and prints `quarantined-flake <id>` instead of `FLAKE` for an id on its active quarantine list that re-ran alone as a flake and is not already failing consistently on that tree. `train_land.sh` counts such an id toward the new failures like a `FLAKE`, reports it, lands past it, and skips the flake-on-base check for it (so a known flake no longer ends in `CANT`). The label needs a solo failure (0 < failed solo runs < runs): a suite failure that passes every solo re-run keeps the plain `FLAKE` and its base check (a quarantined id runs all its solo re-runs, no early stop on the first pass). The ledger records each run separately (`SUITE`, then every solo `FAIL`/`PASS`; verdict labels are not evidence) and counts a flake tree only with a solo fail and a pass. Against a PR forging its own quarantine entry, `FLAKE_LEDGER_DIR` under the worktree or git toplevel is refused (exit 2), the quarantine list is read from a snapshot taken before any PR code runs, and the variable is unset for `VERIFY_CMD`, `BROWSER_CMD`, `RERUN_CMD` and `FLAKE_SETUP_CMD` (ceiling: code running as the same user can still find any path it is told about by other means, so keep the ledger directory outside every checkout). Ledger writers hold an `flock`, `quarantine.json` is replaced via a unique temp file, and a torn last ledger line is tolerated and dropped on the next append. Unlisted ids, expired entries, consistent failures (`REAL`) and a listed id already failing consistently on the union tree behave exactly as before. Routed from the "Fix a red gate or union" row of `agentic-delivery/SKILL.md`. Tests: `scripts/test_flake_ledger.py` (17 cases, incl. concurrent writers and torn lines) and `scripts/test-train-flake-ledger.sh` (10 end-to-end `train_land.sh` cases, one wired into `scripts/test-ci-gates.sh`).
