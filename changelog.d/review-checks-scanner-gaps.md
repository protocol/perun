### Fixed
- `review_checks.sh`: ten cases where a finding was dropped or mislabelled, or a run could read as clean. Each has its own block in `scripts/test-review-checks-scanner-gaps.sh` (stub tools on a hermetic PATH, offline), and each fails on the previous script.
  - zizmor findings were silently dropped: zizmor echoes the path it was given (`./.github/...`), which never matched the changed-file list. Paths are now normalized. A batch hub tool (zizmor, actionlint, bandit) that returns a row for a file outside the list it was given is now listed under `NOT RUN` with a `not-checked` row instead of reading as clean (gosec is exempt: it scans `./...`).
  - `--full` on a repo whose file list outgrew a pipe buffer dropped gitleaks, trivy and hub rows: `printf list | grep -q` under pipefail failed whenever grep matched early. Membership is now tested against a temp file.
  - osv-scanner: an exported `OSV_SCANNER_LOCAL_DB_CACHE_DIRECTORY` that already holds a seeded database now runs offline by default (as `REVIEW_OSV_DB_DIR` does; `provision_tools.sh --cache osv` reads it); `REVIEW_OSV=1` still asks the API. A cache with no database is never used: with none, osv-scanner prints empty results, not an error, which would read as clean.
  - actionlint is routed for workflow files (`actionlint -format '{{json .}}'`, exit 1 = findings), alongside zizmor.
  - An empty diff, or one with only excluded paths, exited 1 with no output (`grep -c` exits 1 at a count of 0 under `set -e`). It now exits 0 with `[]` and says `0 files in diff`.
  - semgrep: errors with zero findings on one 200-file chunk marked the whole tool `NOT RUN`, even when other chunks scanned fine. That chunk is now partial (stderr line plus a `not-checked` row, semgrep stays under `analyzers ran`); a scan is `NOT RUN` only when every scanned file errored. A single scan with errors on some files and no findings is likewise partial.
  - checkov and grype rows had shifted columns (rule held the check name or package, message empty, line 0) because `read` collapsed the empty leading file field. Rows now carry the rule id, line and message.
  - semgrep rule ids no longer carry the dotted local config-directory prefix that semgrep adds.
  - grype is routed to SBOM-like names only (`sbom`, `bom`, `cdx` or `spdx` as a whole name part): `app.cdx.json` is scanned, `bomb.json` and `kaboom.json` are not.
  - checkov: the flat "nothing to check" summary (no `results`, `parsing_errors` 0, for example variables-only Terraform) is a clean file instead of `NOT RUN`; compose files are no longer routed to it (not a checkov framework).
- Bundled semgrep rules (`templates/semgrep-taint/js.yml`): a `typeof req.body.password !== "string"` type check was reported as a hardcoded credential compare, because semgrep binds the whole operand and the name regex matched the tail of `typeof req.body.password`. `hardcoded-credential-compare` and `hardcoded-basic-auth` now skip an operand that starts with `typeof`; `scripts/test_semgrep_typeof_compare.py` applies the rule regexes to the bound text (offline, no semgrep) and fails on the previous rules.
