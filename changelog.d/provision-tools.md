### Added
- `provision_tools.sh`: new skill script that makes the scanners `review_checks.sh` wires actually run. The agent sandbox denies installs and the network, so scanners come out NOT RUN until the owner provisions them outside it. A plain run is a dry run that lists the missing scanner binaries and the cold caches (trivy DB, osv-scanner offline DB, a local semgrep `p/default` snapshot) and installs or writes nothing; `--print` emits the ONE line to paste yourself: `brew` and `pipx` installs (the pipx pins are the PyPI versions checked 2026-10-29; brew formulae cannot be pinned) plus the cache warm-ups (trivy with an empty `DOCKER_CONFIG`, because its DB download fails when `~/.docker/config.json` names a missing credential helper; `osv-scanner --offline-vulnerabilities --download-offline-databases`; a `curl` of the semgrep registry pack). A scanner found only in `~/.local/bin` (pipx, `uv tool`) counts as installed.
- `review_checks.sh` uses warm caches offline with no flag: the osv-scanner offline DB runs as `--offline-vulnerabilities` (`REVIEW_OSV=1` still selects the online API, an explicit `REVIEW_OSV_DB_DIR` still wins, a cold cache stays NOT RUN with the fix named) and the semgrep snapshot replaces the registry `p/default` pack as a local `--config` file (it counts as warm only when it has a top-level `rules:` key, so an empty file or an error page is cold and the registry pack is used; `scripts/test-provision-semgrep-warm.sh`); trivy runs offline against the cache `provision_tools.sh` warmed and is given it as `--cache-dir` (the cache moves under `DCR_CACHE_ROOT` when that is set, which trivy's own default dir ignores, so a provisioned host used to stay NOT RUN). It appends `~/.local/bin` to PATH (`DCR_USER_BIN` overrides, empty disables; `DCR_CACHE_ROOT` overrides the user cache dir).
- `review_checks.sh`: a closing stderr line `review_checks: ran X / wired Y scanners; not run: ...; partial: ...; fixable: ... (run: bash .../provision_tools.sh --print [DIR])` (wired = the scanners that had work in this run, shellcheck, ruff/pyflakes and `--history` gitleaks included, which a provision cannot install and so are never fixable), recorded in `review-checks-last.json` in the git common dir. A scanner that ran with a narrower scope (trivy secret-only, semgrep with errors) is listed under `partial` and in the record's `partial` key instead of counting as a full run. The osv-scanner fix names this repo as DIR: a bare `--print` treats one ecosystem's DB zip as a warm cache and can print nothing.
- `perun_doctor.py`: a `review scanners` row reads that record. WARN (exit 1) when scanners the last run wired did not run, or ran without their offline cache, for a cause `provision_tools.sh` fixes (the osv-scanner fix carries this repo as DIR); INFO with no readable record, no provisioning fix, or a partial scope; OK when everything wired ran in full.
- `scripts/test-provision-tools.sh` (hermetic: stub binaries, throwaway HOME and caches; it also runs the printed owner line against stubs and re-runs the review to prove a provision ends in ran = wired) and `scripts/test_doctor_review_scanners.py`.
- `docs/standards-index.md`: the osv-scanner, trivy, semgrep and PyPI sources behind the offline flags and pins, fetched 2026-10-29; the one observed osv-scanner v2.7.0 deviation from its docs (the DB directory is `osv-scalibr/`, not `osv-scanner/`) is recorded there.

### Changed
- `scrub_env.sh` pins `DCR_CACHE_ROOT` (a throwaway dir) and `DCR_USER_BIN` (empty) for every CI test child, so no test depends on which scanners or caches the host has provisioned. A test run by hand on a provisioned host that restricts PATH should set both itself.
- `tool-hub.md`: a Provisioning section (and the pre-seed bullet points at `provision_tools.sh --print`); osv-scanner is described as offline on a warm DB, online only with `REVIEW_OSV=1` (it used to say it stays behind that flag; `method-situational.md` and the `review_checks.sh` header agree), and the unsourced "exits 127" claim is gone (the osv-scanner docs list 127 as a general error only); `full-map.md` routes `provision_tools.sh` and tightens three pointer lines to pay for it, so the file stays 18996 bytes and the mustload floor keeps its pin.
- `test-scanner-offline-db.sh` and `test-review-checks-semgrep-default.sh` pin `DCR_CACHE_ROOT` and `DCR_USER_BIN` themselves, so they keep asserting the cold defaults when run directly on a provisioned host (CI already gets this from `scrub_env.sh`).
- `test_audit_skills.py` triages the new `provision_tools.sh` `net-host` finding (the owner line it prints, never runs, downloads the semgrep `p/default` snapshot from semgrep.dev); the suite is selected by any change to `method-situational.md`, which is how the untriaged finding surfaced.
- `review_checks.sh`: the semgrep `p/default` pack fallback (the pack, from the registry or the snapshot above, errors or hangs to the timeout, so that chunk reruns with the bundled rules) reports the gap once. `semgrep(bundled-only)` counts as partial and as fixable in the closing line and `review-checks-last.json`, beside the NOT RUN entry and the not-checked row, which names `provision_tools.sh --print`; there is no separate `missing tools` line for it. A bundled rerun that also fails leaves semgrep NOT RUN and not fixable (a snapshot would not help). New `scripts/test-semgrep-pack-fallback.sh`; `test-semgrep-registry-timeout.sh` now pins `DCR_CACHE_ROOT` and `DCR_USER_BIN` like the other review tests.
