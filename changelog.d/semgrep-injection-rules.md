### Added
- `perun.js.postgrest-filter-injection` (WARNING, in `.claude/skills/deep-code-review/templates/semgrep-taint/js.yml`): a request value built into the argument of `.or(...)`, when that argument is a template literal or a `+` concatenation, written inline or held in a local variable assigned one earlier in the same block (an assignment inside an `if`, `else` or `try` block, with the call outside it, is not followed), or into the third argument of `.filter(column, "in", ...)` or `.not(column, "in", ...)`. The value is followed through `String(...)`, `.trim()`, TypeScript `as` casts and `await`, and comes from an Express-style `req` or `request` field or, inside an exported app-router route handler, the URL search parameters or the JSON, form or text body. Value methods (`.eq`, `.neq`, `.ilike`, `.like`, `.in(column, array)`, `.match({...})`), an `.or(...)` that takes a call or a schema value (a validation library's `.or(...)`, also with a request value inside the call), constant strings and values passed through `Number`, `parseInt` or `parseFloat` stay clean. An `.or(...)` argument built by a helper call is not followed.
- `perun.js.git-argument-injection` (WARNING): a request value (same sources) that is an element of the array literal passed to `execFile`, `execFileSync`, `spawn` or `spawnSync`, bare or prefixed with `child_process.`, when the first argument is the string literal `git` or a path ending in `/git` and no `"--"` or `"--end-of-options"` element comes before the value in that array. A template literal that starts with the value counts. A terminator before the value, an `if (value.startsWith("-"))` that returns or throws before the call (alone or joined to other conditions with `||`), an all-constant array, a binary that is not git and an element with a constant option prefix before the value (`--opt=${v}`) stay clean. An argv array built elsewhere is not followed.
- `perun.py.git-argument-injection` (WARNING, in `.claude/skills/deep-code-review/templates/semgrep-taint/py.yml`): the same shape for a list literal passed first to `subprocess.run`, `call`, `check_call`, `check_output` or `Popen` whose first element is `"git"` or a path ending in `/git`, with request reads (`request.<x>.get(...)`, `request.<x>[...]`, `flask.request.<x>.get(...)`, `flask.request.<x>[...]`, `request.get_json()` and `flask.request.get_json()`) as sources; plain function parameters and `input()` are not sources. A terminator before the value, an `if value.startswith("-")` that returns or raises before the call (alone or in an `or` condition) and an element with a constant option prefix before the value (`f"--opt={v}"`) stay clean. A list built elsewhere is not followed.

### Changed
- `perun.js.sqli` and `perun.js.command-injection` now also read app-router input, only inside an exported `GET`, `HEAD`, `POST`, `PUT`, `PATCH`, `DELETE` or `OPTIONS` handler (`export async function`, `export function` or `export const NAME = async (...) =>`) with the request as its first parameter: the URL search parameters (through `nextUrl`, `new URL(request.url)` with or without a base, a variable holding the URL, or destructured) and `await request.json()`, `.formData()` and `.text()`; a function that is not such a handler is not a source, and every existing source, sink, sanitizer and guard is kept. `perun.js.sqli` also reports the string passed to `$queryRawUnsafe` or `$executeRawUnsafe` on any receiver, to `sql.raw` and to `sql.unsafe`, and treats a `sql` or `Prisma.sql` tagged template as binding its values, so it is not reported; a template that holds a `sql.raw(...)` call is not treated as safe, so every request value in it is reported, bound ones included. Left out: `sql.raw` and `sql.unsafe` on a receiver not named `sql`, other ORM raw fragments, handlers declared in any other form (a default export, another name), server actions, route-segment `params`, and the app-router sources for the other taint rules.
