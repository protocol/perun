### Fixed
- `pipeline_hub.py` duplicate checks no longer call two different gates a duplicate and no longer print a saving they did not measure. A duplicate is now the same normalized command (script and arguments) in two enforced CI steps. The same script run with different arguments in each step, such as one gate run with `--changed` in one step and `--all` in another, is listed as an advisory (`same suite, different arguments: check one covers the other before dropping`) with no drop advice and no saving; before, both steps were reported as the same suite and the recommendation said to drop one. The hub also stopped printing `saves about X per run (even split over its step's suites)`: the API times whole steps, never one suite, so that figure was the step's median divided by the number of suites in it. A saving is printed only for a step that runs that one command, and then as an upper bound (`saves at most about X per run (its step's median)`); for any other step the recommendation says the suite's own time is unmeasured and to time it locally. The JSON `duplicates` entries gain `identical` (false for an advisory), and `step_p50_s` is null for a step that runs several commands, so `saved_s` sums only the measured copies. Tests: `scripts/test_pipeline_hub.py`.
