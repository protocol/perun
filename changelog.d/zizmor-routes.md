### Changed
- The `review_checks.sh` tool hub now also hands zizmor the Dependabot config (`.github/dependabot.yml` or `.yaml`) and GitHub Actions action manifests (`action.yml` or `action.yaml`, in any directory the hub does not exclude: `node_modules`, `vendor`, `dist`, `build`, ...), not only workflow files, so findings such as `dependabot-cooldown` in a Dependabot config and `template-injection` or `unpinned-uses` in a composite action reach the report instead of never being scanned. Routing is by file name: other YAML such as `config/app.yml` still goes nowhere, and actionlint still reads workflow files only. A changed `action.yml` that is not a GitHub Actions manifest and is the only file zizmor is given makes it collect no input; the run reports that as `NOT RUN: zizmor (exit 3)` with a not-checked row, never as clean. The zizmor row of `references/tool-hub.md` says the same.
- The scanner JSON reader now starts at the first line that begins with `[` or `{`, not at the first bracket anywhere in the output. zizmor logs each path it audits (`INFO audit: zizmor: completed ./x/[]/action.yml`) before its JSON, and the hub merges that log into the file the reader parses, so a bracket in a changed path could hide findings: `pkgs/[id]/action.yml`, `x/{}/action.yml` or a workflow named `[id].yml` made the whole batch unparseable (not run), and `x/[]/action.yml` read as an empty list, so zizmor counted as run with no findings. Those paths now yield their findings.
- Test: `scripts/test-review-checks-zizmor-routes.sh` (registered as `scripts/ci-tests.d/review-checks-zizmor-routes.sh`) runs the hub with a zizmor shim on a hermetic PATH that logs each audited path to stderr before its JSON, as zizmor does. It checks that the Dependabot config (`.yml` and `.yaml`), a nested `.github/actions/setup/action.yml`, a root `action.yaml` and manifests under `x/[]/` and `x/[id]/` are each handed to zizmor and yield a row on that file, and that the files zizmor receives are exactly the workflows (`.yml` and `.yaml`) plus those, so a nested workflow, `sub/.github/dependabot.yml`, `docs/dependabot.yml`, `config/app.yml`, `config/reaction.yml` and `docs/action.yml.md` are not routed. Every case fails on the previous script.
