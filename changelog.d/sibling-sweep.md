### Added
- Sibling-call sweep for incomplete fixes. New `.claude/skills/deep-code-review/scripts/sibling_sweep.py --repo DIR --base REF [--head REF]` finds the functions whose call arguments a diff changes at some call sites and lists the same function's unchanged call sites in non-test code as review leads. This is the shape of a fix that covers one route and misses its sibling: the guard call is edited in the route the report named and left alone in the route next to it. It is stdlib only and read-only: it reads `git diff` and `git grep` against commits, so it needs no checkout and never touches the working tree. A row is the rule `unchanged-sibling-call`, the sibling's file and line, and a message that names the call, the changed site and the old and new arguments. A lead is a place to look, never a finding.
- What it skips and how it caps. Definitions, test paths (also `tests.py`, `test.ts`, `*.mock.ts` and `__fixtures__/`), calls already in the new form, same-named calls in another language and the call whose callback body (not its own arguments) was edited are not leads. A name with more than 25 call sites is not swept, because a common name's sites are noise; the first five such names are listed in the `not-checked` row (the hub keeps rows and drops the script's stderr summary line) and on stderr. Sites whose arguments equal an old form come first. At most 5 leads are listed per function and 30 in all; the rest are counted in one `not-checked` row. At most 40 functions and 300 changed files are read. Known ceilings are written in the script's docstring: the match is by name with no scope or type resolution, so same-named functions in different modules collide, and a changed definition signature is `impact_map.py`'s job (it lists at most 8 references per symbol by default).
- `review_checks.sh --base` now runs it as the `sibling-sweep` step, right after the committed-data step. Rows carry the usual shape and the tool `sibling-sweep`, and the step is listed under `analyzers ran`. It does not run under `--full`, which has no diff, and a missing script gives one `not-checked` row. `method-situational.md` names the step in the Phase-1 analyzer list.
- Measured, read-only, on the first version (before the test-path, keyword-receiver and colour fixes). Replayed on a real fix whose sibling route kept the old arguments, it flagged that route: 1 true miss among its 2 leads. On a sample of 30 recent fix commits across 10 private repositories it ran without error and listed 28 leads (75 before the per-function cap), and none was a missed sibling: the changes were variable renames, a wrapper's own change, same-named helpers in two files and a moved call. Expect most leads to be dismissed in a minute each; the sweep is there for the one that is not.
- New test `scripts/test-review-checks-sibling-sweep.sh` (23 checks, registered in `scripts/ci-tests.d/sibling-sweep.sh`): a fictional repo with a base and a fix commit covers the exact lead rows and their order, every exclusion above, a multi-line insertion and an empty old argument list, a commit-only sweep with the fix not checked out, the refused and unresolvable refs, the hub step (rows, `analyzers ran`, no `--full` run, the missing-script row), both caps, a call far into a long line (still a lead) next to a long comment line (still no call), the over-cap name as a `not-checked` row from the script and through the hub, test paths named by file alone and `__fixtures__/`, a receiver named like a keyword (`proc.wait()`, `impl.run()`: a call, not a definition), git run with `color.ui=always` (the same leads, not none), and the test's own pin of the host's git config and tool dir. 20 of the 23 checks fail on the previous release; the other 3 are negative guards and the pin check, which hold when the step is absent.
