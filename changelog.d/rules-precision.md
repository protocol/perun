### Fixed
- semgrep-taint: perun.js.raw-sql-concat and perun.py.raw-sql-format were too noisy and missed two real shapes. Measured on 108 repos, raw-sql-concat reported 424 hits and 0 of 14 sampled were true (the interpolations were UPPER_SNAKE constants such as ${ROW_COLUMNS} or ${TABLE} next to bound $1 parameters), and the Python rule mostly hit alembic migration f-strings. Both rules now skip UPPER_SNAKE-only interpolations and migration files (`migrations/<digits>*`, `alembic/versions/`); other files that merely sit under a directory named migrations or alembic are still scanned. Two missed true shapes are now caught: a query built in a variable and then passed to the sink (let query = `...${orderBy}`; query += ...; $queryRawUnsafe(query, ...values)), added to the js, py and go raw-SQL rules, and an auth guard with statements before the return (if (!token) { logger.warn(...); return true; }) in perun.js.guard-allows-missing-token and perun.py.guard-allows-missing-token. The messages state the remaining limits (one assignment in the same function, no cross-file or helper flow, receiver matched by name). Test: scripts/test_semgrep_audit_classes.py, new cases fail on the previous rules.
