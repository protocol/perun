### Changed
- Operating layer: `outcome_claim_guard.py` Stop check flags fewer honest replies. A claim word no longer counts when it describes an action rather than an outcome: a finished deliverable ("the audit is done"), a fixed typo or error, a resolved git conflict, triage of "already fixed" issues, or a "pre-merge" check; and a merged tally is skipped when it names a set ("the 40 PRs merged since Monday") or sits beside a backlog count ("12 merged, 30 still open") without a progress word. Each rule skips one claim, never the whole message. On 438 replayed coordinator replies the flags fall 34 to 23; every flag that was an unmeasured outcome claim is still flagged. Default mode stays `warn`. Tests: `scripts/test_outcome_claim_guard.py` (run in CI).
