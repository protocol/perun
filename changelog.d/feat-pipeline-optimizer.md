### Added
- Pipeline optimizer for slow delivery pipelines (commit and push hooks, CI, queue, merge wait): the procedure `agentic-delivery/references/pipeline-optimizer.md` and the stdlib script `agentic-delivery/scripts/pipeline_profile.py`. The conductor owns it as the COO function (flow, timebox, one batched escalation) with the Architect hat as the CTO function (the fix); `agentic-ceo` routes "the pipeline is slow" to it.
- `pipeline_profile.py map` is step 1 and mandatory: it reads hooks, workflows and the documented pre-PR commands into a suite x stage table (commit, push, precheck, ci, train) and flags every suite that runs at more than one stage, with the latest server-enforced gate to keep. `profile` measures per-stage wall time on the critical path, CI queue wait, push-to-merge lead time, reruns, flake suspects, duplicates in seconds and the cache hit rate (counted from job logs only; otherwise `n/a`) from the GitHub REST API plus local timings (`time`, `hooks --run`, `suites --run`), and prints a ranked bottleneck table. When one step dominates it says so and prices sharding from section timings (`--sections`). `fixes` prices a ten-fix catalogue from the profile with duplicate removal first, `compare` keeps a change only if the measured time dropped (exit 0 KEEP, 1 REVERT, 2 UNVERIFIED). A rate-limited API run keeps what it fetched and resumes from its `--data` bundle.
- Anti-stall rules in the procedure: no fix without a profile, one timebox per hypothesis, the measured delta reported at every step, one batched escalation with exact commands.
- Dogfood on this repository's own pipeline, record in `docs/bench/pipeline-1016/`: the profile put 82% of CI execution (10m27s of 12m46s) in `scripts/test-ci-gates.sh`; section timings showed each call of the shipped gate runner re-proving the same seven idempotent selftests (about 45 s per call). `dcr-gates.sh` now stamps a passing selftest once per run (`DCR_SELFTEST_STAMPS`; the key is the script's content hash; a failure is never stamped; an unusable stamp directory means run). Measured locally: full suite 2092 s to 1421 s wall (-32%), 971 s to 564 s CPU (-42%). The CI step is not re-measured yet; the record lists the commands and the kill criteria.
- Evals `pipeline-dedup-before-stage-tuning` (the same four suites at four stages: the answer is dedup, 1300s to 325s, not a faster runner), `pipeline-map-first`, `pipeline-moving-a-gate-is-not-weakening`, `pipeline-timebox-and-batched-escalation`, `pipeline-keep-only-if-time-drops`, `pipeline-local-precheck-breakeven`, `pipeline-dominant-step-drill-down` and `ceo-routes-slow-pipeline-to-pipeline-optimizer`. Tests: `scripts/test_pipeline_profile.py` and `scripts/test-selftest-stamps.sh`, both wired into CI.
- `docs/standards-index.md`: the sources for the catalogue and the measured fields, fetched 2026-10-16 with each quote checked verbatim.

### Changed
- `CONTRIBUTING.md` no longer asks for the full gate suite before a PR (the profile showed a local full run costs more than the CI run it would save); the quick tier stays.
- Clarified in place that moving a blocking check to one later blocking gate is not weakening it, while removing it or making it non-blocking is: `agentic-delivery/SKILL.md` Gates, `references/roles.md` (anti-pattern "Collapsing a gate" and the commit-tier gate table: each blocking check runs once, at the latest gate that still blocks merge), `references/host-enforcement.md` (cost discipline: the local-run break-even) and `deep-code-review/references/method-situational.md`.
