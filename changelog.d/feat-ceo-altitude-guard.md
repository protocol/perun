### Added
- Operating layer: `ceo_altitude_guard.py` (PreToolUse on Edit, Write, MultiEdit, NotebookEdit and Bash, plus UserPromptSubmit) keeps the main session at CEO altitude. It counts the main session's direct source edits per session. Once policy `role` is `ceo` it warns on the 2nd direct source edit and the 4th build/test run in a turn with `delegate: spawn a lane with the brief ...`; `role: ceo-strict` blocks them instead (a JSON deny, never exit 2). Subagents and in-process teammates are never counted, warned or blocked: the host sends `agent_id` only inside them (Claude Code hooks reference, fetched 2026-10-16, logged in `docs/standards-index.md`), and `agent_type` is not used because a `--agent` main session carries it too. The docs do not say outright that the main session omits `agent_id`, so a wrong assumption makes the guard silent, never blocking a lane; a separate top-level lane process sets `PERUN_ROLE=off`. Docs, config, memory, handoff, changelog and temp-dir files are never flagged; a Bash write to a source file (`> f.py`, `tee`, `sed -i`, `perl -i`) counts like an Edit. `ceo:off` in an owner prompt lifts it for that turn. It fails open. Tests: `scripts/test_ceo_altitude_guard.py` (59 tests, run in CI).
- Policy key `role` (`off|ceo|ceo-strict`, default `off`; `ceo strict` is read as `ceo-strict`) in `.perun/policy.json`. Env `PERUN_ROLE` overrides it for one process, and `install.sh --policy role=ceo` writes it. The agentic-ceo skill and `/perun-run` now tell the conductor to arm it.
- `operating_selfcheck.py` prints the drift counter: a `ceo-altitude:` line (role in effect, sessions recorded, direct source edits in all) and one `ceo-altitude-session <id>:` line per recent session of the project, counted even while `role` is `off`. It also reports a `ceo-altitude-guard` wiring item, PRESENT only when both events are wired. `perun_doctor.py` flags an installed guard that no hook calls.

### Fixed
- `heavy_gate.py`: a quoted empty argument (`sed -i '' ...`) no longer splits a shell command into two segments. The tokenizer helpers are now public (`tokens`, `segments`, `strip_wrappers`, `heavy_patterns`) so the guard reuses one copy. Regression test in `scripts/test_ceo_altitude_guard.py`.
