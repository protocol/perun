### Fixed
- trufflehog step: one bad file no longer voids a whole 200-file call. `--fail-on-scan-errors` makes a single unreadable file fail the entire call with no output, so the step reported `not run: trufflehog` and every finding in the other 199 files was lost. A failed call (a crash, a timeout or an unreadable file) is now retried file by file: files that pass alone keep their rows, each file that still fails is one `not-checked` row naming it, and the run is `partial` (`trufflehog(errors)` in the closing line and the record) instead of `not run`. When no file passes alone the tool itself failed, so it is `not run` as before, with the first call's reason. A call that succeeds is never retried, and neither is a one-file call (the retry would be the same call). The retry gives up after three failed single-file runs while none has passed (that chunk is `not run`, with the first call's reason), so a tool that crashes or hangs on every call costs three extra runs per chunk and not up to 200 timeboxed ones; the price is that three or more unreadable files ahead of the first good one also read as `not run` (loud, never clean).

### Changed
- trufflehog now follows gitleaks' noise rules. When the repo has no `.gitleaks.toml` (gitleaks then uses `templates/gitleaks.toml`), the template's skip paths (`.history/`, `fixtures/`, `testdata/`, generated registry JSON, lockfiles) are dropped from trufflehog's file list and counted on stderr: `review_checks: trufflehog template skipped N changed file(s) ...`, in the wording of gitleaks' line. The filter runs on the file list and not through `--exclude-paths`, because on trufflehog 3.99.7 that flag is ignored for files named on the command line (checked on the real binary), so passing it would change nothing. A diff made only of those paths leaves trufflehog no work: it is not called and is not listed as wired or as not run. A repo with its own `.gitleaks.toml` is scanned in full, as before.
- `tool-hub.md` records that `.gitleaksignore` fingerprints and `.gitleaks-allow` hashes do not apply to trufflehog and that an inline `trufflehog:ignore` comment does (checked on trufflehog 3.99.7), and lists trufflehog among the tools that can be `partial`.
- `scripts/test-review-checks-trufflehog.sh` grows from 40 to 67 checks: the stub `trufflehog` gains `TF_BAD` (a call naming that file fails with no output) and `TF_HANGN` (a call naming that many files hangs), and the suite covers the retry, its cap with a tool that crashes or hangs on every call, a 450-file run with one bad file, the template filter and, with the real binary, an unreadable file, `.gitleaksignore`, the inline ignore comment and the template skip. Its fixture path moved from `tests/fixtures/` to `tests/`, since `fixtures/` is now a skipped path. `scripts/test-review-checks-gitleaks-template.sh` matches its skip-count line on `gitleaks template skipped`, because the trufflehog line now has the same wording.
