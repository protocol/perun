### Security
- Release tags can be required to be signed: when `.claude/skills/agentic-delivery/release-signers` (an ssh allowed_signers file) exists, `land-release.sh tag|publish` signs with `git tag -s` and runs `verify-tag` before any push, and `release.yml` verifies the pushed tag object before cutting the release; both fail closed. The signers file is read from the base branch (`origin/main`), never from the tagged tree or working tree, so a tag commit cannot delete or edit the signers to pass. Limit: a tag-push workflow runs the workflow file from the tagged commit, so a hostile tagger can edit the `release.yml` step away; it catches accidental unsigned tags only. The controls that hold are consumer-side `verify-tag` in `perun_auto_update.py` against the installed signers file and an admin-only `v*` tag ruleset. The first signers file reaches consumers through an update that could not yet be verified (trust on first use). Without the file on the base branch, behavior is unchanged.
