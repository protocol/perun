### Added
- Semgrep rules `perun.js.webhook-no-signature-verify`, `perun.js.webhook-nest-no-signature-verify`, `perun.js.webhook-next-no-signature-verify`, `perun.py.webhook-no-signature-verify`, `perun.py.webhook-fastapi-no-signature-verify` and `perun.go.webhook-no-signature-verify` (`templates/semgrep-taint/webhook.yml`) flag webhook handlers (Express, NestJS, Next.js, Flask, FastAPI, Django, Go net/http) that read the request body and never call a signature verifier. Entry points are a "webhook" name or a `/webhook` or `/hooks` path segment; GET-only routes are skipped. Computing an HMAC does not clear a handler, only a constant-time compare or a vendor verify call does, so `createHmac(...)` or `hmac.new(...)` compared with `===` or `==` is flagged. Annotated vulnerable, clean-twin and mutated fixtures live in `scripts/test_semgrep_webhook.py`. A handler clears only on crypto evidence (`timingSafeEqual`, `compare_digest`, `hmac.Equal`, `subtle.ConstantTimeCompare`, `tsscmp`, `scmp`, `safeCompare`, `constructEvent*`, `ValidatePayload`, or `verify(` with a signature or raw-body argument) or a verb-led name containing signature or hmac (`verifySignature`, `checkSignature`, `@require_signature`, `Depends(...)`, `@UseGuards(...)`, DRF classes), so `verifyToken`, `verifyEvent`, `checkSenderIp`, `computeSignature(body) ===` and a bare `verify(x)` are still flagged; a bare verifier as an options or array value (Fastify `preHandler`) clears; `ctx.request.body`, `this.request.body`, `flask.request.get_json()`, `const {body} = req` and `app.route(path).post(h)` count as body reads. Known limits: a custom helper elsewhere is a false positive (suppress with `nosemgrep`), a verifier-looking string or comment clears, `fastify.route({url, handler})` is not seen. `verify(` and `isValidRequest(` clear only when an argument names sig, signature, rawBody or raw_body (so `jwt.verify(token, JWT_SECRET)` is flagged), or on a `Webhook(secret).verify(...)` receiver; only the exact `constructEvent`, `constructEventAsync` and `construct_event` names clear; decorator and `Depends(...)` names must be verb-led; webhook paths match case-insensitively; in a NestJS `@Controller` a verifier clears only its own `@Post` handler, and a bodyless `@Post` does not fire. An Express/Koa-style route call needs a function-literal handler, so an outbound `axios.post(SLACK_WEBHOOK_URL, ...)` is not flagged; a svix `Webhook` receiver built in the handler clears whether `.verify(...)` is chained or called later (`wh.verify(payload, headers)`). `sig` counts only as its own word (`sigHeader`, `SIG_HEADER`, not `consignmentId` or `SIGNING_KEY`); `verifyAndReceive(`, Twilio `validateRequest(`/`validate(` with a signature argument and slack `is_valid_request(` clear; a flag read such as `if (config.verifySignature)` and a Python `def _verify_signature` that is never called do not. NestJS `@Put`/`@Patch` and `@Body("key")`/`@Body(pipe)` fire, and a class-level `@UseGuards` naming a signature or hmac guard in any position clears both JS rules. FastAPI `Optional[Model]` and `Annotated[Model, Body()]` parameters fire, a GET `api_route` is skipped, and Go `ServeHTTP` on a webhook-named type fires.
