### Changed
- When semgrep reports errors on some of the files it scanned, the `review_checks.sh` tool hub now names those files instead of only saying the scan was partial. Each file with an error is a `not-checked` row (its path, line 0, and the error type and level), at most 20 per 200-file semgrep call, followed by one row with the path `.` that counts the rest and names the first path left out, so two calls with equal error counts keep one such row each instead of the closing dedup of identical `not-checked` rows merging them into one. An error that carries no path stays counted and gets no row. The `review_checks: partial: semgrep ran but reported errors (...)` line on stderr keeps its text and now ends with the error counts, for example `(3 error(s) on 2 of 40 scanned file(s): PartialParsing (warn) x2, Syntax error (error) x1; see not-checked rows)`. The type is semgrep's `type` string, or the first element when it is a list. A warn-level parse error still makes the scan partial and is never read as clean. Whether a scan is partial or not run is decided on the findings alone, before these rows are added, so the "not run" cases (errors on every scanned file, or an error with no path and no findings) are unchanged and name no file. The header comment of `review_checks.sh` now matches.
- The closing summary on stderr no longer counts `not-checked` rows as findings: `review_checks: N findings; ...` counts every other row, and a separate line, `review_checks: K not-checked row(s) (surface a tool did not cover, not findings)`, gives the number of `not-checked` rows and appears only when there are any. The line that reports how many rows are on lines the diff adds still counts every row.
- Test: `scripts/test-review-checks-semgrep-partial.sh` (registered as `scripts/ci-tests.d/review-checks-semgrep-partial.sh`) runs the hub against a stub semgrep that answers each call with its own fictional JSON. It covers a warn-level `PartialParsing` on 1 of 3 files (one row for that path, the counts on the partial line, the finding row unchanged), 25 errored files (20 rows plus the summary row, counts ordered by count), two semgrep calls (200 and 30 files) with equal error counts (two summary rows and two partial lines), the findings count and the separate `not-checked` line, several errors on one file, errors with no path, the "not run" cases, and odd error shapes (a null or string entry, a missing type or level, a path that is not a string, a control character in a path) that must not void the chunk's findings.
