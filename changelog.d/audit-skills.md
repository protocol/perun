### Added
- `scripts/audit_skills.py`: a read-only, stdlib supply-chain auditor for an installed skills directory. It scans every file (SKILL.md, references, templates, scripts, hooks, dotfiles; only `.git/objects` is skipped) for a network fetch run as code (piped to a shell or interpreter, `eval`/`source` of a fetch, fetch then `&& sh`), calls to hosts outside an allowlist (`--allow-host` extends it; userinfo tricks like `github.com@evil.test` are judged by the real host), bidi, zero-width and tag characters in content and file names, base64-decoded execution and PowerShell encoded commands, writes to agent settings, MCP config, CLAUDE.md/AGENTS.md, hooks, shell rc and credential files, `rm -rf` on root, home, globs or variable-prefixed paths, and instruction-override phrasing. Binary, oversize and symlinked files are reported as `unscanned`, never skipped silently. The skill under audit cannot silence its own findings: `audit-skills: ignore <rule>` markers apply only with `--honor-markers` (for your own skills) and only to the named rule. Exit 0 clean, 2 findings, 1 error or usage error; `--json`; each finding carries a severity and file:line. Bench `scripts/test_audit_skills.py`: 89 fictional malicious and 51 benign skill folders generated at test time, recall 89/89 (asserted exact) and 0 false positives on those author-written fixtures (a regression guard, not an independent estimate), under 30 s. This repo's own skills raise 21 findings, all triaged in the test with a reason and pinned per (file, rule) count (guidance and guard denylists that name the pattern, one oversize eval corpus; none execute it). Scheme-less fetch hosts, unreadable directories (exit 1), directory names, long-option `rm`, system-directory `rm`, skill-install and rc/git-config writes, variation-selector and soft-hyphen smuggling are covered; the allowlist names well-known origins, not trusted content, and the phrase lists are heuristics (both stated in `--help`).
