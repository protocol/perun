### Added
- `perun.js.xss-url` (WARNING, in `.claude/skills/deep-code-review/templates/semgrep-taint/js.yml`): `location.search` or `location.hash` (also under `window.` and `document.`, or destructured from `location` or `window.location` with `const`, `let` or `var`), read through `new URLSearchParams(...).get` or `.getAll`, `decodeURIComponent`, string methods, a `??` default, template literals and concatenation, into `.innerHTML =` or `+=`, `.outerHTML =`, the second argument of `.insertAdjacentHTML`, `document.write`, `document.writeln`, the `__html` value of an object literal (so `dangerouslySetInnerHTML={{ __html: ... }}`) or an assigned `.__html` property. `textContent`, `innerText`, a redirect through `location.href` or `location.assign`, `pathname` and `href` reads and constant strings stay clean. Not followed: an alias such as `const loc = window.location`, a renamed destructuring such as `{ search: s }` and a sink inside a helper function; a value placed inside an inline script string after `encodeURIComponent` is treated as safe.
- `perun.js.xss-response` (WARNING): `request.nextUrl.searchParams` or `new URL(request.url).searchParams`, with or without a base argument as in `new URL(request.url, base)` (any handler parameter name, read directly, through a variable or destructured), into the first argument of `new Response` or `new NextResponse` when the same call sets a `content-type` header in an inline object literal to a string literal that starts, after optional spaces, with `text/html` in any case. `Response.json`, `NextResponse.json`, a call with no init and a `text/plain` or `application/json` type stay clean. Headers built elsewhere (a variable, a `Headers` object, a helper) and route params are not followed.
- `perun.js.xss-markdown` (WARNING): the result of `marked(...)`, `marked.parse(...)`, `marked.parseInline(...)` or a showdown converter's `.makeHtml(...)` on an argument that is not a string literal, into the `__html` value of an object literal (inline in `dangerouslySetInnerHTML` or in an object built first), an assigned `.__html` property or the HTML sinks of `perun.js.xss-url`. A markdown-it `render` call stays clean, and so does markdown read straight from `fs.readFileSync` or `readFile`, as the argument or through a `const` declared from it, whatever the path, so a read of a user-chosen file path (uploads included) is skipped like repo content. A variable declared with `let` or `var` (reassigned or not), a read through a helper and a front-matter parser are still reported. Fetched data without markdown, other markdown libraries and a value returned from a callback such as `useMemo` are not followed. `DOMPurify.sanitize`, `sanitizeHtml`, `escapeHtml`, `encodeURIComponent`, `Number`, `parseInt` and `parseFloat` clear the value in all three rules.
