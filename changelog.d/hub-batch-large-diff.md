### Fixed
- review_checks.sh diff mode no longer runs gitleaks and jq once per changed file on a large diff. On a 95.7k-file diff, per-file gitleaks took 3,875 s for 65.5k files and per-file jq took 528 s for 52k files. When the changed-file count exceeds `REVIEW_BATCH_MIN` (default 200), it now runs one batched gitleaks scan (same config precedence, allowlists and `.gitleaksignore` as the per-file path; both paths now use one BASE-derived gitleaks config. Real gitleaks 8.30 loads no repo `.gitleaks.toml` for a single-file scan, so the old per-file path silently ignored BASE rules and allowlists (it was never PR-allowlistable); it now applies BASE's `.gitleaks.toml`, and a PR-edited copy is ignored on both paths. In diff mode the batch scans a temp copy of only the changed files, not the whole tree, and `--full` keeps the whole-tree scan; vendored trees skipped, findings filtered to the changed files) and validates JSON in one python3 process (stricter than jq: NaN, Infinity, a UTF-8 BOM or invalid bytes send the file to jq), calling jq only on the files that fail so rows and messages are unchanged. Diffs at or below the threshold behave as before.
