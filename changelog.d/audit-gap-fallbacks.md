### Fixed
- `review_checks.sh`: when osv-scanner and trivy give no dependency result (DB unreachable in a sandbox or offline, not installed, lease full), the ecosystem's own audit now runs per lockfile (`npm audit --package-lock-only` for `package-lock.json`, `pnpm audit` for `pnpm-lock.yaml`, `pip-audit -r` for `requirements*.txt`) and a `review_checks: dependency scan: <tool> ran for <lockfile>` line names which one ran; its findings land in the JSON under that tool. Coverage is tracked per lockfile (osv-scanner success, or a trivy `Target` for that lockfile), so one covered lockfile never hides another that was not scanned. Like osv-scanner it is opt-in (`REVIEW_OSV=1` or `REVIEW_OSV_DB_DIR`) because it queries the registry. The audit runs on a copy of the lockfile in an empty temp dir with the public registry and no user or global npmrc (a repo `.npmrc` registry or credentials are never read), and `pip-audit` gets `--no-deps --disable-pip` (no resolver, no venv, no target code). The tool counts as ran only after its output parsed. A changed lockfile with no dependency scan at all (opt-in unset, fallback tool missing or unreachable, unparseable output, or no fallback for the ecosystem such as `yarn.lock` or `Cargo.lock`) now yields a `dep-scan` `not-checked` row instead of a silent clean. A trivy secret-only run no longer counts as a dependency scan.
- `full-audit.md`: new "Run conditions" section covering testing without an install (reuse an existing `node_modules` read-only, else report tests not run), a target repo whose `CLAUDE.md`/`AGENTS.md` bans agent commits or pushes (stage only, hand the owner the commands), loading the skill from the release checkout rather than a stale global copy, and that no dependency scan is "not checked", never "clean".
- New test `scripts/test-review-checks-dep-fallback.sh` (also pins that semgrep gets a writable `HOME` when the real one is read-only), registered in `scripts/ci-tests.d/`.
