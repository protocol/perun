### Fixed
- The `install.sh` end-of-run summary no longer lists a running session's transcripts (`.claude/projects/`), its todos (`.claude/todos/`) and other files outside the paths install writes as "Generated". It found the files a run wrote by scanning whole host dirs (`.claude`, `.cursor`, `.agents` and the other hosts) for anything newer than the run's start stamp, so under a home target those files appeared as if install had created them. It now scans only the subpaths install itself writes: the installed skill dirs, each host's `skills/INDEX.md`, `.claude/commands`, `.claude/agents/delivery-lane.md`, `.claude/house-defaults.md`, the install record and flags files, `settings.local.json` and the `.new` and `.bak` siblings of the settings files, the CI-gate files and their `.new` siblings, `.perun/policy.json` and `AGENTS.md`. The rows for a project target are otherwise unchanged; the one difference is that `.github/skills/INDEX.md` and `.github/workflows/dcr-gates.yml` no longer print twice with `--with-extra-hosts --with-gates`, because `.github` used to be a scan root twice. The summary still lists another process's write to a path it does scan: a new file in `.claude/commands` (scanned whole) or an edit to `.claude/settings.local.json` during the run; an exact per-file record of what install wrote would lift that limit.
- `scripts/test-install-hygiene.sh` gains 6 cases (15 in all). Two plant files with a 2099 mtime, one each in `.claude/projects/` and `.claude/todos/`, and a generic stray in every host dir and in `.perun`, `.githooks`, `scripts` and `.github/workflows`, and assert none of them appear in the summary (both fail on the previous `install.sh`). One asserts that every file a `--full --with-gates --with-terse-replies --with-extra-hosts --with-codex` install wrote, the policy and settings files included, still appears, and one asserts a `(N files)` row for every installed skill dir. Two install into an existing target with edited gate files, a `settings.local.json` and a stale operating-layer `.new`, and assert the `.new`, `.new-1`, `.bak` and local-flags rows appear, so dropping a trailing `*` from a scan root fails. The installs run with `PERUN_ROLE` unset.
