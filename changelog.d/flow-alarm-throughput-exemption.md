### Added
- At the cap, the stop-starting hook (`.claude/skills/agentic-delivery/scripts/flow_alarm.py`) now lets through one lone `gh pr create` of a branch already pushed to origin when its diff against `origin/<base>` holds only throughput paths and fewer than `PERUN_THROUGHPUT_OPEN` (default 2) such PRs are open. The hook used to deny test-runtime cuts and CI parallelism along with everything else, and the only override was the free-text `# priority:` marker, which a project may restrict to a human approver, so the work that would shorten the queue waited behind it. The exemption is a grant: whatever the hook cannot judge keeps the deny. It judges a command only when its words start `gh pr create` (or `new`) and hold no operator (`;`, `&&`, `|`, `&`, a newline, a redirect, a heredoc), no word holding a `$`, `*`, `?`, `[`, `{` or backtick (the shell may expand it into other words, and quotes are not seen, so a quoted title with one of them keeps the deny too), no word that starts `#`, no `-R`, `-H`, `--repo` or `--head`, and no bundled or joined short option (`-dB`, `-Brelease`). A command that switches branch, pushes or changes directory first, a second create, a body built with `$(...)`, a brace word that expands into a later `--base` or `--repo`, a glob that expands into a file named like an option, a comment that looks like an option, and a PR for another repo or head are therefore denied. The base is the last `--base V`, `--base=V` or `-B V`, else `origin/HEAD`; a `gh-merge-base` branch config with any non-empty value and no `--base` keeps the deny. The changed files are `git diff --name-only` from the merge base of `HEAD` and `origin/<base>`, read in the hook's `cwd` with rename detection, `diff.relative` and submodule hiding turned off, so a product file moved into `tests/` or a submodule bump still counts. `HEAD` must be the one commit that `refs/remotes/origin/<branch>` points at, with no other remote ref there, so the ledger name is the head name the PR will have; an unpushed branch, or a pushed copy ahead of or behind `HEAD`, is not judged. `git remote` must list no remote but `origin`, and every value of `remote.origin.gh-resolved` (written by `gh repo set-default`) must be `base`, or none set: gh opens the PR on its own base repo and prefers a remote named `upstream`, so with another remote or another default repo the diff read against `origin/<base>` may not be the PR's diff, and the deny stands. Remote names, ref names and config values are compared whole, split only at a newline (config values at a NUL, since a value may hold a newline): git allows U+0085, U+2028 and Unicode spaces in a name, so `origin` plus one of them is another remote or ref. The default paths are test directories and files, CI config and test-runner config; `PERUN_THROUGHPUT_PATHS` (comma-separated globs) replaces them. Below the cap, and with `# priority:`, nothing changes.
- The deny stands, as before, for an empty diff, a path outside the list, a git call that fails or takes over 5 seconds, and any error while judging (only reading the queue still fails open). A grant is appended to `<git-common-dir>/perun-throughput.jsonl`, and the exempt PRs open are the ledger branches among the open PRs' head names, which the single `gh pr list` call now also returns (`headRefName`), so there is no second `gh` call.
- Every deny is appended to `<git-common-dir>/perun-flow-denials.jsonl` as `{"at","class","ready","cap"}`: class `throughput-cap` when only the exempt cap blocked a judged branch, else `work`. The log holds no file names or command text, and a write error is ignored.

### Changed
- The deny message names the exemption as a lone `gh pr create` (body in `--body-file`) of a branch already pushed to origin, while fewer than N such PRs are open, with N the parsed `PERUN_THROUGHPUT_OPEN`; when that value is not a number the clause is left out. The module docstring said `Side effects: none (read-only)`, which would now be an over-claim; it names the two appends and the judging rules. `.claude/skills/agentic-delivery/references/flow-guards.md` gains two sentences on the exemption and the denial log.
- Limits, listed once in the script docstring: the globs match names, not contents (a CI-config edit passes whatever it changes, and `spec/`, `*.spec.*` and `test_*.py` can name product files, so narrow the list with `PERUN_THROUGHPUT_PATHS`); only creation is judged; the ledger is local; two sessions can race for the last slot; a `GH_REPO` exported in the shell is not seen; with more than 100 open PRs an exempt PR can fall outside the list.
- Tests: `python3 scripts/test_flow_alarm.py` goes from 22 to 68 tests. The new `Throughput` class runs the hook against a throwaway repo under a hermetic git environment (no user config, a fixed identity, no repo search above the temp dir) with a fake `gh`; every grant case pushes its branch first. It covers each shape above (bundled and joined options, another repo or head, two creates, a branch switch, push or `cd` first, an expansion, a substitution, a heredoc, a comment, a line continuation, a brace word, a glob word, a second remote, a remote or ref name that only looks like `origin`, a default repo set to another repo or to several values, a repeated or empty `--base`, a configured merge base with one value or several), an unpushed branch, a pushed copy behind or ahead of `HEAD`, a second remote ref, `diff.relative` and a submodule under a hiding config, the exempt cap, the path list and the denial log, and the message with a number and with a value that is not one. The existing tests now run in a plain temp dir, so they neither touch the real repo nor write its denial log.
