### Fixed
- `review_checks.sh`: with a warm provisioned semgrep snapshot (`provision_tools.sh --cache semgrep`), the rule ids of the snapshot's rules kept the dotted path of the local cache directory as a prefix, because only the bundled rules' directory was handed to the rule-id normaliser. Both directories are now stripped; a registry pack (`p/default`) has no local path and adds none. Test: the rule ids block of `scripts/test-review-checks-scanner-gaps.sh` (stub semgrep, throwaway `DCR_CACHE_ROOT` holding a `rules:` snapshot).
- `comms_lint.py` `audit-pr`: the attribution footer a PR body ends with (a line starting with 🤖, or a `---` rule and what follows it) was read as part of the last section, so a compliant body whose last section is `## Not fixed` failed "Not fixed carries detail ('https://')". The footer now ends the section, and a `---` rule or `🤖 Generated` line counts as a footer only when nothing but footer lines follows it, so text after a rule is still checked. Test: the `Footer` class in `scripts/test_audit_pr_body.py`.
- `identity_gate.py`: the `--remote` help said the remote was used "for the no --base case"; its tracking refs are excluded from the pushed range with or without `--base`.
