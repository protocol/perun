### Security
- review_checks.sh runs slither from its private temp dir instead of the reviewed repository. crytic-compile, even with `--compile-force-framework solc`, walks up from its process working directory to a `foundry.toml` or hardhat config and runs the solc binary that config names, so a committed `foundry.toml` with `solc = "./tools/solc"` made a default review execute a repository binary. The target is now passed as an absolute path with `--solc-working-dir` set to the repository root (imports still resolve there), SARIF paths are mapped back to repository paths, only the changed file's rows are kept (a row for an imported file is no longer pinned on the changed file's line numbers), a row outside the repository is not run, and a temp dir inside the repository, or a crytic-compile framework marker (foundry.toml, a hardhat, buidler, truffle, embark, brownie or waffle config, a Makefile naming dapp, a package.json naming etherlime or ethereum-waffle) in any ancestor of the temp dir such as a shared /tmp, is NOT CHECKED. Dropping the other files' rows is by design: a finding slither places in an imported or inherited file, even one the change triggers, is dropped; only that file's own run, as under --full, reports there, and a finding that needs the importing contract may not recur in it. Tests: scripts/test-review-checks-hub-slither-cwd.sh, with a live probe against the installed slither (stub forge and solc) whose positive control runs `./evil` from the repository root; the live probe skips where slither is not installed, as on CI.
- secret_exposure_triage.py reads history with `git log -p --no-textconv --no-ext-diff --no-show-signature`, so neither a repository's `.gitattributes` diff driver nor the `gpg.program` behind its `log.showSignature` runs, and a diff driver cannot hide a secret from the first-seen search. Test: scripts/test_secret_exposure_triage_textconv.py.
