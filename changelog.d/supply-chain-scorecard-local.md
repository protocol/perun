### Added
- `supply_chain_check.sh` scans a git DIR with OpenSSF Scorecard offline when `--scorecard owner/repo` is not given; before, that run printed `SKIPPED scorecard`. It exports the repo root's HEAD (`git archive HEAD`, tracked files only) and runs `scorecard --local` on the export, so an untracked `node_modules` cannot score Binary-Artifacts 0. The export is removed afterwards, also when the run is stopped by SIGTERM, SIGHUP or SIGINT. Only the checks that work offline run: Binary-Artifacts, Dangerous-Workflow, Dependency-Update-Tool, License, Packaging, Pinned-Dependencies, SAST, Security-Policy and Token-Permissions. Vulnerabilities is never included because it reported a false 10 ("0 existing vulnerabilities") while api.osv.dev was unreachable, and Fuzzing errors offline. Scores stay informational with no pass/fail threshold, as in the remote mode, and the `ok scorecard` line says the offline view is partial and not comparable with a public Scorecard score. A subdirectory DIR scores the whole repo root, and the same line names the root and says so. `git archive` runs with `GIT_NO_LAZY_FETCH=1`, so a partial clone that is missing blobs is SKIPPED with a reason naming the partial clone instead of fetching over the network. A non-git DIR or a repo with no commit is also SKIPPED with the reason (exit 3 unless `--allow-skip`), and `--scorecard owner/repo` keeps the remote scan. The `supply-chain-check.md` table row and the script header say so.
