### Added
- `reaper_lint.py` gains the rule `LINUX_ONLY_NO_PREFLIGHT`: a command line whose command word is `setsid`, `flock` or `timeout` with at least one argument (the first word after shell keywords, `sudo`, `nohup`, `env`, `time`, `nice`, `exec`, `xargs`, `command`, `stdbuf`, `ionice`, `chrt`, `taskset`, `NAME=value` and a Makefile recipe's leading `@`, `-` or `+`), or that has a bare `/proc/<path>` word or redirect source, fires when the file has no platform preflight. A stock macOS install has none of those tools and no procfs, so a gate that calls one exits 127 or reads nothing there and posts FAIL for a check that never ran. A preflight anywhere in the file clears the line: `command -v`, `type`, `hash` or `which` naming that tool; any `uname`; `$OSTYPE` or `${OSTYPE`; a `-e`, `-d`, `-r`, `-f`, `-s` or `-x` test on a path (a `/proc` path clears `/proc`, a path to the tool clears the tool); the tool run as its own probe (`--version` or `--help` as its only argument, or `true` or `:` as its whole payload, as in `timeout 1 true`). Only commands are read: heredoc bodies, multi-line quoted strings, `package.json` text outside `scripts`, text after a `$(...)` inside double quotes, arithmetic, Makefile and justfile assignments, and `/proc` as a `find` operand, a `grep`, `sed` or `awk` pattern, or a word `echo` or `printf` prints do not fire. YAML files, hook configs included, are skipped (a CI step runs on its runner's OS) and the usual `# reaper-lint: allow <reason>` marker suppresses a line. The docstring names the residuals, among them `sh -c` strings, `find -exec` tails, option-argument wrappers such as `nice -n 10`, a preflight in a sourced file or a wrapper function, and preflight clearing that is file-wide and blind to mentions.
- `lang-shell.md` gains one bullet, "A gate that calls a Linux-only tool turns red on macOS for a check that never ran", after the `env` bullet; it ends by routing to the rule.

### Changed
- A repo that opted in to the gate (`DCR_REAPER_LINT=1`) and has an unguarded Linux-only call goes red on upgrade, until it adds a preflight or a `# reaper-lint: allow <reason>` marker.
- Tests: `python3 .claude/skills/deep-code-review/scripts/reaper_lint.py --selftest` (already run by CI) goes from 90 to 185 cases: each Linux-only tool and `/proc` shape that fires, each preflight form that clears it (a tool self-probe included), the command-word handling (wrappers, `NAME=value`, a Makefile recipe's `@`, `-` and `+`, a `for` word list, a `grep` argument, a quote split at `$(`), and each non-command the rule leaves quiet (heredoc and multi-line string bodies, JSON prose, text after a quoted `$(...)`, arithmetic, Makefile and justfile assignments, `/proc` as a pattern, `find` operand or printed word). Every earlier case keeps its result.
