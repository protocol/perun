### Added
- `scripts/run-ci-tests.sh --affected` now records a receipt for every run, pass or fail, through lkg.py's internal `record_affected_cli` entry, which only the runner uses and which is no CLI subcommand (kind `affected`, `<hash>.<tree>.affected.json`, never the last-known-good pointer, pruned after 7 days). It holds HEAD, the working-tree tree hash taken before any suite runs (`lkg.py tree`: `git add -A` into a temp copy of the index, so tracked, staged and untracked-unignored files count and the real index is untouched), the base, the blob of `scripts/run-ci-tests.sh` as it ran, each selected suite and its exit code (`-` for a suite the fail-fast runner never reached) and the overall code. The tree is re-hashed after the suites: a suite that changed it leaves no receipt. A lane's hand-back could claim a pass the runner never produced (a claim of 44/45 for a head where one suite failed); the receipt is what makes the claim checkable.
- Receipts work inside the agent sandbox, which denies `~/.cache`: they are written to and read from the first writable of `<git common dir>/perun`, `$TMPDIR/perun`, then the landing cache dir (reads take the newest across all three).
- `scripts/run-ci-tests.sh --list-affected [BASE]` is the dry form of `--affected`: it prints `selected: <suite>` per suite and runs no gate, suite or receipt. `lkg.py affected-check <tree> [BASE]` uses it to re-derive the selection for the tree and requires every selected suite at rc 0 and the receipt's runner blob to be the tree's, so a hand-written receipt that lists some suites (or another runner) is refused, and a receipt missing a key is skipped, never a `KeyError`. Exit 0 pass, 1 refused, 3 could not verify (no writable receipt location, an unreadable receipt file, or a failed re-derivation). The local receipt stops honest, stale and partial over-claims; a deliberate forgery needs CI proof, and CI is the authority.
- `handback.py --body-file` now flags a line that claims a full test pass (`run-ci-tests`, `--affected`, `Tests: N/N` or `Tests N/N`, "N tests passing", beside pass, passing, green, ok, any `X/X` or a tick, so "44/45 pass; rerun 45/45 pass" is a claim) unless `lkg.py affected-check` accepts a receipt for the head's tree (re-derived against the merge-base of `--base`) or the head is the last-known-good. It prints `unverified test claim (no receipt for this tree)` (or `receipt for this tree failed: <suite> rc=1`) per line and exits red (`handback RED: test claim`). Honest prose is not a claim: "not passed", "did not pass" and "2 of 3 passed" are ignored. "added 2 tests; lint ok" is not a claim. When no receipt location is writable, the tree or merge-base does not resolve (the receipt's own base is never used instead), or the receipt file cannot be read, the claim reads `test claim could not be verified` and the hand-back exits 3 (UNVERIFIED), never red. Error text shows the home directory as `~`. Test: `scripts/test_affected_receipt.py` (registered in `scripts/ci-tests.d/affected-receipt.sh`).
