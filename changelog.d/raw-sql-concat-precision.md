### Fixed
- semgrep-taint: perun.js.raw-sql-concat no longer reports interpolations that only build bind-parameter indexes, quoted identifiers or fragments assembled from literals. Skipped now: params.length, n + 1 / i * 2 + 1 style index arithmetic (a plain name plus digits, single letters or CONSTANTS), the length returned by x.push(...), ident()/quoteIdent()/escapeIdentifier() calls, a .map(... => `$${n}`).join() placeholder list, a plain variable named like a SQL fragment (whereSql, idClause, tuples) and sets/conds/clauses/parts.join(...). A tainted fragment is still perun.js.sqli's job; dotted values such as req.query.orderBy or req.params.id + 1 are still reported, and so are plain names such as order, orderBy, limit and offset, because a sort direction or page size passed in as a function argument is a common injection path. Measured on the 7 repos that had hits in a 216-repo sweep: 112 rows before, 68 after; 15 of the 68 are plain order, orderBy, limit, offset or team values, kept on purpose. Of 16 sampled rows, 11 were false (parameter placeholders, an allowlisted table name, a quoted identifier); the 5 true ones (a hand-escaped value, an env value, a function-argument table name, two Prisma.raw splices or DDL names) all still fire. Test: scripts/test_semgrep_raw_sql_precision.py (live ruleid/ok fixtures plus an offline check of the shared regex).
