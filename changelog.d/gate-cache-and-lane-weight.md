### Added
- `deep-code-review/scripts/gate_cache.py`: one PASS cache shared by every gate stage (pre-commit, pre-push, a precheck script, the merge-train gate), keyed by (git tree SHA, gate-set version, config hash) under `<git-common-dir>/perun-gate-cache/`. A tree that already passed the same suite prints one line, `cached PASS <tree>`, and skips it, so whichever stage reaches a tree first runs the suite and the others skip. Only an exit 0 is ever recorded: a FAIL, a dirty or untracked tree, an unmerged index, or a run that edited tracked files is never cached and simply runs. Entries are ignored after 7 days and deleted on the next write. Editing any hook file, the cache script, a path in `$PERUN_GATE_FILES` or `$PERUN_GATE_SET_VERSION` is a new gate set that misses every older entry; `$PERUN_GATE_CACHE_KEY` folds in a toolchain fingerprint. `PERUN_GATE_CACHE=0` opts out, `PERUN_GATE_CACHE=refresh` reruns and re-records. Wire any stage with `gate_cache.py run --stage NAME -c '<suite>'`.
- `deep-code-review/scripts/gate_map.py`: a read-only report of which suites each stage runs (pre-commit, pre-push, precheck, the train gate from `$VERIFY_CMD`/`$BASE_AUDIT_CMD`/`$BROWSER_CMD`/`$RATCHET_CMD`, or any `--stage NAME=PATH`), tagged cached or uncached. It flags a command that runs in two or more stages and says what to change: wrap the uncached stages, or set `DCR_PREPUSH_TREE_PURE=1` when the scopes differ. It writes nothing and runs no suite.
- `perun_policy.py heavy-acquire --kind light` and `perun_policy.py heavy-load`: a lease can declare a light kind (a read-only or doc lane), and `heavy-load` prints the weighted live-lease count.
- Tests: `scripts/test_gate_cache.py`, `scripts/test_prepush_gate_cache.py`, `scripts/test_train_gate_cache.py`, `scripts/test_gate_map.py`, `scripts/test_lane_weight.py`.

### Changed
- `pre-push-verify.sh` asks `gate_cache.py` before running `DCR_PREPUSH_CMD`, replacing the per-commit stamp under `dcr-prepush-stamps/` (that directory is now unused and can be deleted). The tier stays range-aware by default, so its key still includes the pushed range: `dcr-gates.sh` reads commit messages through `BASE_SHA`/`HEAD_SHA`, so a reworded commit or a different base must not share its verdict (the #1153 rule). Set `DCR_PREPUSH_TREE_PURE=1` when the tier is a pure function of the tree (lint, unit tests): the verdict is then shared across amends and with every other stage that runs the same command text through `gate_cache.py`. `DCR_PREPUSH_SKIP_CACHE=1` still forces a rerun and refreshes the entry; `DCR_PREPUSH_CACHE_KEY` is still folded into the key; without python3 or the script the tier runs uncached.
- `train_land.sh` (`BASE_AUDIT_CMD`) and `merge_train.py` (the `--verify-cmd` union gate) consult the same cache, so a base or union tree that already passed the same command is not re-tested; a failed union is never persisted.
- The heavy-lease count that `heavy_gate.py` compares with the slot cap is now weighted: a lane that declares `light` (or, with no declaration, one whose process tree measures under 15% of a core once its lease is 60 seconds old) counts a quarter of a heavy lane, so three light lanes plus one heavy lane no longer fill a four-slot host. A lane that cannot be classified (no `ps`, a young lease, an unknown kind) counts as heavy. `host_probe.py --live-lanes` accepts the weighted fraction.
