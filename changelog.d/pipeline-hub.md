### Added
- `agentic-delivery/scripts/pipeline_hub.py`: one entry point for the first read of a slow delivery pipeline (issue 1559). It prints per-workflow p50/p90 wall time, the slowest jobs, suites run by two or more CI steps, re-run and flake counts per job (from the earlier attempts of re-run runs), red rate, and PR lead time (open to merge p50/p90 plus push-to-merge), then one recommendation per finding that names the workflow, job or step. It reuses `pipeline_profile.py` (workflow reader, suite keys, lead metrics) and `gh_rest.py`; the job table comes from the `gh-workflow-stats` extension when installed and from `gh api` otherwise (the extension's JSON shape is read from its source and tested on a fixture; it was not run live). `docs/standards-index.md` logs the tools fetched and why DORA, flake and duplicate-job tools were not wired. It refuses a `--root` that is not a checkout of `--repo`, flags a duplicate only between enforced check steps (a build step or a post-merge push copy is not one), matches jobs on workflow and name, shows flakes as n/a when a re-run's earlier attempts were not fetched, and exits 2 with one message on bad input. Routed from `references/pipeline-optimizer.md`. Tests: `scripts/test_pipeline_hub.py`.

### Fixed
- `gh_rest.py`: behind an HTTP proxy, `curl -i` prints the proxy's CONNECT reply before the real response, so the fallback returned the response headers glued to the body and callers failed to parse it as JSON (seen in the macOS sandbox). The fallback now skips every leading `HTTP/` header block. Tests: `scripts/test_gh_rest_proxy_headers.py`.
