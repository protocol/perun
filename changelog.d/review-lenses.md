### Added
- Six lens references close the gaps found by checking the review against ISO/IEC 25010:2023, OWASP ASVS 5.0 and the LLM Top 10, WCAG 2.2, and the lens lists of seven review tools (CodeRabbit, Greptile, Qodo, Sourcery, SonarQube, GitHub Copilot code review, Anthropic's code-review plugin). Every source was fetched on 2026-10-16 and is logged in `docs/standards-index.md`. The other lenses considered (accessibility, i18n, observability, reliability, concurrency, data integrity, API compatibility, privacy, FinOps, supply chain and licensing, testability, DX, LLM risks, design-system consistency, runtime speed) were already covered and are not duplicated.
  - `safety-critical.md` (domain F): the ISO/IEC 25010:2023 Safety characteristic as five probes, and the rule that fail-safe is not fail-closed: a conflict goes to the owner, never a silent choice. A review never certifies a system as safe.
  - `energy-efficiency.md` (domain E): the Software Carbon Intensity frame, `UNMEASURED` instead of an invented kWh or gCO2eq, and battery, idle-power and carbon-aware-placement probes.
  - `delivery-speed.md` (domain K): measure time-to-green and the pull-request cycle from run history, then CI wall-clock, build-time and review-friction probes (caches, serial `needs` chains, retries that mask flakes, PR size, review latency, bot severity floors).
  - `code-structure.md` (domain H): read-only import-cycle, fan-in and co-change probes, and the structure-to-speed links (import-time work, bundle shape, hot and cold paths).
  - `product-impact.md` (domain M): a claimed outcome needs a metric with a baseline, an emitter, a guardrail and a decision rule, plus event-correctness probes (exactly once, after confirmation, survives page exit).
  - `compatibility-portability.md` (domain I): declared versus tested support matrix, portability probes, co-existence, installability and lock-in.
