## Drive to the goal (first rule)
- A task ends only when the requested outcome is met and verified. Waiting on a job, gate, budget or answer means you start the next independent item. When everything is blocked, create the next lever: measure, research, ask peers, build the zero-cost part. The only stops are "goal met with evidence" or "every path needs the owner", handed back as one batched question.
- Two spend modes. Default: be cautious about spend and report spend to the owner. Maximum pace: once the owner has asked to proceed at maximum pace or speed ("max speed", "push at max", "keep going", deliver everything, don't worry about budget, or a granted budget), do not stop until you have delivered what was asked. Then lift the lane and heavy-slot caps and the `HOLD`/`FULL` retry waits before a heavy command, and do not pause for approval inside any granted budget; keep reporting spend as you go.
- Maximum pace spends more only where it buys speed or quality: parallel lanes up to the load gate (a `host_probe.py` verdict other than `SPAWN` still blocks a spawn), and a stronger model or deeper verification on hard steps (the top-tier row of `deep-code-review`'s `model-tiering.md` **Route delivery lanes by work type and stage**). The waste filter holds in both modes: no duplicate run of the same gate on the same tree, no idle polling, no courtesy messages, no restating, and the cheapest model that keeps quality for mechanical work (a rename, a fully specified patch, a changelog fragment). Spend that buys neither speed nor quality is waste, not pace.
- An explicit owner instruction in the current session overrides throttle defaults and counts as the grant for the human-gate push (quote it with its date in the record); it covers push and merge only, while deploy, external send, deletion and force-push stay gated below until the owner names that action. To lift the caps run `python3 .claude/skills/agentic-delivery/scripts/perun_policy.py set tokens maximize` (the 2-lane cap) and `... set local_cpu maximize` (idle cores, still behind the load gate); `... set tokens efficient` and `... set local_cpu efficient` restore the default when the grant ends.

## Identity & isolation
- First command: `python3 .claude/skills/agentic-delivery/scripts/lane_guard.py --expect-branch <branch>`. Refusal → stop; hand back the `LANE_GUARD REFUSE:` line plus changed files.
- Resuming after a hold or a pause: re-read the shared record/backlog file for any new standing rule before continuing prior work — a rule posted mid-hold lives there, not in chat.
- Before your first push: `git config core.hooksPath .githooks` (shared by every worktree; do it once). The pre-push hook then runs, in under 30s over the pushed range, the cheap CI gates (size-ratchet, mustload, run-evals selftest, fix-class; INDEX/SHA256SUMS freshness on land commits only) and each failure prints its exact fix. Do not commit `SHA256SUMS`, `INDEX.md` or `size-budgets.tsv` rows from a lane: CI rebuilds them and `land-release.sh` commits them at land time. Never `--no-verify` around it.
- One writer per worktree. Never bare `git stash` (stack is shared — use a WIP commit instead). Never `--no-verify`. Never force-push without an owner-authored grant on file.
- Stage explicit paths only (`git add <path>...`); never `git add -A` or `git add .`, and never `git stash` (it sweeps in files other lanes own).
- Stacked on a parent lane not yet pushed: branch off its LOCAL ref (`git rev-parse <parent-branch>`), never poll the remote — the shared `.git` already sees it (#1152).

## Communication
- Caveman ultra in chat/reasoning: terse fragments, no filler/hedging/pleasantries. Code, commits, and docs stay normal prose.
- Token policy (`python3 .claude/skills/agentic-delivery/scripts/perun_policy.py get tokens`): `efficient` (default) means: use the cheapest model tier that fits, no duplicate review passes, terse hand-backs (guidance, not enforced), and at most 2 parallel lanes (enforced: `perun_policy.py lanes` and `heavy-slots` apply the cap); `maximize` (maximum pace, above) lifts the cap; a number caps lanes at that many (it is not a token budget).
- CI policy: when `perun_policy.py get github_actions` prints `off`, end every commit message you push with `[skip ci]` (`perun_policy.py skip-ci` prints it); required checks are then satisfied by local gates. This is a lane rule, not enforced by code.
- Before running tests from a hook, scrub inherited env: `scripts/scrub_env.sh <cmd>` unsets GIT_DIR, GIT_WORK_TREE, GIT_INDEX_FILE and every other GIT_* var plus DB vars (DATABASE_URL, PG*, MYSQL_*, REDIS_URL); a test's `git init` that inherited GIT_DIR once flipped the host repo to core.bare=true.
- NO POLLING. Never hand-roll a sleep/loop waiting on background work; use the bounded wait below.
- Never run delete/kill experiments on the host (container/VM or skip) and never `rm -rf` a variable-built path; deny rules are text-only, the sandbox is the boundary (`operating-discipline.md` item 8).
- A lane owns its background work until it completes: never hand back while its own `git push` (a pre-push hook can run 15+ minutes), test run or build is still running; `handback_cap.py` blocks a handback while a push from this worktree is live. Never end your turn with background jobs running (browser tests, builds; kill your own dev servers): `python3 .claude/skills/agentic-delivery/scripts/lane_guard.py wait --pid <pid> --port <port> --file <output> --timeout <s> --progress <worktree>/.lane-progress && lane_guard.py handback …`; `--progress` rewrites one liveness line every 15 min (`--progress-every`), so the parent reads that file instead of waiting on interim notices. `COULD_NOT_CHECK` → hand back what is still running, not "waiting".
- Final message is one line: `status | evidence | next`. Deliverables (code, reports, findings) live in files; never paste them into chat. If findings do not fit in one line, write them to a file and hand back its path. A lane that ran long or touched several things always hands back `status | <details-file path> | next`; the parent reads the file instead of re-querying state.
- Push, `gh` or network fails inside the sandbox (TLS x509, connection refused, no route): do not retry or work around it. Commit, hand back branch plus sha, and the main thread pushes.
- Board posts only through `python3 .claude/skills/agentic-delivery/scripts/board_post.py --repo <owner/name> --issue <issue> --type <CLAIM|RELEASE|HANDOFF|BLOCKER> ...` — typed posts, never free-form chat to a shared board.

## Verification
- Before a heavy local command (full test suite, build, browser run): `python3 .claude/skills/agentic-delivery/scripts/host_probe.py --lane-type heavy`; `HOLD` means wait a minute and retry, at most 3 times, then proceed and say so (under maximum pace proceed at once and say so); `COULD_NOT_CHECK` means proceed and say so. Then take the machine-wide lease: `python3 .claude/skills/agentic-delivery/scripts/perun_policy.py heavy-acquire` (exit 1 `FULL` means other sessions fill the `heavy-slots` count: same wait-and-retry, at most 3 times, then proceed and say so) and run `heavy-release` when the command ends; leases from dead pids or older than 2h are ignored.
- No "done" without evidence: a test id, an exact sha, or a file path — never a bare assertion.
- Parked/handback claim: `python3 .claude/skills/agentic-delivery/scripts/lane_guard.py handback --sha <sha> --base <dispatch-base> --branch <branch> --cite <path> --artifact-root <dir>` (one `--cite` per committed evidence file; absolute artifacts must sit under `--artifact-root`). A refusal means not parked.
- Deployed/served claim: `python3 .claude/skills/agentic-delivery/scripts/surface_check.py served --url <url> --expect-sha <sha> ...`.
- CI-checks claim: `python3 .claude/skills/agentic-delivery/scripts/surface_check.py checks --gh-repo <owner/name> --sha <sha> ...`.
- Design port: `python3 .claude/skills/deep-code-review/scripts/parity_differ.py --design <design-file> --app <app-file>` — report the inventory MATCH/gap it prints, never a size measured by hand. Use the `<design-lane>` agent type, if this host defines one, for design ports.

## Stop conditions
- Tool-call budget: at most `<tool-call cap>` tool calls (150 is a starting value; tune it from `python3 .claude/skills/agentic-ceo/scripts/token_report.py --budget`). At the cap, commit work in progress and hand back `BLOCKED | budget | <what remains>` instead of continuing.
- Lane teardown, before handback: `ROOT=<your worktree tree> bash .claude/skills/agentic-delivery/scripts/clean_finished.sh`, then `ROOT=<your worktree> bash .claude/skills/agentic-delivery/scripts/reap_own.sh --report` must print `orphans=0` (no listener left under the worktree). Rules: `merge-operations.md`.
- Before handback: write the changelog fragment and get `git diff --check` clean. Before any shell or layout migration, inventory the old capabilities (search, favorites, collapse) so none is silently dropped.
- After handback this lane may no longer receive messages: a review fix or conflict on its PR gets a fresh lane per PR, not a nudge to this one.
- Blocked: record the block and the next item; don't retry the same fix a third time.
- Question for an absent owner: `python3 .claude/skills/agentic-ceo/scripts/task_ledger.py defer --id <T-###> --question "<q>" --default "<choice taken>"`, state the default in your handback, then continue with `task_ledger.py next`. Human-gate (shared push, deploy, external send, secret/scope change) or destructive/irreversible without a standing grant: never default, always `--park`. Never idle waiting for an answer.
- Destructive or external action (force-push, deploy, secrets/IAM, external send, mass delete): gated — ask the owner, don't act.
